# 图召回（DeepWalk / Item2Vec / EGES / GraphSAGE-PinSAGE / LightGCN）· 实战手记

> 视角：召回算法工程师。图召回把 user/item 当节点、交互当边，用**图结构**学 embedding，核心优势是**捕捉高阶关系 + 缓解稀疏**——共现统计（ItemCF/Swing）只能捕捉直接共现，图召回通过多步游走/传播把间接关联也泛化出来。淘宝 EGES、Pinterest PinSage 是工业经典。

---

## 一、一句话讲清

把行为构成图（item-item 共现图 / user-item 二部图），用图算法（随机游走 or 图卷积）学节点 embedding，再走 ANN 召回。**高阶连通**：A-B 没直接共现，但 A-C-B 连得上，也能学到 A、B 相似。

> 和 I2I 共现的区别：I2I 只看一阶共现，图召回能传播多阶关系，长尾/稀疏节点也能借邻居信息学好。

---

## 二、两大流派

### 2.1 随机游走类（Graph Embedding，产出多为纯 item 向量，天然服务 I2I）

**DeepWalk（奠基方法）**：图上随机游走生成"节点序列"，当句子喂 word2vec(skip-gram) 学 embedding。

```
构图（item-item 图，边权 = 共现次数）
  ↓ 无偏随机游走（按边权重为概率随机跳邻居）
  ↓ 生成大量游走序列
  ↓ Skip-gram + 负采样训练
  ↓ item 向量
```

局限：游走无偏，无法控制"探索局部社区"还是"探索结构相似的远处节点"。

**Node2Vec**：带偏置的游走，`p`(返回参数)、`q`(进出参数) 控制 BFS/DFS 倾向——`q` 小偏 BFS（学到"同质社区"），`q` 大偏 DFS（学到"结构相似"，即使不在同一社区）。工业界很少直接落地，更多是思想被后续方法吸收。

**Item2Vec（最简化版本，工业界常见起点）**：**完全不建显式图**，直接把每个 session/购物车列表当一句"话"，session 内所有 item 互相当上下文（不要求相邻，两两都算共现），直接 Skip-gram：

```
session = [item_A, item_B, item_C]
→ (A,B), (A,C), (B,C) 互为正样本对 → Skip-gram + 负采样
```

没有建图、没有随机游走这两步，本质上等价于把每个 session 看成一个全连接的小型共现图。实现成本最低，很多公司图召回第一版就是它。

**EGES（淘宝，重点）**：在 DeepWalk 基础上融合**side information**（类目/品牌/店铺），解决纯 ID graph embedding 的冷启动问题。

```
每个 item 准备多套 embedding：
  E_id(i)、E_category(i)、E_shop(i)、E_brand(i) ...

加权融合（权重可学习，类似简化版注意力）：
  H(i) = Σ_s w_i^s · E_s(i) / Σ_s w_i^s
```

**为什么能解决冷启动**：新 item 的 ID embedding 学得差（共现太少），但类目/店铺/品牌 embedding 是和大量老 item 共享的（老 item 已训练充分），融合后新 item 依然能拿到还不错的向量。

**EGES 本身产出的是纯 I2I 向量**：图节点全是 item，边是共现关系，训练只学到 item-item 关系，没有用户向量的概念。线上通常接入 ICF（item CF）形式作为独立一路召回；要做 U2I 需要额外把用户历史 item 向量聚合成用户向量，这是衍生用法，不是核心设计。

### 2.2 图神经网络类（GNN）

**GraphSAGE / PinSage**：上面所有随机游走类方法都是**transductive（转导式）**——只有训练时图里出现过的节点才有向量（查表得到），新节点必须等下一次全量重训练才能拿到向量。

GraphSAGE 的关键改进：不直接学"每个节点的向量"，而是学一个**聚合函数**——"如何把节点自身特征和邻居特征聚合成向量"。这个函数训练完之后是通用的，任何新节点只要有自身特征和邻居信息，直接跑一遍聚合函数就能拿到向量，**不需要重新训练**：

```
h_v = AGGREGATE(自身特征, {邻居节点特征})   # 聚合函数是学出来的，节点向量是算出来的
```

**PinSage（Pinterest 工业级实现，规模最大、工程细节最全的案例之一）**在此基础上做了大规模工程优化：
- **基于随机游走的重要性池化**：不均匀采样邻居，而是从目标节点发起多次随机游走，按访问频率给邻居分配权重，聚合时按重要性加权
- **课程学习式难负样本挖掘**：训练早期用简单负样本，随训练推进逐渐加入图上距离较远但仍有关联的难负样本
- **MapReduce 批量离线推理**：支持十亿级节点规模的高效离线向量计算

**LightGCN（推荐主力，直接在 user-item 二部图上跑）**：去掉 GCN 的特征变换和非线性，只保留邻居聚合 + 层组合，简单高效，专为协同过滤设计。**和上面所有方法的本质区别**：LightGCN 直接在 **user-item 二部图**上跑图卷积，一次训练**同时产出 user 向量和 item 向量**，天然是 U2I 形态，不需要像 EGES 那样额外聚合出用户向量。

## 三、方法对比表（背这个，面试常问"这几个怎么选"）

| 方法 | 建图方式 | 产出 | 是否支持新节点直接推理 | 核心解决的问题 |
|---|---|---|---|---|
| **DeepWalk** | item-item 图 + 无偏游走 | 纯 item 向量(I2I) | 否（transductive） | 图 embedding 奠基，泛化共现关系 |
| **Node2Vec** | item-item 图 + 有偏游走 | 纯 item 向量(I2I) | 否 | 游走策略可调(社区 vs 结构相似) |
| **Item2Vec** | 不建图，session 内两两共现 | 纯 item 向量(I2I) | 否 | 最简化实现，落地门槛最低 |
| **EGES** | item-item 图 + side info 融合 | 纯 item 向量(I2I) | 否（图外新品简单平均兜底） | 长尾/新品共现少导致向量差 |
| **GraphSAGE/PinSAGE** | item-item 图(或二部图) + 邻居聚合 | item 向量(I2I，可扩展) | **是（inductive）** | 新节点无需重训练即可拿到向量 |
| **LightGCN** | user-item 二部图 + 图卷积 | **user 向量 + item 向量(天然 U2I)** | 否（transductive） | 协同信号高阶传播，效果强 |

## 四、线上链路

1. 离线建图（item-item 或 user-item 二部图，或直接用 session 序列，无需显式建图）；
2. 训练节点 embedding（游走+Skip-gram，或 GNN 聚合/卷积）；
3. item（及 user，如 LightGCN）向量建 ANN 索引；
4. I2I 形态：trigger item 查近邻；U2I 形态（LightGCN 或 EGES 衍生用法）：user 向量检索 item。

> 归纳式方法（GraphSAGE/PinSAGE）多一步：新 item 上线无需重训练整张图，直接用已训练好的聚合函数对新节点跑一次推理即可拿到向量，补进索引。

## 五、版本迭代

### v0 · DeepWalk/Node2Vec
纯 id 游走 embedding。问题：冷启 item 没向量、side info 没用上。

### v1 · Item2Vec（工程简化的平行分支）
不建图直接对 session 做 Skip-gram，落地成本最低，很多团队第一版从这里起步。

### v2 · EGES
融合类目/品牌等 side info，冷启 item 靠属性也能得到向量。效果：冷启覆盖提升。

### v3 · LightGCN
换 GNN，显式建模 user-item 二部图高阶连通，一次产出 user+item 向量。效果：协同信号更强，召回质量提升。

### v4 · 归纳式 + 大规模工程化
PinSage/GraphSAGE 采样聚合，支持新节点和亿级图；邻居采样 + 负采样优化训练效率。

> 负采样体系（未曝光随机负打底 + 中段难负 + 假负过滤等）跨通路通用，详见 [`负样本挖掘和召回效果评估.md`](../负样本挖掘和召回效果评估/负样本挖掘和召回效果评估.md)。图召回里还要额外注意：随机负可能采到图上的高阶邻居（其实相关），是一类 false negative；EGES/Item2Vec 的 Skip-gram 负采样常用**幂律负采样**（`Q(i)=freq(i)^0.75/Σfreq^0.75`），这种场景下 `Q(i)` 是采样器自带的已知量，不需要额外估计，直接代入 logQ 矫正即可。

## 六、EGES 建图与工程细节（业务实践里最容易踩坑的点）

### 6.1 有向图 vs 无向图

不是固定选择，取决于业务场景——如果"先点 A 还是先点 B"主要取决于随机呈现顺序（不是用户主动的偏好顺序），无向图更合理；如果顺序本身有强因果意义，用有向图。

### 6.2 多跳 vs 单跳建边

不能只连相邻对（A-B, B-C），同一时间窗口内的所有行为都应该两两建边（A-C 也要连），因为它们大概率都反映了同一批兴趣，只连相邻会漏掉这类间接关联。

### 6.3 图噪声清洗

边权重极低（比如只有 1 个用户走过这条边）可以认为是随机噪声，可以丢弃构造更干净的图（虽然随机游走本身就不太会走到低权重边，但从建图质量角度还是值得清洗）。

### 6.4 大图游走内存爆炸的工程解法

node2vec 原始实现会预计算所有节点的转移概率再游走，图太大直接 OOM。解法：**用时间换空间**——游走到某个节点时才实时计算它的转移概率，不预存全量转移概率表，会有重复计算但避免 OOM。

### 6.5 不定长 side info 的聚合

像"喜欢的水果"这种离散多值特征，用 mean pooling 把多个 tag 的 embedding 聚合成一个特征向量，用 placeholder 传入变长的 tag 数量来实现。

### 6.6 冷启动简化处理

论文没细讲图外新 item（没游走过）怎么办。图内 item 有多个 side info embedding + 自身 ID embedding + 学出来的融合权重；图外新品拿不到融合权重（权重是每个图内 item 独有的），**实践发现直接对多个 side info embedding 做简单平均，效果和用图内 item 的平均权重加权差不多**，工程上可以直接简化成简单平均。

### 6.7 离线评估的坑

论文里常用"预测两个节点间是否存在边"作为离线评估任务，实践中会发现无论怎么设计（drop 不同比例的边测预测准确率），结果都很接近，区分度不够。更实用的做法：自建业务相关的评估任务，比如用用户历史 item 向量均值当"伪用户向量"，去候选集里做相似检索算 TopK 准确率——**注意这只是离线评估手段，不代表线上就是按 U2I 部署**，EGES 线上实际走的是 ICF（I2I）形式。

## 七、常见坑

**坑 1 · 冷启节点无 embedding**
原因：纯 id transductive 方法学不出新节点。解：EGES(side info)、GraphSAGE(归纳式聚合邻居)。

**坑 2 · 超级节点(热门)主导传播**
现象：热门节点连边太多，污染邻居聚合。解：邻居采样限制度数、热门降权、归一化(LightGCN 的对称归一)。

**坑 3 · 图太大训练不动**
解：邻居采样(GraphSAGE)、子图采样、负采样；分布式图引擎；游走时实时算转移概率而非预存全量表（见 §6.4）。

**坑 4 · 过平滑(over-smoothing)**
现象：GNN 层数多了所有节点向量趋同。解：层数控制(2~3 层)、LightGCN 层组合、残差。

**坑 5 · 图构建噪声**
原因：误点击/爬虫/活跃用户造假边。解：边权过滤、活跃用户降权、时间衰减。

**坑 6 · 建图时只连相邻对，漏掉间接关联**
同一 session/时间窗口内的行为都应该两两建边，不能只连相邻的，否则同窗口但非相邻的关联会丢失（见 §6.2）。

**坑 7 · 离线边预测评估任务区分度差**
预测边是否存在的任务通常区分度不够，应自建业务相关的评估任务（见 §6.7）。

## 八、常见问答（带追问）

**Q1：图召回比 I2I 共现强在哪？**
I2I 只看一阶共现，稀疏/长尾节点共现少就学不好；图召回通过多阶传播让节点借邻居信息，高阶关系和长尾覆盖更好。

**Q2：EGES 解决了什么问题？EGES 是 I2I 还是 U2I？**
纯 id graph embedding 的**冷启动**——新 item 没游走序列就没向量。EGES 融合 side info(类目/品牌)，新 item 靠属性 embedding 也能得到合理向量。**EGES 核心算法本质是纯 I2I**（图节点全是 item，产出只有 item 向量），线上接入 ICF 形式做召回；U2I 需要额外聚合用户历史 item 向量成用户向量，是衍生用法。
> 追问·side info 怎么融合？ → 每个 item 的 id + 各属性各一个 embedding，用可学习权重(类似简化版注意力)加权求和成最终 item 向量。

**Q3：Item2Vec 和 DeepWalk 的核心区别？**
Item2Vec 不建显式图、不做随机游走，直接把 session 内所有 item 当上下文两两配对训练；DeepWalk 需要先建图再游走。Item2Vec 可理解为"把每个 session 当成一个全连接的小共现图"的简化版本，落地成本更低。

**Q4：LightGCN 为什么去掉特征变换和非线性？它和 EGES 最大的区别是什么？**
推荐的协同过滤里，节点本身没丰富特征，GCN 的特征变换+非线性反而增加训练难度、易过拟合；去掉后只保留邻居聚合(协同信号本质)，更简单、更好、更快。**核心区别**：LightGCN 直接在 user-item 二部图上跑，一次训练同时产出 user 和 item 向量，天然 U2I；EGES 只在 item-item 图上跑，只产出 item 向量，天然 I2I。

**Q5：transductive 和 inductive 区别？**
transductive(DeepWalk/Item2Vec/EGES/LightGCN)只能给训练时见过的节点向量，新节点要重训；inductive(GraphSAGE/PinSage)学的是"聚合函数"，能给新节点现场生成向量，工业更友好。

**Q6：GNN 过平滑怎么办？**
层数别太深(2~3 层)、用 LightGCN 的层组合(各层加权)、加残差/初始连接(APPNP 思路)。

**Q7：工业界这几种方法实际用得最多的是哪个？**
按落地门槛从低到高：**Item2Vec**（最简单，很多公司第一版就是它）→ **EGES**（有明确冷启动收益，国内工业界引用最多）→ **LightGCN**（要做端到端 U2I 协同过滤时的主力）→ **GraphSAGE/PinSAGE**（新品覆盖要求高、图规模巨大时才需要上，工程复杂度显著更高）。DeepWalk/Node2Vec 更多是学术奠基意义。

## 九、选型一句话

- 行为稀疏、长尾长、要高阶关系 → 图召回。
- 快速验证图召回价值、成本要求低 → Item2Vec。
- 有大量 side info 且冷启严重，要做 I2I → EGES。
- 标准协同过滤要简单高效、直接产出 U2I 向量 → LightGCN。
- 图规模大 + 频繁新节点，要求新品立刻有向量 → GraphSAGE/PinSage(归纳式)。

## 十、监控指标

- 离线：自建业务相关的 TopK 召回准确率（避免用边预测任务，区分度差）、Recall@K、NDCG、长尾/冷启子集表现。
- 在线：召回覆盖率、长尾占比、冷启 item 起量、pvctr/uvctr。
