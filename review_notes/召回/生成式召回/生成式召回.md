# 生成式召回（Generative Retrieval）· 实战手记

> 视角：召回算法工程师。这篇以 `tencent_advertising_gr`（2025 腾讯广告算法大赛，HSTU 生成式召回，进决赛）为实战载体，串联生成式召回的技术脉络：为什么要"生成"而不是"检索"，工业界两条主流路线怎么选，以及一套完整可跑通的训练目标（混合负采样 + logQ 矫正 + 难负例挖掘 + 课程学习）长什么样。

---

## 项目介绍

> 传统召回是"表征 + 检索"两段式：双塔各自把 user/item 编码成向量，线下建好 item 的 ANN 索引，线上只需要拿 user 向量去查表。这套范式的天花板在于**表征能力**——不管双塔内部怎么堆结构，最终交互只能是一个内积，用户的长序列行为、多兴趣、上下文全部要被压缩进一个固定维度的向量里。
>
> 生成式召回的核心思路是把"检索"重新表述成"生成"：不再是查表，而是用一个自回归模型，看着用户的历史行为序列，直接**预测/生成"下一个"用户会交互的目标**。这个"目标"可以是一串离散的语义 ID token（Semantic ID 路线，代表工作 TIGER），也可以是一个稠密向量（Dense Embedding 路线，代表工作 Meta 的 HSTU、Pinterest 的 PinRec）。本项目走的是后一条路——用 HSTU（Hierarchical Sequential Transduction Units）作为序列生成骨架，自回归地为每个时间步生成一个"下一步兴趣"的稠密向量，训练时把它当作一个大规模的 sampled-softmax 分类任务，推理时把生成的向量当 query 去和预先算好的 item 向量做 ANN 检索——**本质是把双塔的"一次性打分"换成了"逐步生成 + 逐步打分"**，同时把 SASRec 式的 softmax attention 换成了 HSTU 的无 softmax 逐点门控注意力，以支撑更长序列、更高吞吐。
>
> 工程上的关键难点不在"生成"这个概念本身，而在于把生成式序列模型的训练目标和工业级负采样体系拼起来：全库 item 上亿，不可能对每个时间步做完整 softmax，于是要设计一套**混合负采样（in-batch + 全局随机）+ logQ 重要性矫正 + 假负例过滤 + 难负例挖掘 + 课程学习**的组合拳，外加用户特征通过 FiLM 条件化整段序列、动作类型（曝光/点击/转化）作为条件输入实现"动作可控生成"。最终该方案拿到 0.129843 分，进入 2025 腾讯广告算法大赛决赛。

## 一、为什么要"生成"，不满足于双塔检索

**双塔的结构性限制**：user 向量和 item 向量必须独立编码（否则 item 侧无法离线预算走 ANN），交互被压缩进一个内积。序列越长、兴趣越多元，这个单一向量的表达瓶颈就越明显——这也是 MIND 多兴趣、SASRec 序列建模想解决的问题，但它们本质上都还是"编码成一个/几个向量再做检索"。

**生成式的核心变化**：把"检索"看成一个**自回归序列生成**问题——给定用户到当前时刻的行为序列，模型在每一个时间步都要预测"下一步会交互什么"。这跟语言模型预测下一个 token 是完全同构的问题：

```
传统双塔：  [用户历史序列] → 编码成一个 user 向量 → 查 ANN → top-K
生成式：    [用户历史序列] → Transformer/HSTU 逐步生成 → 每一步都有一个"下一步预测" → (转成向量再查ANN，或直接生成离散ID)
```

这带来两个直接收益：
1. **训练信号更密集**：序列里每一个位置都产生一条训练样本（预测该位置的下一个 item），不再是"一个用户一条样本"，样本利用率大幅提升（这也是 SASRec 类方法的共同优势，生成式框架把它和更强的序列骨架结合起来）。
2. **可以做"条件生成"**：可以把"想要点击"还是"想要转化"当成生成条件注入模型，让同一个模型在不同动作目标下生成不同的候选倾向（本项目的 action-conditioned generation）。

## 二、两条技术路线：Semantic ID vs Dense Embedding

生成式召回工业落地目前分化成两条路线，选型的核心分歧在于"生成的目标是离散 token 还是连续向量"：

| | **Semantic ID 路线**（语义 ID 生成） | **Dense Embedding 路线**（稠密向量生成，本项目属于这一类） |
|---|---|---|
| 代表工作 | Google TIGER、快手 OneRec、百度 COBRA、京东 GRAM、腾讯 RARE、美团 EGA-v2 | Meta HSTU（"Actions Speak Louder than Words"）、Pinterest PinRec、Meta RPG |
| item 表示 | 先用 RQ-VAE 等量化方法把 item 内容 embedding 压成一串离散 codeword（语义 ID），词表规模从"item 总数"降到"codebook 大小" | item 仍然是一个连续的 dense embedding，和传统双塔的 item 向量形态一致 |
| 生成方式 | Transformer Decoder 自回归生成语义 ID 的 token 序列（类似生成一串"分类路径"） | 自回归生成下一步的 dense 向量（或直接输出隐状态当 query），本质更接近"逐步演化的双塔" |
| 检索方式 | 生成的语义 ID 直接映射（挂载）到对应的候选 item，天然自带"生成即检索"的性质 | 生成的向量仍需要走一次 ANN/内积检索，和双塔的检索方式相同 |
| 核心卖点 | ID 词表极小、内存友好；语义相近的 item 共享 codeword 前缀，天然有泛化/冷启动能力 | 不引入量化误差，能更精细地对齐 CTR/CVR 等连续指标；工程改造成本低（复用现有 ANN 基建） |
| 主要争议点 | 量化误差；训练目标（下一个 codeword 的分类）和最终评估目标（item 级相关性）有 gap | 业内有声音认为这类方法本质仍是双塔的一种变体（序列化的双塔），"生成"更多是训练范式的包装而非检索范式的根本改变 |

> 关于 Dense Embedding 路线"本质是不是双塔"的讨论：业内确实存在"预测下一个 item embedding 的生成式召回，本质还是双塔"的观点（这条批评的核心逻辑是：这类方法最终还是靠一个向量去做内积检索，Transformer 只是换了个更强的"user 编码器"）。这个说法有一定道理，但不完全——差异在于**训练信号的组织方式**：传统双塔一个用户只产生一条（或几条）训练样本，序列生成式方法把序列的每个位置都变成一条样本，且通过因果注意力让每一步的表示都能利用到该位置之前的全部上下文，这是纯粹"user 塔换成 Transformer"做不到的（因为双塔训练时通常只监督最后一步）。可以理解为：**Dense Embedding 生成式召回 = 序列双塔的一种更充分利用训练信号、支持条件生成的强化版本**，不是与双塔完全割裂的新范式；Semantic ID 路线才是真正在检索机制上做出根本改变的分支。

## 三、核心架构：HSTU 精讲（对应 `model.py`）

HSTU（Hierarchical Sequential Transduction Units）是 Meta 提出的用于生成式推荐的序列骨架，本项目直接采用其结构。核心改动是**把 Transformer 的 softmax attention 换成了无 softmax 的逐点门控注意力**。

### 3.1 单层 HSTU 的计算流程

```
输入 x (B, L, D)
  ↓ 一次 Linear 同时投出 U, V, Q, K（省一次矩阵乘）
  ↓ attn_logits = QK^T / sqrt(d) + RAB(相对时间偏置)
  ↓ A = SiLU(attn_logits)          ← 关键：这里没有 softmax！
  ↓ A = A ⊙ causal_mask ⊙ padding_mask（逐点相乘，不是softmax里的归一化）
  ↓ y = A @ V
  ↓ y = Norm(y) ⊙ U                ← 用 U 对聚合结果做门控（gate）
  ↓ 输出投影 + Dropout + 残差连接
```

**为什么去掉 softmax，换成 SiLU 逐点非线性**：softmax 要在整行做归一化（依赖当前行的全部元素），这在序列很长、要做增量推理/缓存时代价较高；换成逐点的 SiLU 之后，attention 权重的计算退化成纯逐元素操作，**天然支持增量式/流式计算**，对生成式场景（要一步步产出下一个 token 的表示）更友好，这也是"生成式"骨架和"判别式"骨架在算子层面的核心区别之一。用 U 做门控则是保留了"选择性地让哪些信息通过"的能力，弥补了不做 softmax 归一化可能带来的数值/表达力损失。

### 3.2 相对注意力偏置（RAB）：显式建模时间间隔

```python
tdiff = |ts_q - ts_k|                     # 任意两个时间步的时间差(秒)
bucket = bucketize(log(tdiff), 时间桶边界)  # 对数分桶，远的时间差分辨率低
bias = Embedding(bucket)                   # 学出来的偏置，加到 attn_logits 上
```

序列推荐里"多久之前的行为"本身就是重要信号（一小时前的浏览 vs 三个月前的浏览，参考价值天差地别），用对数分桶把连续的时间差离散化成有限个桶，每个桶学一个偏置项加到注意力分数上，让模型显式感知"时间上的远近"，而不是仅靠位置编码隐式表达。

### 3.3 用户条件化：FiLM 调制整段序列

用户特征不是简单拼接进每个 item 的输入，而是先聚合成一个用户向量 `u`，再通过 FiLM（Feature-wise Linear Modulation）生成 `(γ, β)` 去调制整段 item 序列：

```python
u = mean_pool(user_feature_embeddings)      # 用户侧特征聚合
gamma, beta = Linear(u).chunk(2)            # 生成调制参数
gamma = tanh(gamma)
seqs_emb = item_seq_emb * (1 + gamma) + beta   # 对序列里每个 item 表示统一做仿射变换
```

**这么做的意义**：让"用户是谁"变成对整段序列表示的一次性、全局的仿射变换，而不是和每个 item 简单拼接后再靠 MLP/attention 慢慢融合——计算更轻量，且用户信息以一种类似"风格迁移"里 condition 注入的方式，均匀地影响到序列里的每一个位置。

### 3.4 动作条件化生成（Action-Conditioned Generation）

```python
act_vec = Embedding(next_action_type)   # 0=曝光 1=点击 2=转化
seqs = seqs + act_vec * item_pos_mask
```

把"下一步动作类型"也编码进输入序列（作为要预测位置的条件），本质是告诉模型"我现在要生成的是一个会导致点击的候选，还是仅仅导致曝光的候选"。这是生成式框架相比传统双塔更自然的一个能力——双塔很难优雅地把"目标动作类型"当成检索时的显式条件，生成式框架里它就是序列的一部分输入。训练时用不同动作类型对应的真实位置监督，loss 侧再对点击给更高权重（`w_click > w_expo`），双重强化"点击"这个业务上更重要的动作。

### 3.5 因果掩码：真正的自回归训练

```python
causal_mask = tril(ones(L, L))                 # 下三角，只能看到自己和之前
padding_mask = (mask != 0)                     # 屏蔽 padding 位置
attention_mask = causal_mask & padding_mask
```

和语言模型训练完全同构：每个位置只能看到它之前的历史，这样序列里的**每一个位置**都能同时产出一条"用历史预测下一步"的训练样本，这就是前面提到的"训练信号更密集"的具体实现方式。

## 四、训练目标：CDN_Softmax（重点，工业落地的核心难点）

全库 item 上亿，不可能对每一步做完整 softmax，工程实现上要用**采样 softmax（sampled softmax）**近似，同时要处理好负采样带来的偏差。本项目的 `CDN_Softmax`（Calibrated Dual-Negative Sampled Softmax）把下面几件事拼在了一起：

### 4.1 混合负采样：全局负例 + in-batch 负例

```
全局负例(neg_global)：从全库按热度采样得到的候选，覆盖长尾分布
in-batch负例：batch 内其他样本的正例，天然是"热门+多样"的负例来源
```

两路负例都参与 loss，缺一不可——全局负例保证长尾覆盖（否则模型只学会跟 batch 内热门 item 比较），in-batch 负例几乎零成本、难度适中（都是真实出现过的正样本，比纯随机负例更有区分力）。

### 4.2 logQ 矫正：不仅纠负例，也纠正例（关键细节）

```python
logits_neg = sim(q, neg) / τ - log_q_table[neg_id]     # 负例减 logQ，标准做法
logits_pos = sim(q, pos) / τ - log_q_table[pos_id]     # 正例也减 logQ ← 特殊之处
```

标准 sampled softmax 只需要对负例做 logQ 矫正（负例采样概率越高，打分越容易被系统性低估，减去 `log Q` 抵消这个偏差，参见笔记里 logQ 矫正的推导）。这里**额外对正例也做同样的矫正**：`log_q_table` 是按物品出现频次算出来的（`power=0.75` 幂律平滑），全库超过一半的 item 出现次数 < 5 次，这些冷门正例的 `logQ` 值很小（负值绝对值很大），减去它之后正例 logit 会被显著抬升——相当于**变相加大了冷门正例在 loss 里的权重**，缓解"热门 item 主导训练、冷门 item 学不动"的问题。这是把 logQ 矫正的思路从"单纯纠偏采样概率"延伸到"顺手做冷启动加权"的一个巧妙复用。

### 4.3 假负例过滤：余弦相似度阈值

```python
# 候选负例如果和当前正例的相似度过高，很可能是"漏标的真兴趣"，屏蔽掉不参与loss
if cos_sim(候选负例, 正例) > 0.99:
    mask 掉这个负例
```

采样到的负例里，有一部分可能和真实正例高度相似（同款不同 SKU、同系列的不同素材），把它们当负例训练会引入错误梯度（假负例问题）。用余弦相似度设一个高阈值，超过阈值的候选直接从负例集合里剔除。

### 4.4 难负例挖掘 + 课程学习：训练全过程的调度表

```python
def set_curriculum(global_step):
    if step < 20000:   hard_topk = 0        # 冷启动阶段：不做难负例挖掘，用全部负例稳定训练
    elif step < 40000: hard_topk = 8192     # 突然引入大量难负例
    elif step < 60000: hard_topk = 4096
    elif step < 80000: hard_topk = 2048
    elif step < 100000: hard_topk = 1024
    elif step < 115000: hard_topk = 512
    elif step < 130000: hard_topk = 256
    else:               hard_topk = 128     # 后期只保留极少数、最难的负例

    glb_neg_ratio = 0.5 if step < 80000 else 0.25   # 全局(易)负例占比逐步下降
```

**调度逻辑**：
- **前 2 万步**：`hard_topk=0`，即不挑选难负例，直接用全部负例的 loss（保证冷启动阶段梯度稳定，模型先学会基本的粗粒度区分）。
- **之后**：从一次性保留 8192 个最高分负例开始，随训练推进逐步收窄到 128 个——保留的负例数越少，意味着这些负例是从更大候选池里挑出来的"top 分数"负例，相对越来越难；同时全局（更容易的随机）负例占比从 0.5 降到 0.25，进一步把负例结构从"多而杂"调整为"少而精"。
- 这是标准的**课程学习（curriculum learning）**思路：先易后难，避免训练早期就被大量难负例的强梯度带偏，同时后期用难负例逼模型学出更精细的决策边界。

### 4.5 训练 loss 汇总

```python
denom = logsumexp([pos_logits, 挑选出的负例logits])   # 分母：正例+负例
num   = logsumexp([pos_logits])                        # 分子：只有正例
loss_per_position = denom - num                         # 标准 sampled softmax cross-entropy

# 按位置加权：点击位置权重更高
weight = w_expo + (w_click - w_expo) * is_click
loss = Σ(loss_per_position * weight) / Σ(weight)
```

## 五、推理链路：生成之后，怎么变成"检索结果"

```python
final_feat = HSTU编码后的序列, 取最后一个位置的隐状态
q = L2_normalize(final_feat)          # 生成的"下一步兴趣"向量

# 线下预先把全库 item 过一遍 item 塔，得到 item 向量矩阵
scores = q @ item_embedding_matrix.T   # 精确内积(候选量可控时可以不用近似ANN)
topK = torch.topk(scores, k)
```

可以看到本项目的推理阶段和传统双塔完全一致：**训练时是"自回归生成序列里每一步的下一个兴趣"，推理时只需要最后一步的隐状态，当成一个 query 向量去做内积检索**。这也印证了前面第二节的判断——Dense Embedding 路线的生成式召回，检索机制上和双塔没有本质区别，"生成式"体现在**训练范式**（序列里每一步都是一次预测/生成，用因果注意力保证只用历史信息）而不是**检索范式**。

## 六、和其他召回方式的关系（串联复习）

| | 传统双塔 U2I | 序列召回(SASRec) | MIND多兴趣 | 生成式召回(本项目 HSTU) |
|---|---|---|---|---|
| user 表示 | 单一 user 向量 | Transformer 编码序列，取最后一步 | 动态路由出 K 个兴趣向量 | 序列每个位置都有一个"生成态"向量 |
| 训练监督 | 一个用户一条（或几条）样本 | 序列里每个位置监督（同 SASRec 传统做法） | Label-aware Attention 后取一个兴趣向量做监督 | 序列每个位置监督 + 动作类型条件化 |
| attention 机制 | 无 / 简单 pooling | 标准 softmax self-attention | Squash + 动态路由 | 无 softmax，逐点 SiLU 门控（HSTU） |
| 检索方式 | ANN 内积 | ANN 内积 | 每个兴趣向量各自查 ANN，再融合 | ANN 内积（本质同双塔）|
| 核心卖点 | 简单、工程成熟 | 显式序列依赖建模 | 多兴趣解耦，避免单向量坍缩 | 训练信号更密集 + 动作可控生成 + 更强序列骨架 |

一句话定位：**生成式召回（Dense Embedding 路线）可以理解成"序列召回 + 更强的骨架(HSTU) + 更充分的训练目标设计(混合负采样体系) + 条件生成能力"的集大成版本，而不是和双塔/序列召回完全割裂的新物种**；真正范式级改变的是 Semantic ID 路线（TIGER 等），它把检索本身也变成了"生成即索引"。

| 架构 | Qwen Decoder-only | Encoder-Decoder（Gated MLP + GNN + SASRec-style Decoder） | Decoder-only | Decoder-only + DeepSeek-V3 风格 MoE |

> 与本项目 `tencent_advertising_gr` 的关系：baseline 已经具备"HSTU 序列骨架 + 混合负采样 + logQ 矫正 + 课程学习"的完整雏形，四个获奖方案是在这个雏形之上，把**行为条件化做得更精细**、**语义 ID 引入进一步解决冷启动**、**训练工程（优化器/负样本规模/推理加速）做到极致**。

### 7.2 行为条件化的进阶版本：三机制协同（对照本项目的 action_emb 加法注入）

本项目（`model.py`）里动作条件化只是简单的 **加法注入**：`seqs = seqs + action_emb(next_action_type)`。第一名方案把这一步拆成三个协同机制，是同一个思路的精细化版本：

```
机制A · FiLM：x_FiLM = γ(a_t) ⊙ x_t + β(a_t)          ← 用动作类型生成的仿射变换直接调制特征
机制B · Gated Fusion：x_gate = g(a_t)⊙x_FiLM + (1-g(a_t))⊙x_t   ← 软门控自适应混合"条件化后"与"原始"表征
机制C · Attention Bias：Attn = softmax(QK^T/√d + B(a_t))V        ← 在注意力层面让高价值动作位置获得更高权重
```

**设计动机**：TencentGR-10M 数据里曝光占 94.63%、点击 2.85%、转化仅 2.52%——如果三类动作的 token 一视同仁地喂进 Transformer，94% 的曝光噪声会淹没点击/转化的强信号。三机制分别在**特征空间**（FiLM 精细调制、Gated Fusion 控制信噪混合比例）和**注意力空间**（Attention Bias 让模型自己学会少关注曝光位置、多关注点击/转化位置）双管齐下，比单纯"加一个 embedding"能更彻底地解耦三类动作的语义。

**和本项目的差距点**：本项目只做了加法注入 + loss 侧对点击加权（`w_click > w_expo`），相当于只用了"类似 Gated Fusion 的静态版本"（固定权重而非动态门控），且完全没有在 attention 层面做偏置调控——这是一个可以直接借鉴改进 baseline 的点。

### 7.3 语义 ID 引入：RQ-KMeans + Random-k 正则化（衔接第二节 Semantic ID 路线）

第一、二名都在 Dense Embedding 路线的基础上，**额外引入语义 ID 作为辅助**（不是替代 dense 检索，是两条路线的融合）：

```
多模态 Embedding e
  ↓ 第1级：c1 = argmin_k ||e - μ1^k||²  →  码字id1，残差 r1 = e - μ1^c1
  ↓ 第2级：c2 = argmin_k ||r1 - μ2^k||² →  码字id2，残差 r2 = r1 - μ2^c2
  ↓ ...（L级，残差逐级量化）
语义ID = (id1, id2, ..., idL)          ← 形成语义树，相似广告共享更长前缀
```

这就是**残差量化 K-Means（RQ-KMeans）**，和 TIGER 用的 RQ-VAE 思路一致（残差逐级量化），只是把 VAE 换成了更轻量的 K-Means 聚类。**为什么第一名要在纯 dense embedding 方案里额外引入语义 ID**：低频广告的 dense ID embedding 学不好（长尾问题），语义 ID 让相似广告共享 codeword 前缀，天然有跨物品的知识迁移能力——这正是第二节表格里 Semantic ID 路线的核心卖点，说明**两条路线不是互斥的，工业最优解常是"dense 检索为主，语义 ID 作为辅助特征/正则化信号"**。

**Random-k 正则化（来自 FORGE 论文）解决的坏味道**：如果始终从第 1 级码开始训练，模型容易"抄近路"只学第 1 级粗粒度语义，忽略后面更精细的层级（一种语义 ID 版本的特征坍缩）。解法是训练时随机选一个起始级数 `k`，只用 `id_k, id_{k+1}, ..., id_L` 这一段作为输入，强迫模型在不同的粒度切片上都要学到有效信息，起到类似 Dropout 的正则化作用。

### 7.4 时序特征工程：三级层次 + 多频 Fourier（比本项目的 RAB 更精细）

本项目只用了"时间差分桶 + 学习偏置"（RAB）加上简单的 sin/cos 周期特征。第一名做到三级：

```
Level 1 绝对时间：小时(0-23)、星期几(0-6)、是否节假日
Level 2 相对间隔：Δt = t_now - t_prev（秒级=同session连续行为，分钟级=同session不同段，天级=跨session回访）
Level 3 Session结构：Request-level ⊂ Session-level ⊂ Cross-day Visit，携带"属于哪个session、session内第几个位置"
多频Fourier：FourierEncode(t) = [sin(2πt/ω1), cos(2πt/ω1), ..., sin(2πt/ωk), cos(2πt/ωk)]，多个频率覆盖小时/日/周尺度
```

**思路的共性**：都是在承认"Transformer 位置编码只表达相对顺序、不表达真实时间语义"的前提下，用显式特征工程把"多久之前""处于哪个访问层级"这些强信号喂给模型，而不是指望模型从数据里自己学出时间概念。这一条可以直接对照本项目 RAB 的分桶方式来理解——本质是同一个问题的不同精细度解法。

### 7.5 训练工程的极致化

| 技术点 | 做法 | 解决的问题 |
|---|---|---|
| **Muon + AdamW 混合优化器**（第一名） | Muon（Newton-Schulz 正交化梯度）优化 Transformer 稠密权重，AdamW 优化 Embedding Table 稀疏参数 | 稠密权重和稀疏 ID 特征的最优更新方式不同，分开用不同优化器收敛更快 |
| **Large Negative Banks + 静态图 InfoNCE**（第一名、第三名的 Scaling Law 发现） | 固定 batch size/负样本数使计算图可静态编译；维护跨 batch 的负样本缓冲区，每步抽取大量负样本 | 负样本数量是生成式推荐里最有效的 scaling 维度——第三名实验显示负样本从 1 扩到 38 万，性能仍在提升、没有天花板 |
| **两阶段训练**（第二名） | Stage1 在全量曝光数据（94%）预训练学基础分布，Stage2 在点击+转化数据上微调校准到高价值区域 | 类似 LLM 的 Pretrain→SFT，先用弱信号但量大的数据学基础表征，再用强信号但量少的数据精调 |
| **推理后过滤历史交互**（第二名） | ANN 检索 Top-K 后，显式移除用户已交互过的物品 | 生成式检索有时会命中"历史正样本相似度高"的已交互物品，过滤后提升新颖性 |
| **Outcome-Conditioned 生成**（第二、三名，借鉴 PinRec） | Decoder 生成时把"目标行为类型"作为条件嵌入注入最后一个位置 | 和第一名的三机制条件化是同一诉求（可控生成）的不同实现方式——特征调制 vs 输入端条件注入 |

### 7.6 Scaling Law 的核心结论（第三名，理论价值最高）

系统性研究了生成式推荐里"哪个维度的 scale 最划算"：

```
Performance ∝ C^α · D^β · N^γ         (C=模型容量, D=负样本规模, N=ID Embedding维度, β 系数最大)
```

**优先级排序（投资回报率从高到低）**：**扩大负样本数量 > 扩大模型容量（深度/宽度）> 扩大 Item ID Embedding 维度**，三者的收益都高于设计更复杂的网络结构。这条结论直接呼应了本项目 §4 里"混合负采样体系"的重要性——不是负采样做得越精巧越好，负样本的**规模**本身就是一个被低估的 scaling 维度。

### 7.7 技术创新奖：检索与排序一体化（范式创新，值得关注但工程门槛最高）

```
L_total = L_semantic-ID(生成下一个感兴趣物品的语义ID，对应检索任务)
        + L_action-prediction(预测用户对该物品的行为类型，对应排序任务)
```

用一个 Decoder-only 模型联合建模"检索"和"排序"两个传统上分离的阶段，逻辑是——两者都依赖同一份用户兴趣表征，联合训练能互相增益（行为预测提供更丰富监督信号，物品生成提供更准确候选），且工业部署上用一个模型替代两个模型，维护成本更低。配合现代 LLM 组件（FlashAttention/SwiGLU/RMSNorm/RoPE/MoE）和两项语义 ID 创新：① 用专门训练的 Decoder-only+InfoNCE 从行为序列里提取"协同 Embedding"（不只用多模态内容 embedding，融合协同过滤信号），② 对 RQ-KMeans 第二级码做**碰撞检测**——多个物品分到同一个 `(id1, id2)` 组合时，搜索次近的聚类中心直到无碰撞，避免语义 ID 精度因码表碰撞而损失。

> 这条方向和第二节提到的"两条路线的分化"呼应：检索排序一体化本质是把 Semantic ID 生成（检索）和传统排序目标（预测行为）统一到一个训练目标里，是生成式范式相比传统"召回排序分离"架构最具颠覆性的延伸方向，但对工程基建（MoE 推理、KV Cache、Grouped GEMM）的要求也最高，目前更多是范式验证阶段。

## 八、常见问答

**Q1：生成式召回和序列召回（SASRec）到底有什么本质区别？**

如果是 Dense Embedding 路线（如本项目），本质区别不大，可以理解为序列召回的加强版：换了更强的骨架（HSTU 去 softmax、支持增量计算）、更完整的负采样训练目标（混合负采样+logQ+难负例+课程学习）、支持条件生成（动作类型）。真正范式级的区别在 Semantic ID 路线——item 不再是连续向量，而是离散的语义 token 序列，检索本身变成"生成即索引"，这是 SASRec 类方法做不到的。

**Q2：HSTU 为什么要去掉 softmax？**

softmax 需要对整行做归一化，依赖当前行全部元素，序列长/要做增量推理时代价高；换成逐点的 SiLU 非线性后，attention 权重的计算是纯逐元素操作，天然支持流式/增量计算，更贴合"生成式"场景里逐步产出下一步表示的需求。用 U 做门控（gate）弥补了去掉 softmax 归一化后可能损失的表达力。

**Q3：为什么正例也要做 logQ 矫正，这不会削弱正例的监督信号吗？**

标准做法只矫正负例（抵消热门负例被过采样导致的打分低估）。这里对正例也矫正，是刻意利用 logQ 值和物品热度的强相关性——冷门正例的 logQ 绝对值大，减去它会显著抬升冷门正例的 logit，相当于变相加权冷门正例的梯度贡献，缓解"过半 item 出现<5次、模型学不动长尾"的问题。这是一种一举两得的设计，不是削弱监督信号，而是重新分配了不同热度正例的梯度权重。

**Q4：课程学习里 hard_topk 为什么是先 0 再从大到小，而不是一直很大？**

前 2 万步用 `hard_topk=0`（即不挑难负例，用全部负例的 loss）是为了让模型在冷启动阶段先学会最基本的粗粒度区分，避免一上来就被高强度难负例的梯度带偏、训练不稳定。之后从 8192 逐步收窄到 128，是标准的"先易后难"课程学习：保留的负例越少，意味着这些负例是从更大候选池里精选出来的最高分（最难区分）负例，训练后期用这些难负例逼模型学出更精细的决策边界。

**Q5：这套方法最终推理阶段还是要做 ANN 检索，那"生成式"体现在哪？**

体现在**训练范式**，不是检索范式：序列里每一个时间步都是一次"用历史生成下一步"的自回归预测，配合因果注意力，一个用户的一条行为序列能产出跟序列长度等量的训练样本，比传统双塔"一个用户一条样本"的信号密度高得多；同时可以把动作类型当条件注入，实现"条件生成"。检索阶段确实和双塔一样走 ANN 内积，这也是 Dense Embedding 路线区别于 Semantic ID 路线（生成的 token 本身就是检索结果）的关键。

**Q6：Semantic ID 路线（TIGER）和 Dense Embedding 路线（本项目/PinRec）该怎么选？**

词表规模、存储成本是硬约束、且冷启动/新品覆盖要求高 → 优先考虑 Semantic ID 路线（用 RQ-VAE 或更轻量的 RQ-KMeans 把连续 embedding 逐级残差量化成离散 codeword，词表远小于 item 总数，语义相近 item 共享 codeword 前缀天然有泛化性）；已经有成熟的双塔+ANN 工程基建，想在此基础上升级序列建模能力、更精细地对齐 CTR/CVR 等连续指标、且不想承担量化误差 → Dense Embedding 路线改造成本更低，本项目就是这类改造的典型案例；实践中也可以两条路线融合（见 Q8）。

**Q7：这套方法和 MIND 多兴趣召回比，解决的是同一个问题吗？**

不完全是。MIND 解决的是"单一 user 向量表达能力不足、多兴趣坍缩"的问题，输出是多个兴趣向量各自检索再融合；生成式召回（本项目）解决的是"如何更充分利用序列里每个位置的训练信号 + 支撑更强的序列骨架 + 条件生成"，输出仍是逐位置演化的单一表示。两者不冲突，理论上可以结合（比如在生成式框架的每一步都路由出多个兴趣分量），但目前工业界公开方案里，两条线大多是分开演进的。

**Q8：Semantic ID 和 Dense Embedding 两条路线是非此即彼的关系吗？（结合 §7.3）**

不是。§2 的对比表是为了讲清楚两条路线各自的核心卖点，但工业/竞赛顶尖方案（§7 第一、二名）显示更常见的做法是**融合**：主体检索仍走 dense embedding + ANN，但额外用 RQ-KMeans 生成语义 ID 作为**辅助特征或正则化信号**注入模型，专门用来缓解 dense embedding 在长尾/冷启动物品上学不好的问题。可以理解为——Dense Embedding 路线负责"精细检索"，Semantic ID 负责"给长尾物品一个兜底的泛化表示"，两者分工不冲突。

**Q9：本项目的 action conditioning（加法注入 embedding）和更精细的方案比，差在哪，怎么改进？**

本项目只做了"加法注入 + loss 侧对点击加权"，相当于用了一个固定权重的简化版融合，且完全没有在 attention 层面做调控。可以借鉴 §7.2 的三机制协同：① 把加法注入换成 FiLM 的仿射调制（γ/β 由动作类型生成，比单纯相加表达力更强）；② 加一个动作类型驱动的软门控（Gated Fusion），让模型自适应决定"这个位置该信任条件化后的表征还是原始表征"；③ 在 attention_logits 上加一个动作类型驱动的偏置矩阵，让模型在算注意力权重时就已经知道该少关注曝光位置、多关注点击/转化位置，而不是等到特征层面才做区分。

**Q10：Scaling Law 研究给了什么可以直接落地的结论？（结合 §7.6）**

如果训练资源有限，优先把预算花在**扩大负样本规模**上（in-batch + 全局负例的总量，本项目的混合负采样体系正是在做这件事），其次才是加深/加宽模型（Transformer 层数、隐层维度），最后才是加大 Item ID Embedding 维度——三者的投资回报率依次递减，且负样本规模在实验里扩到 38 万仍未看到收益天花板，是最值得投入的方向，优先级高于设计更复杂的模型结构。
