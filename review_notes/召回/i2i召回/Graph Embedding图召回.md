# Graph Embedding 图召回（I2I 向量类的图模型分支）· 实战手记

> 视角：召回算法工程师。这篇是 `I2I召回.md` 里"向量类 i2i embedding"分支的深挖——共现统计（ItemCF/Swing）本质是**局部、稀疏**的关联，图 embedding 通过在关系图上传播/游走，把这种局部关联**泛化**成稠密向量，缓解长尾/冷启动覆盖不足的问题。

---

## 项目介绍

> 图召回解决的是纯共现方法（ItemCF/Swing）天生的覆盖率短板——没有共现就没有相似，长尾和新品永远召不出来。核心思路是把用户行为序列构建成 item-item 关系图，再用图上的游走/传播把稀疏的直接共现关系**泛化**到间接关联的 item 上，训练出稠密的 item 向量。
>
> **建图阶段**：从用户行为 session 里构建 item-item 图，边权重 = 共现次数。这里有几个容易踩坑的细节——有向图还是无向图取决于业务场景（顺序是否有强因果意义）；建边范围不能只连相邻对，同一时间窗口内的行为都应该两两连接；权重极低的边（近似孤立随机行为）可以清洗掉，减少图噪声。
>
> **游走+训练阶段**：从 DeepWalk 的无偏随机游走起步，用 Skip-gram 训练 item 向量；后续引入 Node2Vec 的可控游走（在"结构相似"和"同质社区"之间调节），以及阿里 EGES 的**side info 加权融合**——给每个 item 同时用 ID embedding 和多个属性（类目/店铺/品牌）embedding，学一套融合权重，解决长尾 item 因为共现太少学不好向量的问题。
>
> **规模化阶段**：当图规模达到十亿级节点，离线预计算全部转移概率会内存爆炸，改成边遍历边计算（用时间换空间）；为了支持新 item 不训练就能有向量，引入 GraphSAGE / PinSAGE 这类**归纳式**图神经网络方法，通过学习"如何聚合邻居"而不是死记每个节点的向量，新节点也能直接推理出向量。
>
> 最终作为独立一路接入 I2I（ICF 形式），和 Swing 共现召回融合：共现保准、图向量保长尾覆盖，长尾 item 的召回覆盖率提升明显。

---

## 一、为什么要用图，而不是直接统计共现

**ItemCF/Swing 的本质局限**：只能捕捉**直接共现**的 item 对。如果 A-B 共现多、B-C 共现多，但 A-C 从未共现过，纯共现方法永远学不到 A 和 C 有关系——即使它们可能通过 B 存在很强的间接关联。

**图 embedding 的核心价值**：把 item 关系建成图之后，通过**多步游走/多层传播**，让信息沿着图结构扩散——A 通过 B 间接影响到 C 的向量表示，即使 A、C 从未直接共现，最终学出的向量依然能反映这种间接关联。这就是"泛化"能力的来源，直接解决长尾、冷启动 item 覆盖不足的问题。

## 二、方法演进路线

### 2.1 DeepWalk（图 embedding 的奠基方法）

最朴素的思路：把图上的随机游走序列当成"句子"，把 item 节点当成"单词"，直接套用 word2vec 的 Skip-gram 训练。

```
构图（item-item 图，边权 = 共现次数）
  ↓ 无偏随机游走（按边权重为概率随机跳邻居）
  ↓ 生成大量游走序列
  ↓ Skip-gram + 负采样训练
  ↓ item 向量
```

局限：游走是无偏的，无法控制"更倾向探索局部社区"还是"更倾向探索结构相似的远处节点"。

### 2.2 Node2Vec（DeepWalk 改进：可控游走策略）

引入两个超参 `p`（返回参数）、`q`（进出参数），控制游走行为在两种模式间调节：

- **偏 BFS（q 小）**：倾向在起点附近打转，学到的向量反映"同质社区"（这批 item 经常被一起交互）
- **偏 DFS（q 大）**：倾向往远处探索，学到的向量反映"结构相似"（两个 item 在图里的角色/位置类似，即使不在同一个社区）

工业界很少纯粹用 Node2Vec，但它提出的"游走策略可调"思想影响了后续很多图召回方法的设计。

### 2.3 Item2Vec（最简化版本，工业界常见起点）

**完全不建显式图**，直接把每个 session/购物车列表当成一句"话"，session 内所有 item 互相当作上下文（不要求相邻，整个 session 内两两都算共现），直接做 Skip-gram：

```
session = [item_A, item_B, item_C]
→ 直接当训练样本：(A,B), (A,C), (B,C) 互为正样本对
→ Skip-gram + 负采样
```

**没有建图、没有随机游走这两步**，本质上等价于把每个 session 看成一个"全连接的小型共现图"。工程实现最简单，很多公司图召回的第一版落地就是从 Item2Vec 起步，效果和实现成本都比较友好。

### 2.4 EGES（阿里，重点方法，解决冷启动）

上面几种方法都只用 item ID 的共现关系，长尾/新品因为共现次数太少，学出来的向量质量差。EGES 的核心改进是**融合 side information**：

```
每个 item 准备多套 embedding：
  E_id(i)、E_category(i)、E_shop(i)、E_brand(i) ...

加权融合（权重可学习，类似简化版注意力）：
  H(i) = Σ_s w_i^s · E_s(i) / Σ_s w_i^s
```

**为什么能解决冷启动**：新 item 的 ID embedding 学得差，但它的类目/店铺/品牌 embedding 是和大量老 item 共享的（这些老 item 已经训练充分），融合后新 item 依然能拿到一个还不错的向量。

> 完整推导（建图细节、有向无向选择、多跳建边、图噪声清洗、大图游走内存优化、变长 side info 聚合、冷启动简化平均等工程细节）见对应聊天记录整理，这里只保留核心结论。EGES 本身是**纯 I2I 方法**（产出 item 向量），线上通常接入 ICF 形式作为独立一路召回；若要做 U2I，需要额外把用户历史 item 向量聚合成用户向量，这是衍生用法不是核心设计。

### 2.5 GraphSAGE / PinSAGE（归纳式，彻底解决新节点问题）

上面所有方法（DeepWalk/Node2Vec/Item2Vec/EGES）都是**transductive（转导式）**——向量表**查表**得到，只有训练时图里出现过的节点才有向量，新节点必须等下一次全量重训练才能拿到向量。

**GraphSAGE 的关键改进**：不直接学"每个节点的向量"，而是学一个**聚合函数**——"如何把一个节点自身的特征和它邻居的特征聚合成向量"。这个聚合函数（mean/pooling/LSTM 聚合器）是通用的，训练完之后，**任何新节点，只要有自身特征和邻居信息，直接跑一遍聚合函数就能拿到向量，不需要重新训练**。

```
h_v = AGGREGATE(自身特征, {邻居节点特征})   # 聚合函数是学出来的，节点向量是算出来的
```

**PinSAGE（Pinterest 工业级实现，非常经典的行业案例）**在 GraphSAGE 基础上做了大规模工程优化：

- **基于随机游走的重要性池化**：不是均匀采样邻居，而是从目标节点发起多次随机游走，按访问频率给邻居分配权重（访问越频繁的邻居越重要），聚合时按这个重要性加权
- **课程学习式难负样本挖掘**：训练早期用简单负样本（随机负），随着训练推进逐渐加入更难的负样本（图上距离较远但还有一定关联的节点），提升区分力
- **MapReduce 批量离线推理**：支持十亿级节点规模的高效离线向量计算

PinSAGE 是工业界公开的图召回论文里规模最大、工程细节最全的案例之一，能落地支撑十亿级图规模。

## 三、线上链路

1. 离线训练：构图（或直接用 session 序列）→ 游走/聚合 → 训练得到 item 向量；
2. 全量 item 向量建 ANN 索引（HNSW 等）；
3. 线上取用户近期 trigger item，查 ANN 取 TopN 近邻；
4. 和共现类 I2I（Swing）结果分数归一后合并，去重截断。

> 归纳式方法（GraphSAGE/PinSAGE）多一步：新 item 上线时无需重训练整张图，直接用已训练好的聚合函数对新节点跑一次推理即可拿到向量，补进索引。

## 四、方法演进对比表

| 方法 | 是否建图 | 训练方式 | 是否支持新节点直接推理 | 核心解决的问题 |
|---|---|---|---|---|
| **DeepWalk** | 是（无偏游走） | Skip-gram | 否（transductive） | 图 embedding 奠基，泛化共现关系 |
| **Node2Vec** | 是（有偏游走） | Skip-gram | 否 | 游走策略可调（社区 vs 结构相似）|
| **Item2Vec** | 否（session 内两两共现） | Skip-gram | 否 | 最简化实现，无需建图/游走 |
| **EGES** | 是 | Skip-gram + side info 加权融合 | 否（图外新品用简单平均兜底） | 长尾/新品因共现少导致向量差 |
| **GraphSAGE / PinSAGE** | 是 | 学习聚合函数 | **是（inductive）** | 新节点无需重训练即可拿到向量 |

## 五、常见坑

**坑 1 · 建图时只连相邻对，漏掉间接关联**

同一 session/时间窗口内的行为都应该两两建边，不能只连相邻的 (A-B, B-C)，否则 A-C 这类同窗口但非相邻的关联会丢失。

**坑 2 · 大图预计算转移概率导致 OOM**

图节点数巨大时，游走前预计算所有节点的转移概率会内存爆炸。解法：游走到某节点时才实时计算它的转移概率（用时间换空间，接受一定重复计算）。

**坑 3 · 图外新 item 没有 side info 加权权重，强行用别的 item 的权重效果一般**

EGES 训练出的加权权重是每个图内 item 独有的，图外新品没有这个权重。实践发现用所有图内 item 的平均权重去加权效果和直接简单平均差不多，工程上可以直接简化成简单平均。

**坑 4 · 离线边预测评估任务区分度差**

论文里常用的"预测两个节点间是否存在边"作为离线评估任务，实践中会发现无论怎么设计（drop 不同比例的边测预测准确率），结果都很接近，区分度不够。更实用的做法：自建业务相关的评估任务，比如用用户历史 item 向量均值做召回，算 TopK 准确率。

**坑 5 · 图 embedding 和共现类 I2I 直接拼接分数量纲不一致**

图向量的相似度分数和 Swing 共现分数量纲完全不同，直接加权融合前必须做分位归一化，否则某一路会系统性主导排序。

## 六、常见问答

**Q1：图 embedding 和纯共现方法（ItemCF/Swing）到底解决了什么本质不同的问题？**

共现方法只能捕捉**直接**共现的 item 对，图 embedding 通过多步游走/传播能捕捉**间接**关联（A 通过 B 关联到 C，即使 A-C 从未直接共现）。这是覆盖率大幅提升的根本原因。

**Q2：Item2Vec 和 DeepWalk 的核心区别是什么？**

Item2Vec 不建显式图、不做随机游走，直接把 session 内所有 item 当上下文两两配对训练；DeepWalk 需要先建图再游走。Item2Vec 可以理解为"把每个 session 当成一个全连接的小共现图"的简化版本，实现成本更低，是很多公司图召回落地的第一步。

**Q3：为什么说 DeepWalk/Node2Vec/EGES 都是"transductive"，这有什么实际影响？**

这些方法本质上是给训练图里出现过的每个节点学一个专属的 embedding 向量（查表得到），新节点没在训练图里出现过，就没有对应的向量——必须等下一轮全量重训练，把新节点纳入图重新走一遍才能有向量。这意味着新品上线到能被图召回覆盖之间，存在一个训练周期的延迟窗口。

**Q4：GraphSAGE/PinSAGE 怎么解决新节点问题？**

它们学的不是"每个节点的向量"，而是"怎么从节点自身特征+邻居特征聚合出向量"这个聚合函数。聚合函数训练好之后是通用的，新节点只要有自身特征和已知的邻居关系，直接跑一次聚合函数推理即可拿到向量，不需要重新训练整张图。

**Q5：工业界实际用得最多的是哪个？**

按落地门槛从低到高：**Item2Vec**（最简单，很多公司第一版就是它）→ **EGES**（有明确冷启动收益，阿里/淘宝生态验证过，国内工业界引用最多）→ **GraphSAGE/PinSAGE**（新品覆盖要求高、图规模巨大时才需要上，工程复杂度显著更高）。DeepWalk/Node2Vec 更多是学术奠基意义，工业界直接落地案例相对少，一般会跳过它们直接上 EGES 或 GraphSAGE 系。

**Q6：图召回和双塔 item 塔产出的向量都能做 I2I，选哪个？**

双塔 item 塔向量是**任务导向**的（为点击/时长这些目标优化出来的），图向量是**结构导向**的（反映 item 之间的关系网络，不直接绑定某个业务目标）。两者信号来源不同，工业界常见做法是两路都留、分数归一后融合，而不是二选一。

## 七、方法选型一句话

- 想快速落地验证图召回的价值 → **Item2Vec**，成本最低。
- 长尾/新品覆盖是主要痛点，且能接受一定训练周期延迟 → **EGES**，最成熟、案例最多。
- 新品上线频繁、要求新品立刻有向量、图规模巨大 → **GraphSAGE/PinSAGE**，归纳式是唯一解，但工程复杂度显著提升。
- 单纯做学术对比/理解游走机制 → DeepWalk/Node2Vec，不建议作为工业首选。

## 八、监控指标

- 离线：自建业务相关的 TopK 召回准确率（避免用边预测任务，区分度差）、长尾 item 覆盖率。
- 在线：图召回通路的召回覆盖率、和共现类 I2I 的重合度/互补度、长尾 item 曝光占比提升幅度。
