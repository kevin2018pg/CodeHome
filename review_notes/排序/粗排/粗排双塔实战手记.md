# 粗排双塔实战手记

> 视角：推荐算法工程师。从 XGB 粗排到多目标双塔粗排的完整演进，涵盖单目标建模、多目标扩展、精排对齐三个阶段。

---

## 一、项目介绍

### 背景

首页 feed 流的粗排层原本使用 **XGB 架构**，特征工程依赖大量手工交叉特征，扩展性差、迭代成本高，且单一 CTR 目标与精排层的多目标优化存在严重割裂：

- 粗排只召回"用户可能点击的"，精排却在优化点击+时长+互动的综合价值
- 进精排的候选质量差，直接限制精排天花板
- XGB 无法利用用户行为序列，对冷启动和长尾 item 表达弱

### 演进路径（两阶段）

```
2021.10  XGB粗排 → DSSM单目标粗排（CTR）         → CTR +7.3%，人均点击 +3.75%
2022.01  单目标双塔 → 多目标双塔 + 精排蒸馏对齐   → CTR +3.71%，时长 +5.25%，互动 +5.64%
```

---

## 二、阶段一：单目标 DSSM 粗排（XGB 替换）

### 2.1 核心思路

用传统 DSSM 双塔架构替代 XGB，以点击为目标建模：

- 移除精排模型特征 pipeline 中的**用户-物料交叉特征**（交叉特征破坏双塔可分解性，item 向量无法离线预算）
- 用户侧用行为特征，物料侧用 side info + 统计特征
- 以点击为目标，in-batch softmax 对比学习

### 2.2 塔内引入 SENet 门控（降噪关键）

双塔非线性融合时，无效特征的噪声会被放大（MLP 的非线性会把弱特征的随机误差传导进去）。在**用户塔和物料塔分别**加类 SENet 的门控网络：

```
特征 Embedding 拼接
    ↓ SENet (Squeeze → Excitation → Reweight)
    ↓ 对各 field 自适应加权，压制无效特征
    ↓ 塔 MLP
    ↓ 用户/物料向量
```

意义：**双塔信息瓶颈**使得特征质量极为关键——MLP 能记住但不能区分"有用噪声"，SENet 在进 MLP 前就把噪声门控掉，让有效信息畅通到塔顶。

### 2.3 负样本策略（借助精排 pipeline）

初期沿用精排的数据 pipeline，但粗排面向全库，负样本需要额外设计：

| 负样本来源 | 作用 | 说明 |
|---|---|---|
| **热度随机负采样** | 主体负样本，覆盖全库分布 | 在现有样本基础上按热度随机采，热门 item 出现概率更高 |
| **精排打分中间段（hard negative）** | 提升边界区分力 | 精排打高分但处于中游的 item，召回认为好但精排说"一般" |
| **精排打分末尾（easy negative）** | 稳定训练 | 精排打分极低的 item，明确负样本，稳定 loss 下界 |
| **买车用户画像构造 hard negative** | 业务导向难负 | 基于业务逻辑：买车用户对非车类内容几乎无兴趣，构造强负信号 |

> 关键思路：借助**精排打分**划分负样本难易等级，比纯随机更有梯度，且对齐了精排的"好坏"判断——精排说好的（中段）当难负，精排说差的（末尾）当易负。

### 2.4 阶段一效果

> CTR **+7.3%**，人均点击 **+3.75%**

## 三、阶段二：多目标双塔 + 精排对齐

### 3.1 问题：单目标优化时长效果差

直接在点击 loss 上加权时长 loss（加权 InfoNCE），时长有提升但**点击下降**——因为两个目标存在冲突，简单加权会相互干扰。

### 3.2 时长目标建模细节

用户的浏览时长有长尾噪声（极短时长 = 误点/广告，极长时长 = 挂机），需要预处理：

```python
# 去除噪音
duration = clip(duration, min=3, max=300)  # 去掉极端值

# log 压缩：让时长分布更平滑，防止长时长样本主导梯度
duration_label = log(1 + duration)
```

### 3.3 CGC 结构改造 item 塔（解决任务冲突）

借鉴精排的多目标建模（腾讯 PLE 的 CGC），**只改造 item 塔**（用户侧样本稀疏，不适合多任务分离）：

```
Item 特征
  ↓
CGC 结构（Customized Gate Control）
  ├─ 共享 Expert（点击+时长共同依赖的特征表达）
  ├─ 点击专属 Expert → Gate_ctr → item_vec_ctr
  └─ 时长专属 Expert → Gate_dur → item_vec_dur

User 塔：保持不变，输出单一 user_vec

打分：
  score_ctr = user_vec · item_vec_ctr
  score_dur = user_vec · item_vec_dur
```

**为什么只改 item 塔**：用户侧的点击/时长行为都是该用户产生的，样本高度重叠，共享 user tower 不会带来负迁移；item 侧不同内容在点击率和时长上差异更大（短视频 vs 长文章），分离建模收益更明显。

### 3.4 DWA 动态 loss 平衡

点击 loss（交叉熵，量级~1）和时长 loss（MSE，量级~10²）量级差异大，直接加权不稳定。使用 **DWA（Dynamic Weight Averaging）** 自动调整：

```python
# 根据上一轮 loss 变化速度动态调整权重
w_ctr = loss_ctr_prev / loss_ctr_curr   # 下降慢 → 权重自动增大
w_dur = loss_dur_prev / loss_dur_curr

# 归一化后作为权重
total_loss = (w_ctr * loss_ctr + w_dur * loss_dur) / (w_ctr + w_dur)
```

效果：两个任务收敛速度保持相近，避免某个任务主导训练而另一个没学到。

### 3.5 多分数融合（工程难点）

item 塔现在输出两套向量（ctr 和 dur），需要**两个 ANN 索引**，线上打分需要融合：

```
final_score = α × score_ctr + β × score_dur
```

**α/β 怎么定**：

```
Step 1：离线 abtest，根据不同融合比例对应的整体业务表现确定权重范围
Step 2：以 AUC（点击预测准确度）+ PNR（时长排序质量）为离线指标做网格搜索
Step 3：上线 abtest 精调，固定最优比例 → 减少线上反复调参成本
```

### 3.6 互动类 label 引入（稀疏目标的处理）

互动类行为（点赞/收藏/评论）样本量极稀疏，单独建任务头训练不稳定。处理方式：

**不扩展模型结构**，直接在点击目标的 loss 函数里对互动 label 加权：

```python
# 互动样本当作"更强的点击正样本"
weight = 1.0 + λ_like * is_like + λ_collect * is_collect + λ_comment * is_comment
loss = weight * CrossEntropy(score, label)
```

原则：**稀疏目标不建头，加权到已有 loss 里**，保证梯度充足。

### 3.7 精排蒸馏（精排对齐核心）

以上改造让粗排在多目标上更均衡，但粗排和精排的"价值函数"仍有差距。加入精排模型蒸馏作为第四个目标：

```
精排 teacher：对物料打分，log 归一化后得到 ranker_score（0~1）
粗排 student：item 塔扩展一个蒸馏 head

distill_loss = BCELoss(distill_head(item_vec), ranker_score.detach())

total_loss = w_ctr × loss_ctr
           + w_dur × loss_dur
           + w_interact × loss_interact
           + w_distill × distill_loss
```

**工程落地（T+1 蒸馏）**：

```
Day N：精排每天跑完 → 把当天所有曝光物料的精排分存到特征仓
Day N+1：粗排训练时 join 进来精排分 → 有精排分的样本额外加蒸馏 loss
```

**精排分已归一化（log 日志里存的），直接用 BCE 回归，简单高效。**

最后：多目标的 loss 函数权重 + 线上多向量融合比例联合优化（loss 侧用 DWA，向量融合侧用 grid search + abtest）。

### 3.8 阶段二效果

> CTR **+3.71%**，人均点击 **+1.51%**，人均时长 **+5.25%**，人均互动 **+5.64%**

## 四、完整迭代演进路线

```
v0：XGB 粗排（手工特征交叉，单 CTR，扩展性差）
  ↓
v1：DSSM 单目标双塔（替换 XGB，SENet 降噪，精排分辅助负样本）
    → CTR +7.3%
  ↓
v2：加权时长 loss（简单多目标验证）→ 时长涨但点击跌，验证冲突存在
  ↓
v3：CGC 改造 item 塔 + DWA 平衡 loss + 多分数融合（正式多目标）
  ↓
v4：互动 label 加权到点击 loss（稀疏目标轻量引入）
  ↓
v5：精排蒸馏 BCE loss + 多目标联合优化（精排对齐）
    → CTR +3.71%，时长 +5.25%，互动 +5.64%
```

## 五、常见问答

**Q1：粗排为什么要用双塔而不是 XGB？**

XGB 依赖手工交叉特征，无法利用行为序列，可扩展性差；双塔可以自动学习特征组合，支持用户序列建模，item 向量离线预算后 ANN 检索，延迟可控。粗排候选量（几千）远小于召回（几十万），可以承受略高的模型复杂度。

**Q2：粗排双塔和召回双塔有什么区别？**

| | 召回双塔 | 粗排双塔 |
|---|---|---|
| 候选规模 | 全库（亿级）→ 取 top-K（百～千）| 召回结果（千级）→ 取 top-N（百）|
| 计算方式 | ANN 近似检索（快但有误差）| 可以做**精确内积**甚至轻量交叉（候选少）|
| 特征复杂度 | 必须严格可分解（item 向量离线算）| 可以做少量 user-item 交互（候选少，能实时算）|
| 模型复杂度 | 轻量（时延要求严格）| 稍重（百毫秒级可接受）|

**Q3：粗排为什么要 SENet，精排里不也有吗？**

都可以用，但作用场景不同。粗排 SENet 主要解决"移除交叉特征后，单侧特征噪声被 MLP 非线性放大"的问题；精排 SENet 是在更复杂交叉网络里做特征选择。粗排的信息瓶颈（双塔无法交叉）使特征质量更关键，SENet 的收益反而更显著。

**Q4：CGC 和 MMoE 有什么区别？为什么用 CGC？**

MMoE 所有 expert 全部共享，任务间可能负迁移（相互干扰）；CGC（Customized Gate Control）有专属 expert 和共享 expert，专属 expert 只服务一个任务，减少任务干扰。对于点击和时长这两个有一定冲突的目标，CGC 比 MMoE 更适合。

**Q5：为什么只改 item 塔，不改 user 塔？**

用户侧的点击和时长行为都是同一个用户产生的，样本高度重叠，强行分离 user 表示收益小且可能导致表示不稳定（用户数据量相对更稀疏，多任务分头风险更高）；item 侧不同内容在点击率和时长偏好上差异更大，分离建模可以让 item_vec_ctr 和 item_vec_dur 各自专注于不同维度的物料质量。

**Q6：DWA 是什么，和固定权重加权有什么区别？**

固定权重无法应对训练过程中 loss 量级变化——两个 loss 初始量级就可能差一到两个数量级，某个任务会主导训练。DWA（Dynamic Weight Averaging）根据各任务 loss 变化速度自动调整权重（下降慢的权重增大），让两个任务以相近速度收敛，不需要手动调权重。

**Q7：精排蒸馏为什么用 BCE 而不是 KL 散度？**

KL 散度是分布级别的蒸馏（需要对一个集合的 softmax 分布对齐），适合分类任务。这里精排分已经归一化到 `[0,1]`（log 日志里存的），直接当成"item 的综合价值概率"做回归，BCE（Binary Cross Entropy）更简单直接，避免了 softmax 温度等超参调试。

**Q8：精排分 T+1 蒸馏，昨天的分和今天有偏差怎么办？**

有一定偏差，但实践证明 T+1 的精排分仍然有效。原因：精排对 item 的相对排序比绝对分数稳定——昨天精排认为好的 item 今天大概率仍然好。如果追求更实时，可以存精排分的滑动均值（多天加权）来降低单日噪声。

**Q9：多分数融合（α×ctr + β×dur）怎么保证 ANN 仍然可用？**

两套向量（item_vec_ctr, item_vec_dur）需要两个 ANN 索引，分别检索 top-K，再合并打分取最终 top-N。或者：将 α/β 预融合到 user 向量里：

```
user_vec_combined = concat(α × user_vec, β × user_vec)
item_vec_combined = concat(item_vec_ctr, item_vec_dur)
score = user_vec_combined · item_vec_combined = α×(u·v_ctr) + β×(u·v_dur)
```

这样 item 向量合并成一个大向量，仍然只需一个 ANN 索引。

**Q10：互动类 label 为什么不单独建任务头？**

互动样本极稀疏（点赞/评论比点击稀疏 10~100 倍），单独建头训练不稳定，梯度噪声大；但它的信号价值高（互动 = 强正反馈）。直接用它加权到点击 loss 里，相当于告诉模型"这些样本更重要"，既引入了互动信号，又避免了稀疏任务建模的不稳定性。

## 六、关键设计原则总结

1. **渐进式迭代**：先用最简单的方案验证方向（加权 loss），再上结构优化（CGC），最后做精排对齐（蒸馏）。每步都有 offline 指标验收。
2. **稀疏目标不建头，用加权**：互动这类稀疏目标直接加权到已有 loss，避免稀疏任务建模不稳定。
3. **冲突目标用 CGC 分离**：点击和时长有天然冲突，用专属 expert 隔离，共享部分提取公共表示。
4. **精排蒸馏是对齐的根本手段**：soft label 让粗排的向量空间朝精排的"综合价值函数"靠拢，比单纯优化点击更能提升全链路效果。
5. **工程细节决定落地**：DWA 动态权重、T+1 蒸馏存取、多分数 grid search 融合，这些工程决策和模型设计同等重要。
