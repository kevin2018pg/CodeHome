# 2025 腾讯广告算法大赛四个开源方案对比

> 任务：根据用户历史行为、用户/广告特征及动作信息，从大规模候选广告中检索下一条可能交互的广告。
>
> 初赛与决赛的数据规模、动作空间、候选池和指标权重不同，因此公开分数不能完全机械横比。

## 第一部分：常用模型与操作理解

### 1.1 先理解任务：这里的“生成式推荐”生成了什么

四个方案都不是直接预测 CTR，也不是像语言模型一样逐字符生成广告 ID。它们共同采用：

```text
用户历史序列
→ Sequence Encoder
→ 生成 User Query：[B,D]

候选广告特征
→ Item Encoder
→ 生成 Item Embedding：[C,D]

score(u,i) = cosine(query_u, item_i)
→ Top-K 检索
```

所以这里“生成”的是用户当前状态对应的 Query 表示，最终仍通过向量检索得到广告。它与普通双塔的区别是：User Query 不是由静态用户画像直接得到，而是由因果序列模型从整条行为历史产生。

统一记号：

```text
B：Batch Size
S：序列长度，本题代码通常为 maxlen+1=102
D：序列统一表示维度
F：字段数量
E：单字段 Embedding 维度
H：Attention Head 数
d：单个 Head 维度，d=D/H
C：推理候选广告数量
M：一个 Batch 中参与 Loss 的有效 next-item 位置数
```

完整训练目标是：

```text
让 Query 靠近下一条真实广告的 Item Embedding
让 Query 远离随机广告、其他用户广告等负样本
```

### 1.2 数据规模、序列长度与“样本量”口径

官方公开数据分为两个规模：

```text
TencentGR-1M（初赛）：
用户/序列数：1,001,845
广告总数：4,783,154
推理候选：约 660,000
历史 Item 最大长度：100
平均历史长度：91.06

TencentGR-10M（复赛/决赛）：
用户/序列数：10,139,575
广告总数：17,487,676
推理候选：3,637,720
历史 Item 最大长度：100
平均历史长度：97.29
```

模型还会加入 User Token，因此语义上的最大有效输入约为：

```text
1 个 User Token + 100 个历史 Item Token = 101 个 Token
```

四个仓库通常使用 `maxlen=101`，Dataset 再分配 `maxlen+1=102` 的数组，额外位置服务于错位、对齐或 Padding。因此代码里的 `S=102` 不表示有 102 条历史行为。

#### 一条用户序列如何产生多个训练位置

```text
原始序列：
U → A → B → C → D

seq：
[U,A,B,C]

pos：
[A,B,C,D]
```

一次 Causal Forward 并行训练：

```text
[U]       → A
[U,A]     → B
[U,A,B]   → C
[U,A,B,C] → D
```

所以要区分三种口径：

```text
用户序列口径：
初赛约 100 万，复赛/决赛约 1014 万

有效 next-item 位置口径：
初赛约 1,001,845×91.06 ≈ 9123 万
复赛/决赛约 10,139,575×97.29 ≈ 9.86 亿

评测 Query 口径：
通常一个待预测用户对应一个最终 Query
```

上面的 next-item 位置数是按平均序列长度估算，具体仓库还可能切分训练集或截断序列。

#### 负采样是否计入样本量

通常不计入。推荐的汇报方式是：

```text
训练数据：100 万条用户序列
监督实例：约 9100 万个有效 next-item 位置
负采样：每个位置 1 个随机负样本用于构建共享池
       + In-batch Negative / Popularity Negative
```

动态负样本会随 Batch Size、随机种子和 Hard Top-K 改变，把它们算入“数据集样本量”会导致同一份数据仅修改 Batch Size 后样本量也发生变化。负样本更适合单独报告为“每个正样本看到多少负候选”或“计算了多少正负 Pair”。

### 1.3 字段 Embedding、Token 和序列表示

原始输入主要有四类：

```text
ID 特征：
user_id、item_id、离散类别
→ Embedding Lookup

多值特征：
兴趣列表、类目列表
→ 多个 Embedding → sum/mean pooling

连续特征：
CTR、时间差、统计值
→ 归一化/分桶，或 Linear 投影

多模态向量：
图像、文本预训练 Embedding
→ Linear 投影到较小维度
```

每条行为最终需要压成一个统一的 `D` 维 Token：

```text
field_1:[B,S,E1]
field_2:[B,S,E2]
...
→ concat
→ MLP / FeatureInteractionEncoder
→ token:[B,S,D]
```

这里要区分：

```text
字段 Embedding：一个原始字段的局部表示
行为 Token：一个时间位置上所有 Item/Action/Time 字段融合后的表示
序列 Hidden State：Token 经过多层序列模型后的上下文表示
User Query：最后一个有效 Hidden State 或聚合结果
```

候选 Item Encoder 必须能脱离用户独立计算：

```text
item_features_i → item_embedding_i
```

这样才能离线预计算全部候选向量。用户和候选发生复杂 Cross-Attention 虽然表达力更强，但会失去大规模 ANN 检索能力。

### 1.4 SASRec 与 Causal Self-Attention

SASRec 是这类比赛最常见的 Baseline：

```text
Item Token + Position Embedding
→ 多层 Causal Transformer
→ 每个位置预测下一 Item
```

普通多头注意力：

```text
Q = XWq                     [B,H,S,d]
K = XWk                     [B,H,S,d]
V = XWv                     [B,H,S,d]

Score = QK^T / sqrt(d)      [B,H,S,S]
A = softmax(Score + Mask)
Y = A V                     [B,H,S,d]
```

Causal Mask 规定第 `t` 个位置只能读取 `0...t`：

```text
位置 t 不能看到未来 Item
→ 训练时不会泄露预测目标
→ 所有位置可以并行训练 next-item
```

复杂度主要是：

```text
时间复杂度：O(B·H·S²·d) ≈ O(B·S²·D)
注意力矩阵：O(B·H·S²)
```

序列只有约 100 时成本通常可以接受。四个方案的核心差别不在“有没有因果 Mask”，而在 Token 如何构造、Attention 如何改造、负样本如何组织。

### 1.5 HSTU：推荐原生的序列单元

HSTU 全称 Hierarchical Sequential Transduction Unit，来自 Meta 的生成式推荐工作。这里用到的是其 Sequential Transduction Unit 思路。

典型单层：

```text
Z = SiLU(XW)
U,V,Q,K = Split(Z)

A = SiLU(QK^T / sqrt(d) + RelativeBias)
Y = A V

DeltaX = Wo(LayerNorm(Y) ⊙ U)
X_next = X + DeltaX
```

与标准 Transformer 的关键区别：

```text
标准 Attention：
A = softmax(Score)
每行权重和固定为 1

HSTU Pointwise Attention：
A = SiLU(Score)
不要求权重非负，也不要求权重和为 1
```

Softmax 更像“在历史行为之间分配固定总量的注意力”；未归一的 Pointwise Attention 可以让多个相关行为同时产生较强响应，保留一定的兴趣数量和强度。

`U` 是逐通道门控：

```text
Y：从历史聚合到的信息
U：当前 Token 决定哪些通道应该通过
LayerNorm(Y) ⊙ U：内容聚合与当前状态共同决定更新量
```

HSTU 并不自动等于“更快”：

```text
完整 QK^T 仍然是 O(S²D)
真正的吞吐优势依赖 fused kernel、jagged tensor、长度采样等系统实现
```

四个仓库里的“HSTU”并不完全相同：

```text
Kaipeng：
最接近 SiLU Pointwise Attention，不做 Softmax

O_o：
普通 QK、RoPE QK、时间 Bias 三路自定义聚合

bug-maker6：
SiLU 后 clamp，再除以行权重和，重新做了归一化

Leemenghao：
没有使用 HSTU，仍是 Flash Causal Transformer
```

因此不能只看类名判断模型是否遵循原论文。

### 1.6 FiLM：条件信息控制特征通道

FiLM 全称 Feature-wise Linear Modulation，由 Ethan Perez 等人在 2017 年提出，发表于 AAAI 2018。

给定被调制特征 `x` 和条件向量 `z`：

```text
gamma, beta = ConditionNetwork(z)
FiLM(x | z) = gamma ⊙ x + beta
```

Kaipeng 采用更稳定的残差形式：

```text
gamma, beta = Linear(user_vector)
item'_t = item_t ⊙ (1 + tanh(gamma)) + beta
```

维度为：

```text
user_vector：[B,D]
gamma/beta：[B,D]
item_token：[B,S,D]

广播后：
item'_t[b,s,d]
= item_t[b,s,d] * (1+gamma[b,d]) + beta[b,d]
```

作用：

```text
gamma：按用户放大或抑制 Item Token 的不同通道
beta：按用户补充新的通道偏置
```

相比每个时间步都做 `concat(item,user)→MLP`：

- 用户只编码一次；
- 不增加 HSTU 输入宽度；
- 引入显式乘性交互；
- 候选 Item Tower 仍可独立预计算。

局限是 Kaipeng 对整条序列使用同一组 `gamma/beta`，表达稳定用户偏好，但不能针对每个行为位置产生不同调制。

### 1.7 RoPE：把相对位置写入 Q/K

RoPE 全称 Rotary Position Embedding，由 Su Jianlin 等人在 RoFormer 中提出。

它不把位置向量直接加到 Token 上，而是对每个 Head 的 Q/K 两两通道做旋转：

```text
q'_t = R(t) q_t
k'_s = R(s) k_s
```

点积满足：

```text
(R(t)q)^T(R(s)k)
= q^T R(s-t) k
```

因此 Attention Score 自然包含相对距离 `s-t`。

维度不变：

```text
Q/K 输入：[B,H,S,d]
RoPE 后： [B,H,S,d]
```

作用：

- 不增加 Token 维度；
- 比绝对 Position Embedding 更自然地表达相对顺序；
- 位置外推通常更好；
- 适合行为先后顺序建模。

RoPE 表达的是“第几个位置”，不是“真实过去了多久”。行为间隔 10 秒和 10 天，如果序列位置相邻，RoPE 本身无法区分，所以通常还要加入 Relative Time Bias。

### 1.8 时间建模：绝对时间、相对时间和位置不是一回事

推荐序列常见四种时间信息：

#### 离散日历特征

```text
timestamp
→ hour / weekday / weekend
→ Embedding
```

用于表达每天、每周的周期规律。

#### 周期 sin-cos

```text
hour_sin = sin(2π·hour/24)
hour_cos = cos(2π·hour/24)
```

相比直接使用整数，23 点和 0 点在表示空间中相邻。

#### Fourier 绝对时间

```text
phi(t) = [
  sin(2πt/p1), cos(2πt/p1),
  ...
  sin(2πt/pK), cos(2πt/pK)
]

time_emb = phi(t) W
```

多个周期 `p1...pK` 同时覆盖天、周、月等尺度。O_o 使用 12 个频率，所以：

```text
timestamp:[B,S]
→ 24维 sin-cos
→ Linear(24,D)
→ [B,S,D]
```

#### Relative Time Bias

```text
delta_t(i,j) = |t_i - t_j|
bucket = Bucketize(log(delta_t+1))
bias(i,j) = Embedding(bucket)
```

输出：

```text
[B,S,S] 或 [B,H,S,S]
```

再加到 Attention Logit，直接影响当前行为读取不同历史行为的强度。

总结：

```text
RoPE：相对序列位置
hour/weekday：日历周期
Fourier：多尺度绝对时间
Relative Time Bias：两条行为真实时间距离
```

### 1.9 SENet：学习字段重要性

SENet 最初用于图像通道重标定，在 CTR/推荐中可以把“通道”改成“字段”。

输入字段 Token：

```text
X：[B,S,F,E]
```

先对每个字段的 Embedding 维做聚合：

```text
z_f = Mean(X_f, dim=E)       [B,S,F]
```

再用小 MLP 生成字段权重：

```text
a = sigmoid(W2·ReLU(W1z))    [B,S,F]
X'_f = a_f · X_f             [B,S,F,E]
```

作用是让模型动态判断：

```text
当前样本中 Item ID 是否重要
多模态字段是否可信
某个用户属性是否需要增强
```

它与 Attention 的差别：

```text
SENet：每个字段生成一个门控权重，不做字段两两内容匹配
Self-Attention：每个字段都与其他字段计算相关性
```

所以 SENet 更轻量，复杂度近似线性依赖字段数。

### 1.10 Bilinear 特征交叉

普通拼接：

```text
concat(e_i,e_j) → MLP
```

Bilinear 显式加入乘性交互：

```text
cross(i,j) = (e_i W_ij) ⊙ e_j
```

或者简化为：

```text
cross(i,j) = e_i ⊙ e_j
```

与 FM 的点积不同，Bilinear 通常保留 `E` 维向量，而不是立刻压成标量：

```text
FM：       <e_i,e_j> → 1个分数
Bilinear： (e_iW)⊙e_j → E维交叉表示
```

Leemenghao 只为少量指定字段对建立 Bilinear，避免所有 `F²` 组合导致参数和噪声迅速增加。

### 1.11 FeatureInteractionEncoder

O_o 没有直接使用 SENetBilinearDNN，而是先压缩全部字段，再生成通道相关的乘性更新：

```text
X0 = Concat(fields)                 [B,S,D_in]
X  = X0 W_down                     [B,S,D]
H  = ReLU(X W_expand)              [B,S,R·D]
H  = Reshape(H)                    [B,S,R,D]
Y  = X + X ⊙ Sum_R(H)              [B,S,D]
```

它同时完成：

- 从高维字段拼接压缩到统一 `D`；
- 产生输入相关的 Channel Gate；
- 用乘法提升非线性交互能力。

但它不是显式枚举所有字段对，字段交叉主要在压缩后通道空间发生。

### 1.12 RMSNorm、SwiGLU 与 Residual

#### RMSNorm

```text
RMSNorm(x)
= gamma ⊙ x / sqrt(mean(x²)+eps)
```

它不减均值，只归一化均方根，计算比 LayerNorm 略简单。

#### SwiGLU

```text
up   = xW_up
gate = xW_gate
y = (up ⊙ SiLU(gate)) W_down
```

相比 GELU FFN：

```text
GELU FFN：固定非线性
SwiGLU：输入相关 Gate 控制每个隐藏通道
```

#### Residual

```text
X_next = X + SubLayer(Norm(X))      # Pre-Norm
```

恒等残差路径让梯度可以跨层传播。仓库代码同时存在 Pre/Post-Norm 变体，深层模型通常优先选择 Pre-Norm 或接近恒等初始化。

### 1.13 Flash Attention 与分块在线 InfoNCE

两者解决不同矩阵的显存问题。

Flash Attention 针对：

```text
Attention Score：[B,H,S,S]
```

通过分块和在线 Softmax 减少中间矩阵显存，并提高 SRAM 利用率。

Leemenghao 的 Flash InfoNCE 针对：

```text
Query-Negative Logits：[M,N_neg]
```

在线 LogSumExp：

```text
逐块计算 logits_block
维护 running_max 和 running_sum_exp
最后得到完整 logsumexp
```

它不改变 Loss，只降低峰值显存。真正的在线实现不能在最后再 `cat` 所有 Logit，否则只是计算分块，显存仍会回到全量规模。

### 1.14 InfoNCE、温度和 Sampled Softmax

归一化 Query 和 Item：

```text
q = normalize(query)
k = normalize(item)
sim(q,k) = q^T k ∈ [-1,1]
```

InfoNCE：

```text
L = -log
exp(sim(q,k+)/tau)
/
[exp(sim(q,k+)/tau) + Σ_j exp(sim(q,k_j-)/tau)]
```

温度 `tau` 控制分布尖锐程度：

```text
tau 小：放大相似度差异，梯度集中于困难样本
tau 大：分布更平滑，训练更稳定但区分压力更弱
```

温度过小会导致：

- Logit 很大；
- 少数 Hard Negative 主导梯度；
- 假负样本伤害更严重。

### 1.15 Global、In-batch 与 Hard Negative

```text
随机 Global Negative：
覆盖面广，但大量样本太简单

Popularity Negative：
更接近线上热门候选，但采样分布偏斜

In-batch Positive as Negative：
不增加 Item Encoder 次数，且通常比随机负样本困难

Hard Negative：
当前模型打分最高、最容易混淆的负广告
```

合理顺序通常是：

```text
训练早期：较多随机负样本，先学基础空间
训练中期：加入 In-batch / Popularity Negative
训练后期：逐步只保留较难的 Top-K
```

### 1.16 Log-q：修正非均匀采样

如果负样本按 `q(i)` 抽取，热门广告会更频繁进入负样本池。常见修正：

```text
corrected_logit(i)
= sim(q,i)/tau - log q(i)
```

直觉：

```text
一个广告本来就容易被采到
→ 它出现在负样本池不能被视为同等强度的负证据
→ 用 -log q 修正采样机会差异
```

注意：

- `q(i)` 必须与实际采样机制尽量一致；
- 过滤假负样本、只取 Hard Top-K 后，严格无偏条件会被破坏；
- 所以工业上更应把它视为有效的采样偏差校正，而不是绝对等价定理。

### 1.17 False Negative Filtering

其他用户的正样本未必是当前用户真正不喜欢的广告，常见过滤：

```text
同一用户历史中的 Item 不作负样本
正负 Item ID 相同则过滤
与正样本相似度过高则过滤
同商品/同广告主的近重复 Creative 可按业务规则过滤
```

假负样本在温度很小时危害尤其大，因为它往往成为最高分负样本并主导梯度。

### 1.18 RQ-VAE、Residual K-Means 与 Semantic ID

高维多模态向量不能直接作为离散生成目标，可先转换成多层语义编码。

RQ-VAE：

```text
x → Encoder → z

第1层：z = c1 + r1
第2层：r1 = c2 + r2
...

Semantic ID = [id(c1), id(c2), ...]
```

训练同时优化：

```text
重建 Loss
+ Codebook Loss
+ Commitment Loss
```

Residual K-Means 不训练神经 Encoder/Decoder，而是直接对原向量逐层做残差聚类：

```text
原向量 → KMeans code1 → residual1
residual1 → KMeans code2 → residual2
...
```

优点是实现简单、可流式处理；缺点是语义空间不能针对推荐目标端到端优化。

Semantic ID 的作用：

- 压缩多模态向量；
- 相似广告共享前几层 Code；
- 缓解纯 Item ID 的冷启动；
- 可以作为多个 Sparse Field 加入 Item Encoder。

但本次四个主方案中，O_o 和 bug-maker6 虽提供相关工具，主训练链路并未真正消费生成的 Semantic ID，不能把它当作已验证收益。

### 1.19 ID Embedding Zero-init

普通 ID Embedding 随机初始化后很容易记忆高频 Item。Zero-init：

```text
训练开始：
ID Embedding = 0
模型先依赖类别、多模态、统计等共享特征

训练推进：
ID Embedding 通过梯度逐步学习个体残差
```

适用场景：

- 内容/类别特征较强；
- Item 长尾明显；
- 希望提高冷启动泛化。

风险是优化器和网络结构必须允许零初始化参数收到非零梯度；若上下游也存在对称零初始化，可能无法打破对称性。

### 2.2 Kaipeng：整体完成度最高

#### 2.2.1 任务定义

该方案不是普通 CTR 二分类，而是动作条件化的下一广告检索：

```text
用户历史 + 指定的下一动作
→ 生成 User Query
→ 与候选 Item Embedding 计算余弦相似度
→ 返回 Top-K Creative
```

动作包括：

```text
0：曝光
1：点击
2：转化
```

同一段历史在不同动作条件下可以生成不同 Query。

#### 2.2.2 样本构造

假设用户序列为：

```text
User Profile
→ Item A（曝光）
→ Item B（点击）
→ Item C（转化）
```

训练样本为：

```text
User Profile → Item A，条件=曝光
Item A       → Item B，条件=点击
Item B       → Item C，条件=转化
```

每个位置保存：

```text
seq[t]：当前 token
pos[t]：下一条真实广告
neg[t]：随机负广告
next_action_type[t]：下一条广告对应的动作
```

更完整的例子：

```text
原始基础数据：
U
→ A（曝光，action=0）
→ B（点击，action=1）
→ C（转化，action=2）
→ D（点击，action=1）

seq：              [U,A,B,C]
token_type：       [2,1,1,1]       # 2=User，1=Item
pos：              [A,B,C,D]
next_action_type： [0,1,2,1]
neg：              [N1,N2,N3,N4]
```

这里的 `history_item` 不是原始数据里的独立字段，而是 `seq` 中 `token_type==1` 的 Item。预测 `D` 时：

```text
User Token：      U
history_item：    A、B、C
最近历史 Item：  C
positive label： D
random negative：N4
```

代码不会把四个前缀复制成四行，而是使用 Causal Mask 一次编码 `[U,A,B,C]`，让四个位置并行预测 `[A,B,C,D]`。

需要区分：

```text
Dataset 存储层：
一个 pos[t] 配一个 neg[t]

Loss 计算层：
一个有效 pos[t] 会与整个 Batch 的 Global Negative Pool
及其他用户的 In-batch Positive Pool 比较
```

#### 2.2.3 特征编码

Item 侧：

```text
Item ID
+ 13 个 Item Sparse Feature
+ 可选多模态向量
→ Embedding / Projection
→ Concat
→ Item MLP
→ 512 维 Item Embedding
```

User 侧：

```text
User ID
+ 4 个 User Sparse Feature
+ 4 个 User Array Feature
→ Embedding / Mean Pooling
→ User MLP
→ 512 维 User Vector
```

User Vector 不直接重复拼到每个 Item，而是生成 FiLM 参数：

```text
gamma, beta = Linear(user_vector)

item'_t = item_t * (1 + gamma) + beta
```

作用是利用一次用户编码调制整条历史序列。

##### 默认配置下的精确维度

记：

```text
B=232
S=102
D=512
H=8
d=64
```

User Tower：

```text
User ID：                    32
4 个 User Sparse：      4 × 128 = 512
4 个 User Array：       4 × 128 = 512
------------------------------------------------
Concat：                         1056
Linear(1056,512) + ReLU
→ user_vector：[B,512]

Linear(512,1024)
→ gamma：[B,512]
→ beta： [B,512]
```

Item Tower 在默认不使用多模态时：

```text
Item ID：                       128
5 个较小字段：             5 × 64 = 320
8 个普通字段：            8 × 128 = 1024
------------------------------------------------
Concat：                         1472
Linear(1472,1024)
→ ReLU
→ Dropout
→ Linear(1024,512)
→ item_token：[B,S,512]
```

如果启用一个多模态字段，则先把原始多模态维度投影为 `128`，Item Tower 输入增加 `128` 维。

FiLM：

```text
item_token：[B,S,512]
gamma/beta：[B,512]
→ broadcast 到 [B,S,512]
→ personalized_item_token：[B,S,512]
```

完整输入：

```text
personalized_item_token        [B,S,512]
+ Linear(time_sin_cos)         [B,S,512]
+ action_embedding             [B,S,512]
+ position_embedding           [B,S,512]
= X0                           [B,S,512]
```

#### 2.2.4 HSTU

默认配置：

```text
序列长度：102
表示维度：512
HSTU 层数：16
Head 数：8
每个 Head：64 维
```

单层计算：

```text
U,V,Q,K = Split(SiLU(XW))

Score = QK^T / sqrt(d) + RelativeTimeBias
A = SiLU(Score)
Y = A @ V

Output = Linear(LayerNorm(Y) * U)
X_next = X + Output
```

与普通 Transformer 的关键区别：

```text
Transformer：A = softmax(Score)，每行权重和强制为 1
HSTU：       A = SiLU(Score)，不强制归一化
```

不归一化可以保留相关行为数量和兴趣强度，LayerNorm 再负责控制数值尺度。

#### 2.2.5 时间与动作

输入同时加入：

```text
hour / weekday 的周期 sin-cos
下一动作 Embedding
Position Embedding
```

Attention 中还加入相对时间差：

```text
|time_i - time_j|
→ 对数分桶
→ 查表得到 Relative Attention Bias
→ 加入 QK^T
```

“下一动作控制 Query”不是让模型额外预测 Action，而是把已知的目标 Action 作为条件：

```text
q_exposure   = HSTU(history + action_emb[曝光])
q_click      = HSTU(history + action_emb[点击])
q_conversion = HSTU(history + action_emb[转化])
```

同一段历史在三种条件下会产生不同 User Query，再分别检索对应 Item。训练时 `next_action_type[t]` 来自 `pos[t]` 实际发生的动作；推理时目标 Action 由 `user_action_type.json` 提供。代码把 Action Embedding 加到序列 Token 后再进入 HSTU，因此动作会影响后续 Q/K/V 和最终 Query，而不是只在 Loss 上乘一个权重。

#### 2.2.6 混合负采样

负样本有两个来源：

```text
Global Negative：
从近期活跃广告池随机采样，排除用户看过的广告

In-batch Negative：
其他用户的正样本作为当前用户的负样本
```

Global Negative 覆盖面广，In-batch Negative 更接近真实热门和困难广告。

Global Negative 的生成过程：

```text
item_last_ts.json
→ 保留 2025-05-29 之后仍活跃且有特征的 Item
→ 得到 valid_items

每个有效位置：
从 valid_items 均匀随机抽 1 个
并排除该用户整条序列出现过的 Item
```

虽然 Dataset 看起来是“一正一负”，Loss 会把一个 Batch 中所有随机负样本展平并共享。默认 `B=232、S=102`：

```text
N = B·S = 23664

每个有效 Query：
1 个对齐正样本
+ 最多约 23664 个 Global Negative
+ 其他用户序列的 In-batch Positive
  最多约 23664-102=23562 个

过滤前负候选总量约 4.7 万/正样本
```

固定数组包含 Padding/无效位置，实际有效负候选会更少；当前实现仍先物化 `[N,N]` 矩阵，再对 Query 行做 Loss Mask，因此 Pair 计算量不能当成数据集样本量。

#### 2.2.7 Log-q 校正

In-batch 采样会过度抽中热门广告，因此统计：

```text
count(i)
= Item i 在全部 seq.jsonl 行为记录中的出现次数

q(i)
= count(i)^0.75 / Σ_j count(j)^0.75

logq(i) = log q(i)
```

正负样本 Logit 都做：

```text
corrected_logit(i)
= cosine(query,item) / temperature
- log q(i)
```

`0.75` 次方会平滑头部与长尾差距。例如频次为 `100、10、1`：

```text
count^0.75：31.62、5.62、1
q：          0.827、0.147、0.026
logq：      -0.19、-1.92、-3.65
```

由于 `corrected_logit=raw_logit-logq`，长尾 Item 获得更大的修正，作用是减轻热门广告被重复采样造成的偏差，并增强长尾正样本信号。

需要注意：`item_freq.csv` 对曝光、点击和转化统一计数，没有按 Action 分开。Global Negative 实际在活跃 Item 池中近似均匀采样，但代码仍使用 `frequency^0.75` 修正；再加上假负样本过滤、Hard Top-K 和混合采样后，不能严格声称它与全量 Softmax 完全等价，更准确的说法是近似的流行度/采样偏差校正。

#### 2.2.8 假负样本过滤

假负样本指“训练时被当成负样本，实际上也可能是用户喜欢或可接受的 Item”，例如同一商品的另一条 Creative、用户历史中看过的广告，或其他用户的正样本恰好也适合当前用户。

Kaipeng 使用三层过滤：

```text
1. Dataset 随机采样：
   Global Negative 不能属于当前用户 seen_item_ids

2. In-batch Negative：
   同一用户序列中的正样本不能互相作为负样本

3. 表示相似度：
   对每个候选负样本，计算它与该用户所有正样本的最大余弦相似度
   max_sim > 0.99 时，将其 Logit Mask 为 -∞
```

相似度过滤使用当前 Item Encoder 的表示，会随训练更新。它适合广告素材高度重复、同一商品存在多个 Creative 的场景，但 `0.99` 只能过滤近重复，不能识别所有“用户未来也可能点击”的潜在假负样本。

#### 2.2.9 Hard Negative Curriculum

Hard Negative 不是额外标注的数据，而是过滤后的候选负样本中，当前模型给出最高校正 Logit 的 Item：

```text
hard_negative
= TopK(cosine(query,negative)/temperature - logq(negative))
```

因此完全无关、得分很低的随机广告会被丢弃，模型集中区分相似广告。流程顺序是：

```text
Global + In-batch 候选
→ -logq 校正
→ 同序列/相似度假负样本过滤
→ 每个 Query 分别取 Top-K
```

课程表：

```text
0～20K：使用全部负样本
20K～40K：Top-8192
40K～60K：Top-4096
60K～80K：Top-2048
80K～100K：Top-1024
100K～115K：Top-512
115K～130K：Top-256
130K 以后：Top-128
```

80K Step 之前 Top-K 中 Global/In-batch 约各占 50%；之后 Global 约占 25%，更强调较难的 In-batch Negative。早期使用全部样本学习基础空间，后期逐步缩小 K，集中优化最容易混淆的广告。

当前代码仍先计算完整负样本 Logit 矩阵，再执行 Top-K，因此 Curriculum 主要改变 Loss 关注范围，并没有按 K 的比例直接消除前面的矩阵乘法成本。

##### Loss 的张量链路

HSTU 输出：

```text
Q_seq = log_feats               [B,S,512]
K_pos = positive_item_embedding [B,S,512]
K_neg = global_item_embedding   [B,S,512]
```

代码先展平：

```text
N = B·S = 232·102 = 23664

Q_flat：    [N,512]
Pos_flat：  [N,512]
Neg_flat：  [N,512]
```

然后构造：

```text
正样本 Logit：       [N,1]
Global Negative：    [N,N]
In-batch Negative：  [N,N]
```

最后只使用 `next_token_type==1` 的位置计算 Loss，但大矩阵在过滤前已经构造，所以显存和计算成本很高。这也是该方案依赖大显存 GPU 的主要原因，而不是 16 层 HSTU 本身。

##### 从训练到推理

训练：

```text
每个有效位置 Hidden State
→ 预测该位置的下一 Item
→ 所有位置共享同一个 Item Tower
```

推理：

```text
候选集合 predict_set
→ Item Tower
→ cand_emb：[C,512]
→ L2 Normalize
→ 常驻 CPU，按块搬到 GPU

用户完整历史
→ HSTU
→ 取最后位置
→ query：[B,512]
→ L2 Normalize

score = query @ cand_emb^T
→ [B,C_chunk]
→ Mask 已看过 Item
→ 分块合并 Top-K
→ creative_id
```

该方案训练和推理都使用归一化点积，表示空间一致。

#### 2.2.10 评价

优点：

- 真正使用下一动作条件生成 Query；
- User FiLM、Item Tower 和 HSTU 链路清楚；
- 训练相似度与推理检索方式一致；
- 负采样、log-q、假负样本过滤和 Curriculum 组合完整；
- 不使用多模态仍取得最高公开成绩，收益更容易归因。

不足：

- `B×L` 位置之间构造大规模负样本矩阵，显存开销高；
- Action Loss 权重实际上均为 1，动作差异主要来自输入条件；
- 代码中的完整推理结果落盘仍不完善。

#### 2.3.2 FeatureInteractionEncoder

先把所有字段压到统一表示，再利用非线性通道门控：

```text
X = Linear(concat(fields))
H = ReLU(Linear(X))
Y = X + X * Aggregate(H)
```

分别存在：

```text
User + Item 序列输入编码器
纯 Item 候选编码器
```

保证候选 Item 可以预计算。

#### 2.3.3 三路 HSTU

该实现同时计算：

```text
普通 QK Attention
RoPE QK Attention
相对时间 Bias 聚合
```

然后：

```text
combined = concat(attn_plain, attn_rope, attn_time)
output = Linear(combined * U)
X_next = RMSNorm(output + X)
```

相比标准 HSTU，它显式融合：

- 普通内容相似度；
- RoPE 相对位置；
- 相对时间差。

##### 单层精确维度

输入：

```text
X：[B,S,512]
```

一次投影：

```text
Linear(512,3072) = Linear(D,6D)
→ SiLU

U：[B,S,1536] = 3D
V：[B,S,512]
Q：[B,S,512]
K：[B,S,512]
```

Q/K/V 分 Head：

```text
[B,S,512]
→ [B,8,S,64]
```

三路聚合：

```text
Plain QK：
QK^T → ReLU → /S → V
→ [B,S,512]

RoPE QK：
RoPE(Q)RoPE(K)^T → ReLU → /S → V
→ [B,S,512]

Time Bias：
RelativeTimeBias @ V
→ [B,S,512]
```

拼接：

```text
Concat(plain,rope,time)
→ [B,S,1536]

combined ⊙ U
→ [B,S,1536]

Linear(1536,512)
→ RMSNorm(output + X)
→ [B,S,512]
```

要注意它并不是标准 HSTU 的 `SiLU(QK)`，而是 `ReLU(QK)/S` 加三路融合，属于受 HSTU 启发的自定义 Block。

#### 2.3.4 多尺度时间

使用了四类时间信息：

```text
hour / day-of-week / weekend 离散 Embedding
Fourier 绝对时间编码
相对时间差 Bias
RoPE 相对位置
```

这是四个方案里时间建模最完整的。

#### 2.3.5 InfoNCE

负样本包括：

```text
随机采样负广告
其他用户的正样本
```

正负样本同样执行 log-q 校正。

对不同动作设置样本权重：

```text
点击：1.0
曝光：0.1
```

因此训练更关注点击行为。

##### Loss 维度

只抽取 `next_token_type==1` 的有效位置：

```text
M = 有效 next-item 位置数

Q：[M,512]
Pos：[M,512]
RandomNeg：[M,512]
```

构造两套负样本：

```text
随机负样本矩阵：
Q @ RandomNeg^T
→ [M,M]

其他序列正样本矩阵：
Q @ Pos^T
→ [M,M]
→ Mask 同一用户序列
```

最终：

```text
logits：[M,1+M+M]
```

正样本、随机负样本和 In-batch 正样本都做对应的 `-logQ`。点击/曝光权重在逐样本 Cross Entropy 后应用，不改变 Logit 本身。

#### 2.3.6 自监督

对负广告构造两条增强视图：

```text
随机掩蔽部分字段
对多值字段执行 value dropout
允许掩蔽 Item ID
```

然后对两条 Item 表示计算双向对比 Loss：

```text
Loss = InfoNCE_main + alpha * InfoNCE_ssl
```

作用是降低模型对单个 ID 或单个字段的依赖，但只在负样本上构造 SSL 视图，设计上比较实验性。

#### 2.3.7 Streaming Residual K-Means

`model_rqkmeans.py` 支持：

- 多层不同大小的 Codebook；
- 流式训练，减少内存占用；
- Balanced K-Means 初始化；
- Codebook 利用率、空簇率、碰撞率监控；
- 把多模态向量转换为多层 Semantic ID。

但主 Dataset、Model 和训练脚本没有真正加载这些 Semantic ID，因此它目前属于独立工具，不是主方案实际 Forward 的一部分。

##### 训练到推理的完整链路

训练：

```text
历史 User+Item 特征
→ 4096→512 的序列侧 FeatureInteractionEncoder
→ Fourier Time
→ 8层三路 HSTU
→ log_feats：[B,S,512]

正/负 Item 特征
→ 2304→512 的 Item Encoder
→ pos/neg embedding：[B,S,512]

Main InfoNCE
+ 负 Item 两视图 SSL
→ 总 Loss
```

推理：

```text
候选 Item
→ Item Encoder
→ candidate_embedding：[C,512]

用户历史
→ 序列侧 Encoder + HSTU
→ 最后位置 query：[B,512]

归一化点积
→ ANN / Top-K
```

该实现的 `next_action_type` 没有作为“下一动作 Embedding”加入 Query；序列中加入的是每条历史 Item 自己的 Action Feature 900。因此它属于行为感知序列召回，不是 Kaipeng 那种严格的下一动作条件生成。

#### 2.3.8 评价

优点：

- 初赛第 14 名；
- 时间、位置、字段交叉和多模态建模丰富；
- log-q、动作加权和 In-batch Negative 组合完整；
- 工程代码对缓存、AMP、Early Stopping 和特征预处理考虑较多。

不足：

- 组件过多，难以做清晰收益归因；
- 自监督只作用于负样本，设计较特殊；
- RQ-KMeans 未接入主链路；
- `next_action_type` 主要用于 Loss 加权，不像 Kaipeng 那样直接控制 Query；
- 本地验证候选集不等价于真正全量候选检索。

#### 2.4.4 HSTU-like

代码中的 Attention：

```text
A = SiLU(QK)
A = clamp_min(A, 0)
A = A / sum(A)
```

它重新执行了行归一化，因此并不是官方 HSTU 的未归一 Pointwise Attention，更接近 ReLU/SiLU 版归一化 Attention。

README 提到“局部片段与全局表示”，但代码仍是完整因果 Attention，没有明确的局部—全局双路径。

单层维度：

```text
X：[B,S,64]

U/V/Q/K：
4 × Linear(64,64)
→ 各自 [B,S,64]

Q/K/V：
[B,S,64] → [B,8,S,8]

A：
[B,8,S,S]

A @ V：
[B,8,S,8] → [B,S,64]

RMSNorm(A@V) ⊙ U
→ Linear(64,64)
→ [B,S,64]
```

随后还接独立 PointWise FFN：

```text
Conv1d(64,64)
→ GELU
→ Conv1d(64,64)
→ Residual
```

该 FFN 没有常见的 `D→4D→D` 扩张，参数和计算较小，但通道容量也低于标准 Transformer FFN。

#### 2.4.5 InfoNCE

```text
Sequence Query
正广告
Batch 内随机负广告
→ L2 Normalize
→ Temperature-scaled InfoNCE
```

实现中把负样本分块计算相似度，但最终仍拼接所有 Logit，不是真正在线 Softmax。

具体张量：

```text
seq_emb：[B,S,64]
pos_emb：[B,S,64]
neg_emb：[B,S,64]

neg_pool = reshape(neg_emb)
→ [B·S,64]

每个 Query 与所有 neg_pool 点积
→ [B,S,B·S]
```

再拼接一个正样本 Logit：

```text
logits：[B,S,1+B·S]
→ 仅保留有效 next-item 位置
→ CrossEntropy(label=0)
```

代码还给正样本相似度减固定 margin `0.08`，等价于主动提高正样本必须超过负样本的难度。

```text
→ Encoder
→ 多层残差量化
→ Semantic ID
→ Decoder 重建
```

但主模型没有加载 Semantic ID，仍然只是独立扩展工具。

### 2.5 Leemenghao：分块 InfoNCE 有价值

#### 2.5.1 模型主干

该方案不是 HSTU，而是改进 Transformer：

```text
字段 Embedding
→ SENet 字段重标定
→ 选择性 Bilinear 字段交叉
→ 256 维 Token
→ 8 层 Flash Self-Attention
→ RoPE
→ RMSNorm
→ SwiGLU FFN
→ User Query
```

##### 默认配置

```text
B=256
S=102
D=256
H=8
d=32
Transformer Block=8
FFN 中间宽度=4D=1024
默认多模态字段：81（32维）
```

虽然仓库有 `config.yaml` 为不同字段配置不同维度，但当前主 `model.py` 实际把 ID、Sparse、Array 和多模态投影统一到 `hidden_units=256`。复习代码时应以执行链路为准，不能把配置文件里的字段维度直接当成模型真实维度。

User 字段：

```text
User ID：               1
User Sparse：           7
User Array：            4
User Continual 304：    1
--------------------------------
共 13 个 256维字段

Stack：[B,S,13,256]
Flatten：[B,S,3328]
SENetBilinearDNN(3328→256)
→ user_token：[B,S,256]
```

Item 字段：

```text
Item ID：               1
Item Sparse：          14
多模态81：              1
--------------------------------
共 16 个 256维字段

Stack：[B,S,16,256]
Flatten：[B,S,4096]
SENetBilinearDNN(4096→256)
→ item_token：[B,S,256]
```

序列输入：

```text
X0 = user_token + item_token
→ [B,S,256]
```

Transformer 单层：

```text
QKV Linear(256,768)
→ Q/K/V：[B,8,S,32]
→ RoPE(Q,K)
→ SDPA / Flash Attention
→ [B,S,256]

FFN：
Linear(256,1024)
→ SwiGLU
→ Linear(1024,256)
→ [B,S,256]
```

代码没有再加可学习绝对 Position Embedding，位置主要由 RoPE 表达。

#### 2.5.2 特征交叉

User 和 Item 分别使用 `SENetBilinearDNN`：

```text
SENet：学习不同字段的重要性
Bilinear：对选定字段对做显式乘性交叉
DNN：压缩到统一 Hidden Size
```

相比直接 Concat + Linear，能够增加字段间非线性交互。

代码只选择少量字段对：

```text
User：
(0,1)、(0,6)、(0,7)、(6,7)

Item：
(0,3)、(0,11)、(0,15)、(3,11)
```

这里的下标是字段在 Stack 中的位置，不是原始 Feature ID。只做少数 Pair 的好处是避免所有字段两两交叉产生 `O(F²)` 参数和噪声。

#### 2.5.3 负样本

同时使用：

```text
普通随机负样本
流行度采样负样本
```

Dataset 会替换部分与 Batch 正样本冲突的负样本，但没有执行 log-q 校正。

#### 2.5.4 Flash InfoNCE

普通 InfoNCE 需要物化：

```text
Query × All Negatives
```

该方案分块计算：

```text
每次读取一块 Negative
→ 计算当前块 Logit
→ 在线更新 max_logits
→ 在线更新 sum(exp(logits - max))
→ 最终得到完整 log-sum-exp
```

该方法不改变 Loss，只降低峰值显存，是该仓库最值得复用的部分。

##### 张量链路

有效位置：

```text
Q：[M,256]
Pos：[M,256]
```

负样本来自：

```text
普通随机 neg_emb：[B,S,256]
流行度 pop_neg_emb：[B,S,256]

Flatten + Concat
→ negative_pool：[2·B·S,256]
```

若直接计算：

```text
Q @ negative_pool^T
→ [M,2·B·S]
```

默认：

```text
B=256
S=102
2·B·S=52224
```

该矩阵非常大，所以每次只取 `1024` 个负样本：

```text
block_logits：[M,1024]
```

并维护：

```text
running_max：[M]
running_sum_exp：[M]
```

最终得到与一次性完整 LogSumExp 等价的 InfoNCE 分母。

##### 训练到推理

训练：

```text
历史 User+Item 字段
→ SENet + Bilinear
→ [B,S,256]
→ 8层 Flash Transformer
→ Query Hidden：[B,S,256]

正/随机负/流行度负 Item
→ Item SENetBilinearDNN
→ [B,S,256]

→ Flash InfoNCE
```

推理：

```text
候选 Item
→ Item Encoder
→ candidate_embedding：[C,256]

用户历史
→ Transformer
→ 最后位置 query：[B,256]

→ L2 Normalize
→ ANN Top-K
```

`next_action_type` 虽然由 Dataset 生成并传入 `forward_infonce`，但没有加入 Token，也没有参与 Loss 权重，因此该方案本质上不是动作条件生成。

#### 2.5.5 评价

优点：

- 分块在线 InfoNCE 实现有工程价值；
- Flash Attention、RoPE、RMSNorm、SwiGLU 组合完整；
- 使用 SENet 和 Bilinear 进行字段交叉；
- 考虑流行度负样本和假负样本修正。

不足：

- 初赛公开排名只有 150+；
- 流行度采样没有 log-q 校正；
- `next_action_type` 没有真正进入模型；
- 部分特征投影运行在 `torch.no_grad()` 内，相关层无法正常学习；
- 频繁 `torch.cuda.empty_cache()` 会影响训练效率；
- 部分配置和代码没有完全统一。

### 2.7 推荐的组合方案

不建议把四个方案的所有模块简单堆叠。更合理的组合是：

```text
Kaipeng 主干：
Item Tower
+ User FiLM
+ Action-conditioned HSTU
+ Mixed Negative
+ log-q
+ False Negative Filtering
+ Hard Negative Curriculum

选择性加入 O_o：
RoPE
+ Fourier 绝对时间
+ 少量消融有效的字段交叉
+ 点击/转化样本权重

工程上加入 Leemenghao：
分块在线 InfoNCE
```

第一版不建议默认加入：

```text
负样本 SSL
未接入主链路的 Semantic ID
全部多模态向量
过多人工字段交叉
```

原因是这些模块会显著增加训练成本和调参难度，但公开仓库没有给出足够消融证明其稳定收益。

#### 2.7.1 我会采用的第一版架构

核心原则：

```text
用 Kaipeng 保证任务和负采样闭环
用 O_o 补充时间与少量特征交叉
用 Leemenghao 解决大负样本矩阵的显存问题
```

推荐配置：

```text
最大序列长度 S：102
统一表示 D：256
Head 数 H：8
单 Head d：32
HSTU Block：6～8
Item 输出维度：256
User 输出维度：256
```

不直接使用 Kaipeng 的 `D=512、16层`，因为推荐系统第一版更需要稳定迭代和高效消融。`D=256、6～8层` 已经能提供较强容量，确认数据和负样本收益后再扩容。

#### 2.7.2 推荐 Tokenizer

User：

```text
User ID：32
低基数 User Field：16～32
高基数 User Field：32～64
多值 User Field：EmbeddingBag Mean Pool

Concat
→ Linear/MLP
→ user_vector：[B,256]
```

Item：

```text
Item ID：64～128
低基数 Item Field：16～32
高基数 Item Field：64～128
多模态：原始向量→Linear→64/128
少量验证有效的 Cross Field：32～64

Concat
→ Linear(总维度,512)
→ SiLU/SwiGLU
→ Linear(512,256)
→ item_token：[B,S,256]
```

用户条件：

```text
Linear(256,512)
→ gamma/beta 各256维

item'_t = item_t * (1+tanh(gamma)) + beta
```

#### 2.7.3 推荐序列 Backbone

第一版：

```text
Personalized Item Token
+ Action Embedding
+ hour/weekday 周期编码
+ Position/RoPE（二选一先做消融）
→ 6～8层 HSTU
```

Attention：

```text
A = SiLU(QK^T/sqrt(d) + RelativeTimeBias)
Y = A @ V
Delta = Wo(RMSNorm(Y) ⊙ U)
X_next = X + Delta
```

时间建模优先级：

```text
1. Relative Time Bias：直接影响历史聚合，优先保留
2. hour/weekday：成本很低
3. RoPE：用于相对顺序，可做增量实验
4. Fourier Time：确认长周期明显后再加入
```

不建议第一版照搬 O_o 的 Plain QK + RoPE QK + Time 三路并行，因为普通 QK 与 RoPE QK 信息重叠，增加计算后未必稳定增益。

#### 2.7.4 推荐动作建模

使用 Kaipeng 的下一动作条件：

```text
next_action_type
→ Action Embedding：[B,S,256]
→ 加入当前位置 Token
```

再根据评测或业务价值做 Loss 权重：

```text
曝光：1.0
点击：1.5～2.0
转化：2.5 左右
```

权重必须通过离线指标和线上价值校准，不能只因为转化重要就无限增大，否则会牺牲覆盖率和点击召回。

#### 2.7.5 推荐负样本与 Loss

负样本池：

```text
随机活跃 Item
+ In-batch Positive
+ 可选热门 Item
```

必须配套：

```text
同序列过滤
同 Item ID 过滤
近重复 Creative 过滤
log-q 校正
```

训练节奏：

```text
阶段1：
较多随机负样本，不做 Hard Top-K

阶段2：
加入 In-batch Positive，观察假负样本比例

阶段3：
逐渐缩小 Hard Top-K，提高困难样本占比
```

工程上使用分块在线 LogSumExp：

```text
不物化完整 [M,N_neg]
每次处理 512～2048 个 Negative
维护 running_max / running_sum_exp
```

这样保留 Kaipeng 的目标设计，同时避免其 `[B·S,B·S]` 全量矩阵显存问题。

#### 2.7.6 推荐推理链路

离线：

```text
全量候选 Item
→ Item Encoder
→ candidate_embedding：[C,256]
→ L2 Normalize
→ 写入向量索引
```

在线：

```text
用户最近 101 条行为
+ 用户画像
+ 当前目标 Action
→ HSTU
→ query：[B,256]
→ L2 Normalize
→ ANN Top-N
→ Mask 已看过/失效广告
→ 规则或精排重排
→ Top-K
```

离线验证必须尽量接近真实候选池，不能只使用 Batch 内候选计算 HR/NDCG，否则模型选择会偏向容易的小候选集合。

#### 2.7.7 推荐迭代顺序

```text
V1：
Item ID + Sparse
+ Action-conditioned HSTU
+ Random/In-batch Negative
+ log-q

V2：
+ User FiLM
+ Relative Time Bias
+ False Negative Filtering

V3：
+ Hard Negative Curriculum
+ 分块在线 InfoNCE
```
