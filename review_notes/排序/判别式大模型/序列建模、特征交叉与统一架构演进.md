# 判别式推荐大模型：三条技术路线与重点论文

> 复习目标：不展开 LR、FM、DeepFM、DIN、DIEN 等经典模型，只把它们作为背景；重点理解 2024—2026 年在工业界有代表性的特征交叉 Scaling、长序列建模、序列—交叉统一架构。  
> 每篇重点论文统一回答：优化什么问题、输入如何 Token 化、前向链路如何执行、核心公式是什么、为什么有效、代价与边界是什么。
>
> 经典模型基础见[《经典精排模型复习：特征交叉、序列与多任务》](./经典精排模型复习：特征交叉、序列与多任务.md)。

## 一、先看结论：重点复习哪些论文

### 路线 A：非序列特征交叉与 Ranking Scaling

必读：

1. **RankMixer**：Token Mixing + Per-token FFN/Sparse-MoE，硬件友好交叉的代表。
2. **TokenMixer-Large**：修复 RankMixer 深层残差与 MoE，扩展到十亿级参数。
3. **RankUp**：从 effective rank 分析“参数增加但表示容量没有增加”。

选读：

- **Wukong**：堆叠 FM，使显式交叉阶数随深度增长；与 Mixer 路线差异明显。
- Hiformer、DHEN、HHFT：理解异构 Attention/混合交叉即可，不逐篇展开。



### 路线 B：行为序列与长序列 Scaling

必读：

1. **HSTU**：推荐原生序列 Backbone 与生成式推荐 Scaling。
2. **LONGER**：Token Merge + Hybrid Attention + KV Cache，GPU 端到端长序列。
3. **STCA**：只做 Target-to-History Cross Attention，将长度复杂度降为线性。

选读：

- **TWIN V2**：生命周期行为的离线聚类压缩 + 两阶段 Target Attention。
- TransAct V2、DV365：分别代表在线检索式和离线用户向量式长序列。



### 路线 C：序列与特征交叉的桥接/统一

必读：

1. **OneTrans**：S/NS token 单流统一 Transformer。
2. **HyFormer**：Global Query 反复读取长序列并进行 Query Boosting。
3. **EST**：LCA + CSA，保留原始行为 token 的非对称稀疏统一。
4. **TokenFormer**：解决朴素统一引发的 Sequential Collapse。

选读：

- **InterFormer**：双路逐层桥接的早期代表。
- **WHALE**：Wukong + HSTU 的逐层生产融合。
- MixFormer：与 HyFormer 同属 Query Bottleneck 路线。
- HeMix：序列先压成兴趣 token，再用 HeteroMixer 交叉。
- UniFormer：把统一范围从 Feature Space 扩展到 Task Space。

## 二、整体演进：两条路线并行，最后汇合

```text
非序列特征交叉：
FM/DCN
→ Hiformer/DHEN
→ Wukong
→ RankMixer
→ TokenMixer-Large / RankUp
                         ┐
                         ├→ InterFormer/WHALE 桥接
                         └→ OneTrans/HyFormer/EST/TokenFormer 统一
                         ┌
用户行为序列：           │
DIN/DIEN
→ SIM/TWIN
→ HSTU/TWIN V2
→ LONGER/STCA
```

传统工业结构通常是：

```text
history
→ DIN/Transformer/LONGER
→ sequence summary ─┐
                    ├→ DCN/RankMixer → pCTR/pCVR
user/item/context ──┘
```

问题在于：

- 序列先压缩，细粒度行为损失；
- 信息主要从序列单向流向交叉模块；
- Attention、FM、MLP、Mixer 算子碎片化；
- 参数预算无法在序列与交叉之间统一 Scaling。

## 三、Attention 分类：Self、Target、Cross 与无 Attention



### 3.1 统一公式

```text
Query 输入 Xq:  [B,M,D]
Key/Value Xkv: [B,L,D]

Q = Xq  Wq             [B,M,d]
K = Xkv Wk             [B,L,d]
V = Xkv Wv             [B,L,d]

Score  = Q K^T / sqrt(d)       [B,M,L]
Weight = softmax(Score + Mask) [B,M,L]
Output = Weight V              [B,M,d]
```

区别只在 Q、K、V 来自哪里。

### 3.2 Self Attention

```text
Q、K、V 都来自同一组 token
Xq = Xkv = X
Score shape = [B,L,L]
```

用途：学习 history-history 或 field-field 关系。

主要模型：

- SASRec、BERT4Rec、BST；
- HSTU：推荐原生的因果 Self Attention 变体；
- AutoInt、Hiformer：field token Self Attention；
- OneTrans、TokenFormer：S/NS 统一 token 流 Self Attention；
- EST 的 CSA：行为—行为内容稀疏聚合。



### 3.3 Target Attention

```text
Q = 当前候选 target     [B,1,D]
K/V = 用户历史          [B,L,D]
Score shape = [B,1,L]
```

用途：生成候选相关兴趣。

主要模型：

- DIN、DIEN；
- SIM、TWIN、TWIN V2；
- STCA；
- ETA、SDIM。

DIN 不一定使用标准点积，而常用：

```text
match_i = concat(
  target,
  history_i,
  target - history_i,
  target * history_i
)

score_i = MLP(match_i)
interest = sum_i weight_i * history_i
```



### 3.4 Cross Attention

```text
Q 来自集合 A，例如 NS/global/query token
K/V 来自集合 B，例如行为序列
Score shape = [B,M,L]
```

主要模型：

- HyFormer、MixFormer：Global/NS query 读取 sequence；
- EST LCA：NS token 读取 behavior token；
- WHALE：Wukong token 读取 HSTU sequence；
- LONGER 第一层：global/recent query 读取长序列；
- HeMix：动态/固定兴趣 query 读取长期和实时序列；
- UniFormer：sequence、feature、task 之间多组 Cross Attention。

Target Attention 是 Cross Attention 的特例：Query 数通常为 1，且语义明确是候选 target。

### 3.5 不使用 Attention 的代表模型

```text
Wukong：
堆叠 FM + 线性交互

RankMixer：
reshape/transpose Token Mixing + PFFN

TokenMixer-Large：
Mixing & Reverting + Sparse Per-token MoE

RankUp：
多 embedding/token 组织 + MetaFormer
重点是提高 effective rank
```

HeMix 需要拆开看：

```text
序列 Tokenizer：Cross/Target Attention
主交叉 Backbone：HeteroMixer，不是 Attention
```



### 3.6 一眼判断

```text
Q=history，K/V=history         → Self Attention
Q=target，K/V=history          → Target Attention
Q=NS/global，K/V=sequence      → Cross Attention
所有 S+NS token 一起生成 QKV   → 统一 Self Attention
没有 QKV，只做 FM/reshape/MLP  → 无 Attention
```

# 路线 A：非序列特征交叉与 Ranking Scaling



## 四、Wukong：显式交叉阶数 Scaling



### 4.1 优化的问题

传统 DLRM/FM 主要建模二阶交叉；DCN、AutoInt 加深后容易收益饱和。Wukong 希望：

> 随着网络变宽、变深，显式交叉阶数和模型质量都能持续增长。



### 4.2 输入与前向链路

```text
sparse feature → embedding
dense feature  → MLP projection
→ X0:[N,D]
→ L 个 Wukong Layer
   ├─ FMB：FM 二阶交互 → MLP → 新交叉 token
   └─ LCB：线性组合，保留低阶信息
   → concat + residual + LayerNorm
→ flatten/pooling
→ task tower
```

Wukong 架构与显式交叉升阶

这里的 `N` 是最终 embedding/token 数，不一定等于原始字段数：

```text
普通单值 field：ID lookup → 1 个 D 维 embedding
multi-hot field：多个 ID lookup → pooling → 1 个 embedding
重要 field：允许分配多个 embedding，增加表示容量
低重要性 field：先用较小底层维度，再分组 concat + MLP → D 维 embedding
```

因此，工程第一版可以采用“一 field 一 token”，但 Wukong 原始设计并没有强制这种一一对应关系。

### 4.3 核心公式

```text
X: [N,D]
FM(X) = X X^T                  [N,N]

FMB(X) = reshape(
  MLP(
    LN(flatten(FM(X)))
  )
)

LCB(X) = W_linear X

X_next = LN(
  concat(FMB(X), LCB(X))
  + ResidualProject(X)
)
```

FMB 中的“FM”与经典 FM 的关系需要区分：

```text
经典 FM：
原始特征 embedding 两两内积
→ 全部二阶项求和
→ 得到预测分数的一部分

Wukong FMB：
当前层 embedding 两两内积
→ 保留交互矩阵
→ MLP 重新生成 n_F 个交叉 embedding
→ 交给下一层继续交叉
```

LCB 作用在 token 维而不是 channel 维：

```text
X_i:[N_i,D]
W_L:[N_L,N_i]
LCB(X_i)=W_L X_i:[N_L,D]
```

每个输出 token 都是全部输入 token 的线性组合，但 `D` 不变。LCB 没有乘法和激活，因此不会继续提高已有特征的多项式阶数。

若直接计算 `(X X^T)Y`，可利用结合律：

```text
X:[N,D], Y:[N,K]
(X X^T)Y:[N,K] = X(X^T Y)

O(N²D) → O(NKD)，K << N
```

`Y` 是可学习投影矩阵。优化后的 FM 不再物化完整 `N×N` 交互矩阵，而是保留其 `K` 个投影方向。

第 `l` 层继续对上一层交叉表示做二阶 FM，理论最高交叉阶数按 `2^l` 增长：

```text
第 1 层：一阶输入
FMB：1+1 → 二阶；LCB：保留一阶
→ 输出覆盖一至二阶

第 2 层：一至二阶输入
FMB：最高 2+2 → 四阶；LCB：保留一至二阶
→ 输出覆盖一至四阶
```

“可达到四阶”只表示表示空间允许包含四阶项，不表示每个四阶组合都被单独、可解释地枚举。

### 4.4 为什么只选读

Wukong 与 Mixer 路线差异明显，值得理解“显式交叉阶数 Scaling”。但它依赖较重的 FM/MLP，论文对超大模型实时 serving 的公开证据弱于 RankMixer 系列。

## 五、RankMixer：硬件友好的交叉 Backbone



### 5.1 优化的问题

- FM、DCN、Attention、多分支交叉带来小算子和不规则访存；
- 推荐 token 语义异构，共享 FFN 容易相互干扰；
- 参数增加后 FLOPs 和延迟同步膨胀。

目标：

> 用规则大 GEMM 提升 GPU MFU，并让参数增长快于线上延迟增长。



### 5.2 Token 化

```text
categorical feature → embedding
numeric feature     → projection
sequence feature    → 外部序列模块先聚合

按 user/item/context/sequence/cross 语义分组
→ 每组 concat
→ 独立 Projector
→ X0 = stack(token_1,...,token_T) [B,T,D]
```

Projector：

```text
token_g = LayerNorm(
  GELU(
    concat(group_g) W_g + b_g
  )
)
```

更完整地写，`g=1...T` 表示语义组：

```text
z_g = concat(
  embedding(feature_g1),
  ...,
  embedding(feature_gm)
)                                      [B,C_g]

token_g = Projector_g(z_g)             [B,D]
X0 = stack(token_1,...,token_T, dim=1) [B,T,D]
```

这里的 `concat` 是组内拼特征，`stack` 是组间新增 token 轴。上式 Projector 只有一个可学习 Linear，再接 GELU 与 LayerNorm，严格说是“单层非线性投影器”；实现为 `Linear→GELU→Linear` 时，才是通常意义上的两层 MLP。

原论文实现更接近“先按业务语义排序拼接，再按固定片段切分”：

```text
e_input = concat(e_1,...,e_N)
z_t = e_input[d*(t-1):d*t]
token_t = Proj_t(z_t)
```

因此 token 是领域知识驱动的 feature chunk，不保证严格“一 field 一 token”，也不要求每个 chunk 只含一种业务特征。

### 5.3 完整前向链路

```text
X0:[B,T,D]
→ RankMixer Block × L
   ① Multi-head Token Mixing
   ② residual + LayerNorm
   ③ Dense PFFN 或 Sparse Per-token MoE
   ④ residual + LayerNorm
→ mean pool over T
→ shared/task towers
→ pCTR/pCVR
```

RankMixer Token Mixing 与 Per-token FFN

原论文采用两次 Post-Norm：

```text
S = LN(TokenMixing(X) + X)
Y = LN(PFFN(S) + S)
```

第一个子层负责 token 间通信，第二个子层负责每个 token 内部的 channel 非线性变换。两个残差分别保护两种子层，而不是重复做同一件事。

### 5.4 Token Mixing

它没有 Q/K/V，不计算动态权重，只做重排：

```text
X: [B,T,D]
→ split channel into H heads
→ [B,T,H,D/H]
→ transpose T and H
→ [B,H,T,D/H]
→ flatten last two dims
→ S: [B,H,T*D/H]
```

原 RankMixer 设置 `H=T`，因此：

```text
S: [B,T,D]
```

每个新 token 获得所有原 token 的一个 channel 子空间，实现零参数全局通信。

例如 `T=H=2,D=4`：

```text
A=[a1,a2 | a3,a4]
B=[b1,b2 | b3,b4]

Mix 后：
U1=[a1,a2,b1,b2]
U2=[a3,a4,b3,b4]
```

每个新 token 都读取了 A、B 的一个 channel 子空间，但 `U1/U2` 的位置含义已经不再是原来的 A/B。

### 5.5 Per-token FFN

```text
对第 t 个 token：

h_t = GELU(x_t W1_t + b1_t)      [B,rD]
y_t = h_t W2_t + b2_t            [B,D]

W1_t、W2_t 在不同 token 间不共享
```

参数和 FLOPs 近似：

```text
Parameters ≈ 2*T*r*D²
Forward FLOPs ≈ 4*T*r*D²
```

增大参数主要是扩大 `D、r、L、expert 数`，计算集中为大矩阵乘法。

### 5.6 Sparse Per-token MoE

```text
每个 token 有自己的专家集合
router_t(x_t) → 激活部分 experts

y_t = sum_e gate_t,e * Expert_t,e(x_t)
```

RankMixer 原版采用 ReLU Routing 和 Dense-Training/Sparse-Inference：推理稀疏，但训练并未真正节省专家计算。

#### 平衡 / 稀疏辅助 Loss：两套算法不要混用

MoE 里常说的「平衡 loss」其实有两套，门控假设不同，统计维度也不同。

**路由单位先分清：**


| 场景                           | 路由单位                 | 统计维                |
| ---------------------------- | -------------------- | ------------------ |
| 精排 MMoE → Softmax Top-K SMoE | 每条样本（多任务则每任务一个 Gate） | 对 batch 样本数 `B` 平均 |
| RankMixer / PSMoE            | 每个特征 token           | 对 `B × T` 平均       |


公式里的 **N 一律是专家数 E**，不是 token 数；token/样本数只出现在 f_i,P_i 或 mean 的分母里。

---

**套一：经典 Softmax Load Balancing（Switch 类）**

适用于 Softmax / Top-K Softmax 路由（MMoE 改稀疏、或 vanilla SMoE）：

```text
L_balance = α · N · Σ_i (f_i · P_i)
L_total   = L_task + L_balance
```

- `N`：专家数
- `f_i`：实际路由到 expert i 的比例（看 Top-K mask）
- `P_i`：router Softmax 后对 expert i 的平均概率
- `α`：系数

精排 SMoE 示例（`B=4, E=4, Top-K=2`，按**样本**统计）：

```text
样本 Softmax P                 Top-2 Mask
s0  [0.40, 0.10, 0.30, 0.20]   [1, 0, 1, 0]
s1  [0.50, 0.25, 0.15, 0.10]   [1, 1, 0, 0]
s2  [0.10, 0.15, 0.45, 0.30]   [0, 0, 1, 1]
s3  [0.35, 0.30, 0.20, 0.15]   [1, 1, 0, 0]

f = [0.75, 0.50, 0.50, 0.25]   # mask 列均值，Σf=2（每人选2个）
P = [0.3375, 0.20, 0.275, 0.1875]

Σ f_i P_i = 0.5375
α=0.01 → L_balance = 0.01 × 4 × 0.5375 = 0.0215
```

多任务 MMoE：每个任务 Gate 各自算一份 L_{bal,t}，再相加。

若同样公式用在 RankMixer 的 Softmax 路由上，只需把统计从「样本」改成「所有 token」：分母变为 `B×T`。

Dense MMoE（全专家 Softmax 加权、不算 Top-K）一般不需要这套 f_i，因为每个专家每次都会算。

---

**套二：RankMixer 主推 — ReLU + L1 稀疏正则**

门控不做 Softmax，权重不必和为 1：

```text
G_{b,t,j} = ReLU(router(s_{b,t}))_j     # [B, T, E]

L_reg = mean_{b,t}( Σ_j G_{b,t,j} )      # 对所有样本×token 平均「门控激活总量」
L     = L_task + λ · L_reg
# 实现里常再 / sparsity_ratio，把平均激活压到预算附近
```

示例（`B=2, T=4, E=4`）：

```text
样本0 各 token 的 Σ_j G:  2.0, 0.8, 1.4, 0.8
样本1 各 token 的 Σ_j G:  1.5, 1.8, 0.9, 2.0

L_reg = (2.0+0.8+1.4+0.8 + 1.5+1.8+0.9+2.0) / 8 = 1.4
```

含义：压的是每个 token 的**总激活量**（开多大/开多少），让平均激活靠近稀疏预算；信息量大的 token 仍可多开专家。

**不是**套一里的「每个专家路由率 f_i」。L1 不按专家拆均匀性；专家被充分训练主要靠 DTSI（训练 dense / 推理 sparse）。论文对比：vanilla SMoE 加上套一 balance 有帮助，但仍不如 DTSI + ReLU + L1。

DTSI 时：`L_reg` 通常只加在**推理门控** `h_infer` 上；训练门控可更 dense，保证专家吃到梯度。

---

**对照一句话：**

```text
MMoE→SMoE：样本维 + Softmax，用 N·Σ(f_i P_i) 拉齐专家负载
RankMixer： token维 + ReLU，用 mean(Σ_j G_j) 控制平均激活预算
```



### 5.7 局限

- 固定重排不理解候选、时间和内容；
- `H=T` 是为了残差 shape 对齐；
- mixing 前后的 token 语义已变化，却直接残差相加；
- Post-Norm 和错误残差使深层扩展困难；
- 序列通常已被外部模块压缩，因此不是统一 S/NS 模型。

详细实现见[《RankMixer复习笔记》](./RankMixer复习笔记.md)。

## 六、TokenMixer-Large：修复 RankMixer 并扩展到十亿级



### 6.1 优化的问题

它直接修复 RankMixer：

- Mix 后 token 语义错位却做残差；
- `H` 被迫等于 `T`；
- 深层梯度衰减；
- Dense-Train/Sparse-Infer 成本高；
- 动态专家数难以线上容量规划。



### 6.2 Tokenization、Global Token 与完整链路

TokenMixer-Large 延续语义分组，但将每组交给独立 MLP：

```text
group_i = concat(embedding(field_l),...,embedding(field_m))
token_i = MLP_i(group_i)                         [B,D]

global_info = concat(group_1,...,group_(T-1))
global_token = MLP_global(global_info)            [B,D]

X = stack(global_token,token_1,...,token_(T-1))  [B,T,D]
```

分组 token 保留局部业务语义；Global Token 直接读取全体输入，提供跨组公共信息。论文声明最终总数为 `T`，但部分公式的索引存在排版歧义，复习时应抓住“一个 Global + 其余分组 token”，不要机械照抄冲突下标。

这里“Linear 改为 MLP”的增强只有在 MLP 中存在中间非线性时才成立：

```text
Linear：zW+b
MLP：W2 * activation(W1*z+b1) + b2
```

若实现只是单个 Linear，或者连续 Linear 中间没有激活，表达能力并没有真正升级。

```text
semantic tokens X:[B,T,D]
+ Global Token
→ Block × L
   → Pre-RMSNorm
   → Mixing
   → mixed-token Per-token SwiGLU / Sparse MoE
   → mixed-space residual
   → Reverting
   → original-token Per-token SwiGLU / Sparse MoE
   → 与原 X 做语义对齐 residual
   → inter-layer residual / auxiliary loss
→ pooling
→ task towers
```

TokenMixer-Large Mixing、Reverting 与深层训练设计

需要把三类修复分开理解：

```text
Post-Norm
→ 数值爆炸与梯度不稳定
→ 改为 Pre-RMSNorm

Mix 后直接与原 token 残差
→ token 槽位语义不对应，且 H 被迫等于 T
→ 增加 Reverting

网络极深时早期层训练不足
→ 每 2～3 层加入 inter-layer residual
→ 中间层 auxiliary loss 提供更短监督路径
```



### 6.3 Mixing & Reverting

```text
Mixing:
X [T,D]
→ [T,H,D/H]
→ transpose
→ U [H,T*D/H]

Reverting:
U
→ inverse split/transpose
→ X_revert [T,D]
```

关键区别：

```text
RankMixer：
Mix(X) + X
形状相同，但 token 语义位置不同

TokenMixer-Large：
Revert(FFN(Mix(X))) + X
回到原 token 坐标布局后再残差
```

因此 `H` 不再必须等于 `T`。

“Revert”并不撤销 FFN，也不恢复原值。严格关系是：

```text
Revert(Mix(X)) = X

但：
DeltaX = Revert(FFN(Mix(X))) != X
X_next = X + DeltaX
```

假设 `T=2,H=2,D=4`，Mix 后得到：

```text
U1=[A 的前半通道, B 的前半通道]
U2=[A 的后半通道, B 的后半通道]
```

经过 FFN 后数值已经变化。Revert 只把 `U1/U2` 的 A 槽重新拼成 `DeltaA`，把 B 槽重新拼成 `DeltaB`：

```text
A_next = A + DeltaA
B_next = B + DeltaB
```

所以论文所说的语义对齐，更准确地说是“恢复原 token 的槽位和坐标约定”。

### 6.4 Per-token SwiGLU 与 Sparse MoE

```text
up_t   = x_t Wup_t
gate_t = x_t Wgate_t
ffn_t  = (Swish(gate_t) * up_t) Wdown_t
```

Sparse Per-token MoE：

```text
top-k_t = Router_t(x_t)

y_t =
  alpha * sum_{e in top-k_t} gate_t,e Expert_t,e(x_t)
  + SharedExpert_t(x_t)
```

特点：

- 每个 token 拥有独立专家集合；
- 固定 top-k；
- 训练和推理都稀疏；
- shared expert 也是 per-token；
- `Wdown` 小尺度初始化，使初始 Block 接近恒等映射。

SwiGLU 与 RankMixer GELU FFN 的区别：

```text
GELU FFN：
h = GELU(x W1)
y = h W2

SwiGLU：
up   = x Wup
gate = x Wgate
y = (up * SiLU(gate)) Wdown
```

SwiGLU 多一条输入相关 gate，可以动态调节每个隐藏 channel。相同隐藏宽度下，它比 GELU FFN 多一个投影；公平比较时通常应缩小 SwiGLU 的中间维度。

### 6.5 Pre-RMSNorm、跨层残差与辅助监督

```text
Pre-RMSNorm：
Y = X + SubLayer(RMSNorm(X))

RMSNorm(X) =
  gamma * X / sqrt(mean(X^2) + eps)
```

RMSNorm 不减均值，只控制均方根尺度；Pre-Norm 则让残差路径保留显式恒等梯度。两者分别回答“用什么归一化”和“归一化放在哪里”。

论文正文、架构图和附录明确主张 Pre-RMSNorm，但正文公式 `(8)/(12)/(16)` 仍沿用了 `Norm(F(x)+x)` 的 Post-Norm 写法，原文并不完全自洽。架构理解应以其设计说明和消融为准，同时保留这一公式冲突备注。

跨层残差主要缓解深层梯度衰减，辅助 loss 则让中间表示直接参与预测。辅助 loss 不是结构越多越好：它可能约束最终高层抽象，因此权重和接入层需要单独消融。

### 6.6 系统、证据与边界

- GroupedGEMM、Token Parallel、FP8 serving；
- 论文报告线上 7B、离线 15B；
- 论文消融中，移除 Mixing & Reverting 的 `ΔAUC=-0.27%`；
- 公开线上结果包括电商订单 `+1.66%`、人均预览支付 GMV `+2.98%`；
- 大模型需要更多训练数据才充分收敛；
- 公开数据难以复现其系统收益；
- 它仍是特征交叉 Ranking Backbone，不负责原始长序列建模。

## 七、RankUp：参数变多不等于有效表示变强



### 7.1 优化的问题

RankUp 观察到 RankMixer 类深层模型的 token 表示 effective rank 呈阻尼振荡，深层可能下降：

```text
Token Mixing：跨 token 升秩能力有上限
Per-token FFN：可能收缩通道有效秩
→ 参数增加，但表示可区分方向没有同比增加
```



### 7.2 Effective Rank

```text
H:[T,D]
SVD(H) → singular values sigma_1...sigma_m
m = min(T,D)

p_i = sigma_i / sum_j sigma_j
erank(H) = exp(-sum_i p_i * log(p_i))
```

解释：

```text
erank 接近 1：能量集中在少数方向，表示坍缩
erank 较高：表示空间使用更充分
```

RankUp 没有直接加入 `erank loss`，而是通过输入与 token 设计间接改善。

### 7.3 前向链路

```text
sparse fields
→ 随机排列和分组切分
→ K 套独立 embedding
→ 多组 sparse tokens

同时构造：
├─ Global Token
├─ user/item pretrained cross token
├─ dense/sequence tokens
└─ task-specific tokens

→ MetaFormer/TokenMixer Blocks
→ pooled shared tokens + task token_k
→ task tower_k
```

Cross token：

```text
e_cross = Project(
  e_user_pretrained * e_item_pretrained
)
```



### 7.4 核心理解

```text
随机分组       → 降低 token 相关性
Multi-Embedding→ 增加独立表示视角
Global Token   → 保存全局上下文
Cross Token    → 注入外部 user-item 先验
Task Token     → 降低多任务表示互相挤压
```

RankUp 属于“表示容量 Scaling”，不是长序列或完整统一模型。论文主要实验仍是浅层配置，因此对几十层模型的持续升秩结论需要谨慎。

# 路线 B：行为序列与长序列 Scaling



## 八、HSTU：推荐原生序列 Backbone



### 8.1 优化的问题

- 传统排序依赖大量手工统计和交叉特征；
- Transformer Softmax Attention 未必适合推荐中的兴趣强度；
- 同一用户历史在多个样本和候选间反复计算。



### 8.2 Token 与链路

```text
content token Φ_i：item/content 及其属性
action token a_i：click、skip、完播、购买等

[Φ_0,a_0,Φ_1,a_1,...]
→ HSTU Blocks
→ 在内容位置预测动作，或预测下一个正反馈 item
```

HSTU Pointwise Aggregated Attention

HSTU 既可以作为判别式排序中的 sequence tower，也可以采用 next-item 目标做生成式推荐。两者共享序列 Backbone，但样本与输出不同：

```text
判别式：
用户历史 + 当前候选
→ sequence representation
→ pCTR/pCVR

生成式： 
行为前缀
→ 预测下一个 item/action
→ sampled softmax / retrieval objective
```

单层：

```text
X:[B,L,D]
→ fused projection + SiLU
→ split U,V,Q,K
→ S = Q K^T + position/time bias
→ A = SiLU(S) + causal mask
→ P = A V
→ G = LayerNorm(P) * U
→ output projection + residual
```

公式链：

```text
U,V,Q,K = Split(SiLU(X W1 + b1))
A = SiLU(Q K^T + relative_bias)
Y = W2(LayerNorm(A V) * U) + X
```



### 8.3 与普通 Self Attention 的差异

- Q/K/V 都来自行为流，因此主体仍是 Self Attention；
- 使用 SiLU 而不是沿整行 Softmax，保留兴趣聚合强度；
- 加入时间/位置相对偏置；
- 通过 ragged/fused kernel、长度采样、KV 复用提高效率。

Softmax 会令一行注意力权重和固定为 1；历史长度增加时，已有行为之间会重新竞争。HSTU 的 SiLU 聚合不强制归一化，因此聚合向量的尺度可以随有效行为数量变化。它带来更符合推荐“兴趣强度”的自由度，也意味着必须依赖 LayerNorm、门控 `U` 和初始化控制数值。

`U` 不是另一个 Attention 权重，而是逐位置、逐 channel 的输出门：

```text
P = A V                 # 从历史聚合证据
G = LayerNorm(P) * U    # 当前 token 决定哪些 channel 写回
```



### 8.4 边界

理论注意力仍含 `O(L²D)`；超长序列依赖采样、Kernel 和缓存。HSTU 是序列 Backbone，不自动解决丰富 NS 字段交叉。

论文公开结果需要按层次解读：

- HSTU 在长度 8192 上相对 FlashAttention2 Transformer 报告训练最高 `15.2×`、推理最高 `5.6×` 的 encoder 效率；
- HSTU-large 在公开数据集部分指标相对 SASRec 最高提升 `65.8%`；
- `1.5T` 参数和线上 `12.4%` 是完整 Generative Recommender 系统结果，不应全部归因于单个 HSTU Block。

## 九、LONGER：压缩但保留端到端长序列



### 9.1 优化的问题

两阶段检索可能漏掉行为，普通 Self Attention 对几千长度成本过高。LONGER 希望在 GPU 上直接使用细粒度长历史。

### 9.2 输入与完整链路

```text
raw behavior tokens S:[B,L,D]
+ global tokens G:[B,M,D]

→ 相邻 K 个行为分组
→ InnerTrans 建模组内顺序
→ Token Merge
→ merged history S':[B,L/K,D']

→ 第一层 Cross Causal Attention
   Query = global tokens + recent short tokens
   K/V   = merged long history

→ 后续层 Causal Self Attention
→ global/query representation
→ 与 NS 特征交叉
→ pCTR/pCVR
```

LONGER 局部保真压缩与 Hybrid Attention

### 9.3 Token Merge

```text
每 K 个相邻 token：
[x_i,...,x_{i+K-1}]
→ InnerTrans
→ concat/project
→ merged_token_i

L → L/K
```

只 concat 会破坏组内顺序，InnerTrans 用轻量局部 Attention 保留细粒度关系。

这里的 Merge 不是简单 Mean Pooling。对第 `j` 组：

```text
G_j = [x_(jK),...,x_(jK+K-1)]           [B,K,D]
H_j = InnerTrans(G_j)                    [B,K,D]
m_j = Project(concat(H_j))               [B,D']
```

`InnerTrans` 只在长度 `K` 的局部窗口内计算，成本约为 `O((L/K)·K²·D)=O(LKD)`；当 `K` 远小于 `L` 时，比全局 `O(L²D)` 更可控。

### 9.4 Hybrid Attention

```text
Q:[B,M+R,D]       M 个 global + R 个近期 token
K/V:[B,M+L/K,D]   global + merged history

CrossAttn(Q,K,V)
→ 固定长度 query states
→ 后续 SelfAttn(query states)
```

第一层成本从全序列 Self Attention 的约 `O(L²D)` 变为 `O((M+R)(L/K)D)`。

### 9.5 系统与边界

- Mixed Precision、Activation Recompute；
- KV Cache；
- 稀疏与稠密参数同步 GPU 训练/服务；
- 已在字节 10 多个广告、电商场景部署并服务十亿级用户；
- 论文消融中，TokenMerge 将 FLOPs 从 `3.73e9` 降到 `3.03e9`，再加入 InnerTrans 后 AUC 相对基线提升 `1.63%`。

LONGER 的输出通常仍进入 RankMixer，因此原始方案属于“先序列、后交叉”。

它的核心取舍是：尽量让更多原始行为端到端进入模型，但通过局部分组和固定 Query 把全局计算控制住。若 `K` 太大，组内 Attention 变重；若 `K` 太小，压缩率不足，需要根据长度、显存和效果做消融。

## 十、STCA：只保留最重要的 Target-to-History 交互



### 10.1 优化的问题

对于候选排序，最重要的往往是：

```text
target ↔ history
```

而不是全部：

```text
history ↔ history
```

STCA 直接删除历史 Self Attention，以处理 10K 级行为。

### 10.2 前向链路

```text
target q0:[B,1,D]
history H:[B,L,D]

→ target/history 分别做 dimension-preserving SwiGLU + LN
→ CrossAttn(q1,H1,H1) → summary o1
→ concat(o1,target) → query fusion → q2
→ CrossAttn(q2,H2,H2) → summary o2
→ ... 堆叠多层
→ concat(o1,...,oM,target) → final sequence representation
→ task tower
```

STCA Target-to-History Cross Attention

第 `i` 层：

```text
H_i = LN(SwiGLU_i(H))                         [B,L,D]

alpha_i = softmax(
  (q_i Wq_i)(H_i Wk_i)^T / sqrt(d_h)
)                                             [B,h,1,L]

o_i = ConcatHeads(alpha_i * H_i Wv_i) Wo_i    [B,D]

q_(i+1) = SwiGLU(
  concat(o_1,...,o_i,target) Wc_i
)                                             [B,D]
```

所以 STCA 并不是简单地把上一层 `q_i` 做一次普通残差 FFN；下一层 Query 显式融合原始 target 与所有已生成的层级 summary。最终同样把 `o_1...o_M` 与 target 拼接压缩，再送入 RankMixer/任务塔。

注意力矩阵：

```text
Self Attention:   [L,L]
STCA:             [1,L]

复杂度随长度：
O(L²D) → O(LD)
```



### 10.3 为什么堆叠仍有表达力

```text
第 1 层：target 读取一阶相关行为
第 2 层：更新后的 target 再读取历史
第 k 层：形成高阶 target-conditioned 聚合
```

但行为 token 本身不互相更新。

堆叠带来的“高阶”不是历史之间产生了显式高阶交叉，而是：

```text
o1 = CrossAttn(q1,H1)
q2 = Fuse(target,o1)
o2 = CrossAttn(q2,H2)
q3 = Fuse(target,o1,o2)
...
```

后层 query 包含原始候选和全部低层 summary，因此会以更丰富的候选条件再次读取历史。各层有自己的 history SwiGLU/QKV 参数，不能默认层间共享 K/V；RLB 主要是在同一请求的多个候选之间复用用户/history payload 与计算。

单 query 还允许利用结合律重排投影：

```text
(q Wq)(H Wk)^T = ((q Wq) Wk^T) H^T
alpha(H Wv)     = (alpha H) Wv
```

这样避免显式物化两个 `[L,d_h]` 的 K/V 中间张量。长度相关主项保持线性，论文写为 `O(Ldh)`；加入与长度无关的投影后可细化为 `O(Ldh+d²)`。

### 10.4 系统配套

- **Request Level Batching**：同一请求多个候选共享历史 K/V；
- **Length Extrapolation**：平均约 2K 长度训练，最长 10K 推理；
- 重排矩阵乘法，避免物化不必要的长序列投影。

论文报告的系统收益包括：

- `m=8` 的请求级共享使端到端 Host↔Device 带宽下降 `77%～84%`；
- RLB 带来 `2.2×` 训练吞吐，叠加专用 Kernel 后达到 `5.1×`；
- 最大可训练序列长度约提升 `8×`；
- 这些是“STCA + RLB + Kernel”系统结果，不应只归因于 Attention 公式。



### 10.5 边界

STCA 明确牺牲 history-history 关系换取线性复杂度。若任务强依赖兴趣演化和行为组合，HSTU/LONGER 更合适。

## 十一、TWIN V2：百万级生命周期行为的检索式方案



### 11.1 优化的问题

完整生命周期可能达到 `10^5～10^6` 行为，无法全部在线编码。

### 11.2 链路

```text
离线：
life-long history
→ 按行为质量分组
→ 层次 K-means
→ 每个 cluster 生成 virtual item
→ 存储 cluster embedding 和 size

在线：
target + compressed clusters
→ GSU Target Attention 粗打分
→ Top-K clusters
→ ESU Target Attention 精细聚合
→ long-term interest
→ CTR model
```

Cluster-aware 权重可理解为：

```text
raw_score_i = Attention(target, cluster_i)
score_i = raw_score_i + log(cluster_size_i)
weight = softmax(score)

等价于：
weight_i =
  cluster_size_i * exp(raw_score_i)
  / sum_j(cluster_size_j * exp(raw_score_j))
```

优势是长度可到百万级；代价是离线索引复杂、聚类会损失顺序、两阶段检索可能漏召回。

# 路线 C：序列与特征交叉的桥接和统一



## 十二、InterFormer 与 WHALE：保留双 Backbone 的逐层桥接



### 12.1 InterFormer

优化问题：最终 concat 只有单向浅层交互。

```text
NS tokens → Interaction Arch ─┐
                              ├→ Cross Arch 交换摘要 → 下一层
S tokens  → Sequence Arch ────┘
```

它保留完整两路表示，用 Cross Arch 在每层交换：

```text
NS summary → 调制/查询 Sequence Arch
Sequence summary → 注入 Interaction Arch
```

优点：容易从 DCNv2/DHEN + Transformer 生产系统渐进升级。  
局限：两套 Backbone 和桥接算子仍然碎片化，交换的主要是压缩摘要。

### 12.2 WHALE

WHALE 复用两个成熟 Scaling Backbone：

```text
NS → Wukong → H_w:[B,N,D]
S  → HSTU   → H_s:[B,L,D]

Q = H_w Wq
K = H_s Wk
V = H_s Wv

A = softmax(Q K^T / sqrt(D)) V
H_fused = H_w + Project(concat(H_w,A))
```

每层重复：

```text
Wukong high-order interaction
→ 查询 HSTU sequence evidence
→ 写回 NS/Wukong 分支
```

注意：它主要是 `S → NS` 的逐层注入，不是严格对称双向更新。优点是迁移成熟资产；缺点是系统最复杂、Cross Attention 为 `O(NL)`。

## 十三、OneTrans：单流统一 Transformer



### 13.1 优化的问题

分离式 LONGER + RankMixer 阻断 S/NS 深层交互，无法整体 Scaling。

### 13.2 统一 Tokenization

```text
NS group:
concat(fields_g) → MLP_g → ns_token_g:[B,D]

sequence event:
concat(item_id,category,action,time,...)
→ sequence MLP
→ s_token_i:[B,D]

X0 = [S tokens..., NS tokens...] [B,L+N,D]
```

OneTrans Mixed Parameterization 与 Pyramid

Token 化中的“共享/独立”也要分清：

```text
S token：
不同时间步使用同一套 event tokenizer
因为每一步字段结构一致

NS token：
不同语义组使用独立 projector
因为 user/item/context 的输入宽度与含义不同
```



### 13.3 Mixed Parameterization Block

```text
Z_l = X_l + MixedMHA(RMSNorm(X_l))
X_{l+1} = Z_l + MixedFFN(RMSNorm(Z_l))
```

参数分配：

```text
S token：
共享 Wq_s、Wk_s、Wv_s、FFN_s

第 i 个 NS token：
使用 token-specific Wq_i、Wk_i、Wv_i、FFN_i
```

原因：

```text
行为 token 结构同质 → 适合共享
user/item/context token 语义异构 → 需要独立参数
```

MixedMHA 不是“每类 token 单独做 Attention”。它仍然形成同一个注意力矩阵，只是在生成 Q/K/V 时按 token 类型选择参数：

```text
Q_i = X_i Wq(type_i)
K_i = X_i Wk(type_i)
V_i = X_i Wv(type_i)

A = softmax(Q K^T / sqrt(d) + bias + mask)
```

参数异构发生在投影阶段，交互发生在同一个 Attention 矩阵中；但因排列为 `S 在前、NS 在后` 且使用 causal mask，实际方向是：

```text
S token：只能读取此前的 S
NS token：可以读取全部此前 S，以及此前 NS
```

因此严格说是 `S → NS` 的单向注入，不是同一层内 NS 再反向更新早先 S。

### 13.4 Causal Attention、Pyramid 与 KV Cache

排列：

```text
[S_1,...,S_L,NS_1,...,NS_N]
```

因果 Mask 使后置 NS token 能读取历史 S。

Pyramid 不是内容 top-k，而是逐层只保留尾部部分 query：

```text
Layer 1: L+N queries
Layer 2: shorter tail queries
...
Layer K: only a few tail/NS queries
```

K/V 仍读取该层当前完整输入；本层只保留 Query 对应的输出并交给下一层。被裁掉的旧 token 不会在后续层继续作为 K/V 永久存在。

KV Cache：

```text
同一请求多候选：共享用户 S-side K/V
跨请求 append-only：只计算新增行为 K/V
```

Pyramid 的计算收益来自逐层减少 Query 数。假设第 `l` 层只保留尾部 `q_l` 个 Query，而 K/V 长度仍为 `m_l`，该层注意力主项约为：

```text
O(q_l * m_l * D)
```

它不是按内容分数选 top-k，所以没有动态选择开销，但也天然偏向后置 token。位置偏置校准用于缓解不同 token 类型、相对位置和截断策略带来的系统偏差。

### 13.5 实验证据与边界

论文工业数据中：

- OneTransS 相对生产基线提升 CTR AUC/UAUC `+1.13%/+1.77%`；
- OneTransL 提升 CTR AUC/UAUC `+1.53%/+2.79%`；
- Feeds 场景线上 click/order/GMV per user 分别 `+7.737%/+4.351%/+5.685%`，p99 延迟反而下降 `3.91%`；
- 上述结果是统一 Tokenizer、Mixed Block、Pyramid、KV Cache 和系统优化的整体效果。
- S 在前、NS 在后，交互方向受因果顺序限制；
- Pyramid 偏向尾部行为；
- token-specific NS 参数随 N 增长；
- candidate-specific history 难以共享主 KV Cache。

## 十四、HyFormer：Query Decoding + Query Boosting



### 14.1 优化的问题

传统：

```text
LONGER 先压缩 sequence
→ RankMixer 再做 NS 交叉
```

序列压缩时 query 尚未吸收充分 NS 语义。HyFormer 让 query 在每层交替获得序列证据和 NS 交叉信息。

### 14.2 初始化

```text
NS semantic groups → F_1...F_M
sequence summary   → MeanPool(S)

G = concat(F_1,...,F_M,MeanPool(S))
Q0 = [FFN_1(G),...,FFN_N(G)] [B,N,D]
```

HyFormer Query Decoding 与 Query Boosting

这里的多个 `FFN_i` 不是对同一个结果复制 N 次，而是 N 套参数产生 N 个不同的 Query 槽位。它们没有预先固定为“价格兴趣”“品牌兴趣”，但训练后可以承担不同的信息子空间。

### 14.3 Query Decoding

```text
sequence layer l:
H_l = SequenceEncoder_l(S)
K_l = H_l Wk_l 
V_l = H_l Wv_l

Qhat_l = CrossAttention(
  Q=Q_{l-1},
  K=K_l,
  V=V_l
)
```



### 14.4 Query Boosting

```text
Q_all = concat(Qhat_l, F_1,...,F_M) [B,T,D]
→ RankMixer-style channel split/transpose
→ Per-token FFN
→ enhanced queries Q_l
→ 进入下一层 Query Decoding
```

链路：

```text
query 读取 sequence
→ 与 NS token 做 Token Mixing/PFFN
→ 更强 query 再读取下一层 sequence K/V
```

重要纠正：论文公式没有把增强 query 显式写回 sequence token，因此更准确地说是“query 被 S 与 NS 交替增强”，不是 S/NS 状态完全双向更新。

论文公式还省略了一个接口细节：Query Boosting 输入共有 `T=N+M` 个 token，但下一层 Cross Attention 只需要 `N` 个 query；正文没有明确给出从增强后的 `T` 个位置选回 `N` 个 query 的 slicing 规则，因此实现图不应自行虚构。

多序列场景也不是先把所有行为强行 merge：

```text
每类行为序列独立编码、独立 Query Decoding
→ 在 Query Boosting 阶段做 query-level 跨序列交互
```

这样保留序列特有语义，但会增加多套 Query/KV 的工程管理成本。

Query Bottleneck 的成本和信息容量由 `N` 共同控制：

```text
Cross Attention：O(N * L * D)

N 小：
速度快，但可能压丢多兴趣与细粒度证据

N 大：
表达更强，但 Cross 与后续 Mixer 成本同步增加
```

因此 HyFormer 的关键超参不只是 embedding 维度，还包括 Global Query 数量以及 Query Decoding/Boosting 的层数配比。

### 14.5 实验配置与证据

论文在抖音搜索 70 天、约 30 亿样本的数据上评估，典型配置包含：

```text
13 个 NS tokens
3 个 Global Query tokens（对应 3 类行为序列）
MLP-Mixer 输入 token 总数对齐为 16
64 GPU 训练
```

线上相对强 RankMixer 基线：

- 人均观看时长 `+0.293%`；
- 人均完播视频数 `+1.111%`；
- Query 改写率 `-0.236%`。

这些结果支持 Query Bottleneck 的工业有效性，但 Global Query 数 `3` 来自该场景的三类序列，不是通用推荐值。

### 14.6 与相似工作

MixFormer 同属 Query Bottleneck：

```text
NS Query Mixer
→ query-to-sequence Cross Attention
→ Output Fusion
```

区别是 MixFormer更强调 Dense 容量与 Sequence 长度在共享预算下 Co-Scaling，以及 User-item Decoupling。

## 十五、EST：非对称稀疏的细粒度统一



### 15.1 优化的问题

早期 sequence pooling 丢失行为级信息；全部 S+NS Self Attention 又浪费大量计算。EST 分析真正高价值的块主要是：

```text
NS query ← behavior evidence
behavior ← content-similar behavior
```



### 15.2 Token

```text
N:[B,N,D]   非行为 token
B:[B,L,D]   用户与 candidate-specific 行为 token
M:[B,L,Dm]  冻结内容向量
```



### 15.3 Lightweight Cross Attention

```text
Q_N = token_specific_projection(N)
K_B = B Wk
V_B = B Wv

LCA(N,B) =
softmax(Q_N K_B^T / sqrt(D)) V_B

N_l = N_{l-1} + LCA(N_{l-1},B_{l-1})
```

只计算 `N ← B`，复杂度约 `O(NLD)`，不构造完整 `(N+L)²` Attention。

### 15.4 Content Sparse Attention

```text
G = M M^T                     [B,L,L]
Index,Weight = TopK(G,k)

对行为 i：
B'_i = sum_{j in TopK(i)} Weight_i,j * B_j
```

CSA 是行为—行为内容相似度稀疏聚合，不是简单“候选选择历史”。

每层：

```text
N → LCA(N,B) → Per-token FFN
B → CSA(B,M) → Shared FFN
```

最后：

```text
concat(N_final, MeanPool(B_final))
→ MLP
→ prediction
```



### 15.5 边界

- 构造 `M M^T` 本身可能仍是平方成本，需要跨层复用/预计算；
- 强依赖内容向量质量；
- 删除其他 Attention 块的结论依赖业务；
- 最终仍对行为做 Mean Pooling。

## 十六、TokenFormer：防止统一后的序列表示坍缩



### 16.1 优化的问题

论文观察到朴素统一后，大量低秩、异构 NS token 可能污染结构丰富的 S token，称为：

```text
Sequential Collapse Propagation（SCP）
```

这是论文实验发现的故障模式，不是所有统一模型必然发生的定理。

### 16.2 Token 流

```text
X0 = [
  field tokens F,
  SEP,
  sequence tokens T,
  SEP,
  target tokens V
] [B,M,D]
```

TokenFormer BFTS Attention 与 NLIR

位置设计：

```text
静态 F：位置 0
行为 T：按时间位置
target V：最大序列位置 L_max+1
```

TokenFormer 不额外加入 type embedding，而是统一使用 RoPE；静态 field 共用位置 0 只表示“不人为规定 field 先后顺序”，不表示这些 field embedding 相同。action-aware 输入会将行为与动作都放入 token 流，因此总长度相对纯行为序列近似翻倍。

### 16.3 BFTS Attention

Bottom-Full-Top-Sliding：

```text
底部若干层：
Full Causal Attention
→ 建立全局 S/NS 交互

顶部若干层：
Sliding Window Attention
窗口逐层缩小
→ 集中建模局部行为与 target
→ 减少 NS 污染和计算
```

Mask：

```text
Mask_l[i,j] =
  0       if j <= i and i-j < window_l
  -inf    otherwise

window_1 > window_2 > ... > window_L
```

BFTS 的思路不是“越深看得越远”，而是相反：

```text
底层 Full：
先让 field、sequence、target 建立全局联系

顶层 Sliding：
限制深层信息传播范围
→ 降低计算
→ 避免低秩 NS 信息继续无差别污染所有 S token
```

窗口 schedule 是模型容量与污染控制之间的超参，不能直接照搬固定比例。

TokenFormer 还在进入顶层 Sliding 阶段后丢弃部分前置 NS token：

```text
底层：
保留 F、S、V，建立全局交互

高层：
不再让后续 token 读取已充分注入的部分 F
→ 减少冗余计算
→ 限制低秩 NS 噪声继续传播
```

这不是删除所有非序列信息，而是假设它们已在底层写入 sequence/target 表示；丢弃层数需要与窗口 schedule 联合调参。

### 16.4 NLIR

Non-Linear Interacted Representation：

```text
A_l = Attention(RMSNorm(X_l))
G_l = X_l Wg

I_l = X_l + sigmoid(G_l) * A_l

FFN_l =
  (Swish(RMSNorm(I_l) W1)
   * RMSNorm(I_l) W2) W3

X_{l+1} = I_l + FFN_l
```

乘性 gate 强化非线性交叉，并帮助保持表示可区分性。

NLIR 中有两种不同的乘法：

```text
sigmoid(XWg) * Attention(...)
→ 控制 Attention 更新写回多少

Swish(XW1) * (XW2)
→ SwiGLU 式 channel 非线性交互
```

它们分别作用于“残差更新强度”和“FFN 隐藏通道”，不能都笼统理解为 Attention gate。

### 16.5 实验与 Serving 证据

公开 KuaiRand-27K 的 User-Centric Macro AUC：

- Transformer：`0.85467`；
- TokenFormer-S/M/L：`0.86043/0.86116/0.86282`；
- TokenFormer-L 相对 Transformer 提升 `8.15‰`。

BFTS 消融说明顺序很重要：

- `2 Full + 2 Sliding` 比 `4 Full` 高 `0.85‰`，GFLOPs 下降约 `20.1%`；
- 错序 `2 Sliding + 2 Full` 比最佳配置低 `6.18‰`；
- 全四层 Sliding 相对 vanilla 下降 `36.35‰`；
- NLIR、BFTS 单独分别带来约 `+4.87‰/+4.91‰`。

工业侧论文报告微信视频号 GMV `+4.03%`。Serving 使用用户侧先编码并压成 summary token、再与候选组合的解耦优化，吞吐从 `126` 提升到 `695 QPS`；论文没有充分证明该 serving 路径与完整 unified forward 严格数值等价，因此应把它视为部署近似/优化，而不是训练主干定义。

### 16.6 边界

- 底层 Full Attention 仍有平方成本；
- 上层缩窗可能损失长期依赖；
- NS 在前、S/target 在后，交互方向受 causal 排列约束；
- NLIR 缓解表示坍缩主要是经验结果，不是严格理论保证。

## 十七、其他相似工作如何归位



### HeMix

```text
长期/实时序列
→ 动态 query + 固定 query Cross Attention
→ 压成少量兴趣 tokens
→ 与 NS tokens 合并
→ HeteroMixer
→ pooling → tower
```

适合资源有限、希望兼顾候选相关与稳定兴趣的场景；不属于原始 S/NS token 全统一。

### UniFormer

```text
Feature-space Interaction Modules
→ 得到 feature tokens
→ Task tokens Cross-Attend features
→ Task-space Interaction Modules
→ 多任务输出
```

创新点是把 Scaling 从行为/交叉扩展到任务空间，但仍是分阶段结构。

### Hiformer

```text
field tokens
→ token-specific/heterogeneous QKV
→ Heterogeneous Self Attention
→ low-rank + pruning
```

属于非序列特征交叉，不要和 ByteDance 的 HyFormer 混淆。

## 二十、面试速记



### Attention

```text
Self：同一 token 集合内部交互，L×L。
Target：候选查询历史，1×L，是 Cross 的特例。
Cross：一组 query 查询另一组 K/V，M×L。
RankMixer/Wukong：核心不是 Attention。
```



### 三条路线

```text
交叉 Scaling：
Wukong 看交叉阶数；
RankMixer 看硬件效率；
TokenMixer-Large 看深层和 MoE；
RankUp 看有效表示秩。

序列 Scaling：
HSTU 看推荐原生 Self Attention；
LONGER 看压缩与 Hybrid Attention；
STCA 看线性 Target Cross Attention；
TWIN V2 看离线聚类检索。

统一：
OneTrans 看单流 mixed parameterization；
HyFormer 看 query 交替增强；
EST 看非对称稀疏；
TokenFormer 看 SCP、BFTS、NLIR；
WHALE 看成熟双 Backbone 逐层融合。
```



### 最容易说错

1. Target Attention 是 Cross Attention 的特例。
2. HSTU 是 Self Attention 变体，不是独立 Target Cross Attention。
3. LONGER 第一层 Cross、后续 Self。
4. RankMixer 的 Token Mixing 只是重排，不产生动态权重。
5. TokenMixer-Large 仍主要是 NS Ranking Backbone。
6. RankUp 没有显式 erank loss。
7. OneTrans Pyramid 是尾部 query 截断，不是内容 top-k。
8. HyFormer 主要更新 query，没有明确把 query 写回 sequence。
9. EST CSA 是 behavior-behavior 内容稀疏聚合。
10. WHALE 主要把 HSTU 证据写回 Wukong/NS 分支。
11. Hiformer 是 Google 特征交叉；HyFormer 是 ByteDance 统一模型。
