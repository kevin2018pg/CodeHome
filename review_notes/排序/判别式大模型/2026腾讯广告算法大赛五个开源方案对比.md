# 2026 腾讯广告算法大赛五个开源方案对比

> 任务：根据用户、候选 Item、Dense/Pair 特征及四域历史行为，预测点击后转化概率 pCVR。  
> 本文对比五个公开仓库，重点回答：样本和 Label 是什么、各类字段怎样 Token 化、序列与非序列如何交互、维度怎样变化、训练与推理怎样执行、哪些模块真正值得复用。
>
> 本文以仓库源码为准，明确区分“README/作者声明”“源码事实”和“无法由公开材料独立验证的内容”。不同轮次、数据规模和评测环境的 AUC 不能机械横比。

## 第一部分：赛题与共用模块

### 1.1 与 2025 生成式推荐赛题的根本区别

2025 赛题：

```text
用户历史
→ 生成 User Query
→ 在大候选池中检索下一 Item

Label：下一条真实 Item ID
Loss：InfoNCE / Sampled Softmax
指标：HitRate / NDCG
```

2026 赛题：

```text
用户 + 当前候选 Item + 多域历史序列
→ 单个样本的 pCVR Logit
→ sigmoid
→ conversion probability

Label：label_type == 2 时为 1，否则为 0
Loss：通常为 BCEWithLogits
指标：AUC / weighted-AUC
```

因此 2026 的 Item 是已知候选，不需要从百万广告中生成；模型可以让候选 Item 直接参与 Query、Target Attention 和特征交叉。

### 1.2 样本与 Label

每个 Parquet 行是一条候选级样本：

```text
user_id
item_id
timestamp
user_int / item_int
user_dense / item_dense
seq_a / seq_b / seq_c / seq_d
label_type
```

五个仓库的主 Label 基本一致：

```text
y = 1，若 label_type == 2
y = 0，若 label_type != 2 或缺失
```

这表示点击后的转化预测，不是 CTR。当前公开代码普遍把所有非 2 类型统一视为负类，未进一步区分“真实未转化、未知归因、其他动作或缺失标签”，属于比赛数据语义绑定。

### 1.3 五类输入



#### Sparse / Int

```text
标量 ID 或 multi-hot ID
→ 每个 fid 独立 Embedding
→ 多值字段 masked mean / weighted pooling
```

常见规则：

```text
0：Padding / Missing
负值：置 0
OOV：裁成 0
高基数：跳过、HashEmbedding 或单独处理
```



#### Dense

Dense 不等于“所有连续值混成一个向量”。数据中同时存在：

```text
普通统计标量
长尾 Count/Weight
分段语义向量
预训练/聚合 Embedding
```

较好的做法是按 fid 或内部语义分段，再独立投影成 Token；直接将 918 维全部送入一个 Linear，容易混淆不同量纲和结构。

#### Aligned ID-Dense Pair

部分 fid 同时提供：

```text
IDs：      [id_1,id_2,...]
Weights：  [w_1,w_2,...]
```

它们位置一一对应，不应分别 Mean Pool：

```text
e_pair
= Σ_j log1p(w_j)·Embedding(id_j)
  /
  Σ_j log1p(w_j)
```

这一结构是五个方案中最稳定、最值得迁移的特征工程之一。

#### 多域行为序列

四域通常表示不同业务或行为来源：

```text
seq_a：长度 256
seq_b：长度 256
seq_c：长度 512
seq_d：长度 512～1024
```

每个行为位置又包含多个 Side-info fid：

```text
F 个离散字段
→ F×Embedding
→ Concat + Linear
→ event_token：[B,L,D]
```



#### 时间

常见时间信号：

```text
行为顺序 / Position
当前时间 - 行为时间的 Recency Bucket
相邻行为 Gap Bucket
hour / weekday / weekend
连续 log time delta
Attention Temporal Bias
```

这些信号高度相关。实践中应通过消融控制冗余，不能同时堆叠所有时间特征后仅看单次离线 AUC。

### 1.4 HyFormer：五个仓库的主流骨干

HyFormer 的核心不是把所有历史和静态字段做一次 Full Attention，而是用少量 Global Query 作为瓶颈。

初始化：

```text
NS tokens：User/Item/Dense/Pair
序列：H_a,H_b,H_c,H_d

NS flatten + Sequence Mean
→ 每域生成 Nq 个 Query
```

每层交替：

```text
1. Sequence Evolution
   每域 Transformer / SwiGLU / Longer

2. Query Decoding
   Q_domain ← CrossAttention(Q_domain,H_domain,H_domain)

3. Query Boosting
   Concat(所有 Domain Query,NS Tokens)
   → RankMixer

4. 拆回 Query 和 NS，进入下一层
```

长度复杂度主要为：

```text
Sequence Encoder：O(L²D)，若使用完整 Transformer
Query Decoding：  O(Nq·L·D)，Nq << L
Query Boosting：  在少量 Query/NS Token 上执行
```



### 1.5 RankMixer 在本赛题中的作用

RankMixer 主要承担：

```text
NS 特征交叉
或 HyFormer 中 Query + NS 的 Query Boosting
```

无参数 Mixing：

```text
X：[B,T,D]
→ [B,T,H,D/H]
→ 交换 Token 轴与 Head/Channel-group 轴
→ [B,T,D]
```

当实现要求 `H=T` 时，Mix 前后 Token 数和残差形状才能严格对齐。

不同仓库 Tokenizer 差异很大：

```text
Auto-split：
全部 field embedding 拼平，再等长切块
优点：简单
缺点：切断 field 语义

Per-field / Semantic：
每个重要 field 或语义组独立生成 Token
优点：语义清楚，扩容有效
缺点：Token 数和参数更大
```



### 1.6 Target Attention、Target Bias 与 DIN Residual



#### Target-conditioned Query

```text
候选 Item 表示
+ NS
+ Sequence Summary
→ Query Generator
```

让候选在进入 HyFormer 之前就影响 Query。

#### Target Attention Bias

```text
bias_j
= <Wq·target,Wk·history_j>/sqrt(D)

CrossAttentionLogit
= QK^T/sqrt(d) + alpha·bias
```

`alpha=0` 初始化可让新增模块起步时退化为原模型。

#### DIN Residual

```text
target 作为 Q
history 作为 K/V
→ candidate-aware interest
→ 小门控/零初始化投影
→ residual 加回 Backbone 输出
```

稳定做法通常是“轻量残差增强”，而不是用 DIN 直接替换已经训练稳定的 HyFormer 主干。

### 1.7 Structured Dense

对具有内部结构的 Dense 字段：

```text
大语义向量
+ 若干统计值
+ Missing Indicator
```

较好做法：

```text
按语义 Slice
→ 每段独立 Linear/MLP
→ Learned Query Pool / Attention Pool
→ 1 个或多个 D 维 Token
```

需要注意：

- 硬编码 Slice 只适用于固定 Schema；
- 迁移时必须配置化；
- Dense Missing 与真实 0 最好分开；
- Count/Weight 先做 `log1p`，避免长尾支配投影。



### 1.8 主 Loss 与辅助 Loss

主任务最稳的是：

```text
L_main = BCEWithLogits(logit,y)
```

类别不平衡可使用：

```text
pos_weight
Focal Loss
```

常见辅助项：

```text
Pairwise：
softplus(-(positive_logit-negative_logit))

Candidate InfoNCE：
用户表示与自身 Item 拉近，与 Batch Item 拉远

History InfoNCE：
加入用户历史 Item 作为候选

SupCon：
同 Label 样本拉近，异 Label 推远
```

风险：

- pCVR 负样本同样是已点击 Item，把自身 Item固定为 InfoNCE 正类，学习到的可能是点击兴趣而非转化；
- Pairwise 改善排序但可能干扰概率校准；
- 辅助 Loss 应以小权重、独立消融为主。



### 1.9 训练系统共性

```text
Sparse Embedding：Adagrad
Dense 参数：AdamW / Muon
混合精度：bf16
稳定性：Gradient Clip
权重平均：EMA / SWA
可选：SAM
```

区别：

```text
EMA：指数平均，偏向近期参数
SWA：多个时间点等权平均，含 BN 时需重算统计
SAM：两次 Forward/Backward，成本接近翻倍
Muon：对矩阵梯度正交化，主要适合 Dense 权重
```

### 2.1.3 round2 Sparse 与 Pair Tokenization

Sparse 自适应 Embedding：

```text
vocab≤4：4维
≤10：8维
≤50：16维
≤600：32维
更大：64维
```

然后：

```text
所有 fid embedding 拼接
→ LHUC Gate
→ Padding + 等长分块
→ 每块 Linear(chunk,D)
```

默认：

```text
user int：14×192
item int：3×192
```

Pair：

```text
ID embedding：[B,l,e]
dense：Linear(1,e)
统计：valid_count/max/min/std
→ Linear(2e+4,e)
+ dense-weighted ID residual
→ 每 fid e 维
→ 注入 user RankMixer 分块
```

Pair 不是单独 Token，最终 user int Token 数仍为 14。

### 2.1.4 round2 Dense

User Dense 通常形成 4 个 Token：

```text
fid61：前256维 → Linear(256,192)
fid87：10×32 block → attentive pool → Linear(32,192)
118/120/121 组合 → 1 Token
123/130/131/132 组合 → 1 Token
```

Item Dense：

```text
每个普通 field → 1 Token
fid129：
前128维 body → 1 Token
第129个 stat → log1p → 1 Token
剩余维度忽略
```



### 2.1.5 round2 序列与 Forward

每域事件：

```text
S_d 个 Sparse Field ×64
+ 8维连续时间 → Linear(8,64)
→ Concat
→ Linear((S_d+1)×64,192)
+ Recency Bucket Embedding
+ Gap Bucket Embedding
→ [B,L,192]
```

默认四域 Interleave：

```text
四域 Token 拼接
→ 按离散 Time Bucket 排序
→ 单一 Interleave Sequence
```

DualQ：

```text
User NS / Item NS / Time
→ 4 个 User Query + 2 个 Item Query
→ [B,6,192]
```

两层：

```text
SwiGLUEncoder：
逐位置 LN→SwiGLU→Residual
不做 history-history Attention

Query Decoding：
6 个 Q Cross-Attend 整个 Interleave Sequence

Query Boosting：
6 Q + NS → RankMixer
```

最后：

```text
6×192
→ Flatten
→ Linear(...,192)
→ Classifier
→ 1 Logit
```

README 容易让人误以为 SwiGLUEncoder 在做序列交互；实际跨行为聚合主要来自 Query-to-Sequence Cross-Attention。

### 2.1.7 MaskRec 统一 Backbone

序列压缩：

```text
seq_a：96 recent + 4 tail summary = 100
seq_b：64 + 4 = 68
seq_c：96 + 4 = 100
seq_d：128 + 4 = 132
总序列：400
```

加上：

```text
DualQ：24
NS：21
Global Memory：32
Domain Memory：4×8=32
总长度约509
```

每个 UniRecBlock：

```text
TopoMask Self-Attention
→ Residual
→ Shared FFN
+ Token-type Low-rank Adapter
```

TopoMask 规定：

```text
Global Memory：看全部
Domain Memory：看本域 Sequence/Q 与全部 Memory
Sequence：看本域局部窗口、本域 Q/Memory
普通 NS：看 NS、Memory 和各域 Recent
Domain Q：看本域完整 Sequence
```

Readout：

```text
DualQ Mean
+ Item Token Mean
+ Global Memory Mean
+ 4个 Domain Memory Mean
→ 7×192=1344
→ MLP
→ 1 Logit
```

当前仍使用 Dense SDPA Mask，复杂度接近 `O(509²D)`，并不是真正 Block-sparse Kernel。

### 2.2.5 四域 DIN

```text

→ Concat

+ 65档 Time-gap Embedding
```

```text
所有 Item Field Embedding Mean
```

```text
[q,k,q-k,q*k]
```

```text
seq_a=256
```

### 2.2.6 RankMixer Forward

语义 Tokenizer：

```text
每个 Group x_g
→ Linear(width_g,n_g×1152)
→ reshape [B,n_g,1152]
```

每个 Block：

```text
Token Mixing
→ Residual + RMSNorm
→ Per-token pSwiGLU
→ Residual + RMSNorm
```

pSwiGLU：

```text
up_t   = x_t W_up_t
gate_t = x_t W_gate_t
h_t    = up_t * SiLU(gate_t)
out_t  = h_t W_down_t
```

每个 Token 有独立参数，扩张倍数 2。两个 Block 后：

```text
24 Token Mean Pool
→ Deep Representation：[B,1152]
```



### 2.2.7 SENet、Deep/Wide 与 Bilinear

原始 7399 维输入：

```text
BatchNorm
→ Channel SENet：7399→1024→256→7399
→ x_se = x*sigmoid(gate)
```

Deep：

```text
1152→1024→512→256→128→1
```

Wide/Shallow：

```text
7399→512→128→1
```

两边隐藏向量均为 128，切成 8 组、每组16维：

```text
z_bilinear
= Σ_g deep_g^T W_g wide_g
```

最终：

```text
logit
= deep_logit
+ wide_logit
+ zero-init bilinear residual
```

### 2.2.9 消融与边界

作者声明：

```text
Weighted Pair Pooling：+7.469‰
SWA：+3.272‰
总提升：+14.716‰
```

这些是累计式消融，不是所有模块从同一基线独立开关。24 Token 与 D=1152 同时变化，也不能将增益全部归因于 Per-field Tokenization。

主要风险：

```text
1. 模型约601M参数，Dense约425.6M，部署成本高。
2. SAM训练成本接近翻倍。
3. vocab>1M字段直接归零，丢失高基数信号。
```

### 2.3.4 TargetAttnBias

Target：

```text
Item NS Mean → [B,64]
```

每层、每域独立：

```text
q_t = Linear(LN(target))
k_j = Linear(LN(sequence_j))
bias_j = <q_t,k_j>/sqrt(64)
```

加入 Query Cross-Attention：

```text
attn_logit += alpha_layer,domain * bias
```

`alpha=0` 初始化，因此训练初期等价于原主干。

需要注意：当前层 Bias 实际由进入本层前的 `curr_seqs` 计算；首层使用原始 Sequence Embedding，后续层使用上一层输出，并非总是当前层 Sequence Encoder 后的结果。

### 2.3.5 DIN Residual

DIN Query：

```text
User Mean
+ Item Mean
+ User*Item
+ |User-Item|
→ 4×64=256
→ 256→128→64
```

每域：

```text
Query 与 History Dot
→ Mask
→ Top32
→ Softmax
→ Context 64
```

四域 Context 用 Gate 聚合，再生成：

```text
delta：[B,64]
output = backbone_output + delta
```

Delta 末层零初始化。DIN 使用进入 HyFormer 前的原始序列 Token，不是最后一层序列表示。


### 2.3.7 Auxiliary Loss

三路 Projection Head：

```text

64→64→64
→ L2 Normalize
```

主 Loss：

```text
L_main = BCE
```

活跃辅助项：

```text

= BCE
+ 0.1*(CandidateInfoNCE + 0.25*HistoryInfoNCE)
```

Candidate 候选：

```text

+ Batch 随机 Item，最多63
```

History 候选：

```text
自身 Item
+ Batch Item
+ 同用户历史中随机抽取最多32个 Token
```

所谓 History Hard Negative 实际按随机数 Top-K 抽样，不是根据相似度或当前 Loss 挖掘。

```text
即使 y=0，自身 Candidate Item 仍被 InfoNCE 当成正类。
```

这更接近“用户点击兴趣匹配”，不完全等价于“转化偏好匹配”。

```text
4. seq_d使用Recent/Older Dual-window DIN或Tail Summary
5. Dense-only EMA
6. Per-field/Semantic Tokenization
```

这些模块都可以从基线平滑退化，适合单变量消融。

#### 第三阶段：容量扩展

算力有限：

```text
D=128或192
Token=16～24
Block=2～4
不要直接上D=1152、601M参数
```

算力充足：

```text
Semantic RankMixer
+ 24～32 Token
+ D=384～768
+ 2～4 Block
```

只有当 Per-field Tokenizer 在相同 D 和训练预算下已验证有效，再继续放宽。

#### 第四阶段：谨慎尝试

```text
Pairwise Loss：lambda 0.01～0.03
Aux InfoNCE：先确认负样本自身Item是否应为正类
SWA：含BN时必须重算统计
Muon：仅在大Dense矩阵上尝试
SAM：最后再试，因训练成本近2倍
TopoMask Unified Backbone：先实现Block-sparse Kernel
```



### 3.6 明确不建议照搬

```text
1. 每Epoch重置全部/大部分Sparse Embedding
2. Pair Dense在Dataset和Model重复log1p
3. 918维Dense固定Slice且无Schema校验
4. CrossNet、SENet、NS Attention、RankMixer、Output Fusion全部同时开
5. Recency、Gap、Calendar、Cyclical、Temporal Bias全部同时开
6. 用测试集重新统计训练期Frequency特征
7. 以user_id作为唯一预测Key而不检查重复
8. 在509 Token上使用Dense TopoMask却称为稀疏统一建模
9. 把随机历史采样称为Hard Negative
10. 在没有相同基线消融时，仅按README增益判断模块有效
```



### 3.7 最终结论

本赛题最稳定的优化优先级是：

```text
第一优先级：
正确Label与时间切分
Aligned ID-Weight Pair
Structured Dense
Target-conditioned Query

第二优先级：
HyFormer Query Bottleneck
Zero-init Target Bias
Gated DIN Residual
长短期序列拆分

第三优先级：
Semantic RankMixer扩容
EMA/SWA
轻量Pairwise

最后才是：
Full Unified Backbone
大规模MoE/RankMixer
Muon+SAM
多类辅助对比Loss
```
