# 经典精排模型复习：特征交叉、序列与多任务

> 这篇笔记不追求收集全部模型，而是掌握现代工业精排的基础积木。近两年的 RankMixer、LONGER、OneTrans 等工作，本质上仍在回答三个经典问题：特征如何交叉、行为如何形成候选兴趣、多个业务目标如何联合学习。

---

## 一、重点复习顺序

### 第一优先级：必须能手写链路

1. **DeepFM**：FM 显式二阶交叉 + DNN 隐式高阶交叉。
2. **DCNv2**：可控、稳定的显式高阶交叉。
3. **DIN**：候选相关 Target Attention。
4. **DIEN**：兴趣抽取、辅助损失、兴趣演化。
5. **ESMM**：曝光空间中联合学习 CTR 与 CVR。
6. **MMoE / PLE**：多任务专家共享与负迁移控制。

### 第二优先级：理解差异

- LR / Wide & Deep：记忆与泛化的起点；
- FM / FFM：低秩二阶交叉；
- xDeepFM：向量级显式高阶交叉；
- AutoInt：field token Self Attention；
- DLRM：工业稀疏推荐基线；
- BST：Transformer 行为序列；
- SIM：长序列两阶段检索。

### 一张总图

```text
Raw Features
  │
  ├─ categorical → Embedding
  ├─ numerical   → Normalize/Projection
  └─ behavior    → Sequence Encoder
                         │
                         ▼
                  Candidate-aware Interest
                         │
     ┌───────────────────┴──────────────────┐
     ▼                                      ▼
Feature Interaction                    Multi-task Learning
FM/DeepFM/DCN/AutoInt                 ESMM/MMoE/PLE
     │                                      │
     └───────────────────┬──────────────────┘
                         ▼
                  pCTR/pCVR/value
```

## 二、工业精排的统一输入



### 2.1 非序列字段

```text
用户：user_id、年龄、城市、会员等级
候选：item_id、类目、品牌、价格
上下文：时间、设备、渠道、广告位
统计：历史 CTR/CVR、频次、活跃度
交叉：user-item 相似度、query-item 匹配度
```

离散字段：

```text
field_i
→ embedding table_i
→ e_i:[B,d_i]
```

数值字段：

```text
x_i
→ clip/log/normalize
→ Linear(1,d_i)
→ e_i:[B,d_i]
```



### 2.2 行为序列

```text
history ids: [B,L]
→ embedding lookup
→ H:[B,L,D]
→ pooling / GRU / Attention / Transformer
→ interest:[B,D]
```



### 2.3 最终训练样本

```text
样本 = (
  user features,
  target item features,
  context,
  behavior sequence,
  labels
)

labels 可包含：
click、conversion、duration、GMV、like、finish
```

# 路线 A：静态多域特征交叉



## 三、LR 与 Wide & Deep：人工交叉的起点



### 3.1 LR

```text
logit = w0 + sum_i(w_i * x_i)
p = sigmoid(logit)
```

操作含义：模型为每个特征学习一个标量权重，当前样本激活哪些特征，就把对应权重相加。`sigmoid` 再将任意实数 logit 映射到 0～1 概率。LR 没有 embedding 之间的自动交互。

LR 只能学习一阶贡献，因此工业中需要人工构造：

```text
city × hotel_category
user_level × coupon_level
query_city × item_city
```

优点：

- 快、稳定、可解释；
- 适合超大稀疏空间；
- 可作为校准或线上保底模型。

问题：

- 人工交叉依赖经验；
- 无法泛化到未出现的组合；
- 高阶组合数量指数增长。



### 3.2 Wide & Deep

```text
wide_logit = Linear(raw + manual_cross)

deep_input = concat(embeddings, dense)
deep_logit = MLP(deep_input)

logit = wide_logit + deep_logit
p = sigmoid(logit)
```

执行时，两条分支读取同一个样本：

- Wide 分支直接累加原始特征和人工交叉的线性权重，保留明确规则；
- Deep 分支将离散特征查成 embedding，与数值特征拼接后经过多层非线性变换；
- 两个分支各输出一个标量 logit，相加后统一计算概率。

核心思想：

```text
Wide：记忆已出现的高价值组合
Deep：泛化到相似但未完全出现的组合
```

它奠定了现代推荐“多分支融合”的基本形式。

## 四、FM 与 FFM：低秩二阶交叉



### 4.1 FM 要解决的问题

若直接为每对特征学习参数：

```text
interaction_ij = w_ij * x_i * x_j
```

参数量接近 `O(N²)`，稀疏组合又很难训练。

FM 为每个特征学习低维向量：

```text
v_i:[K]

logit =
  w0
  + sum_i(w_i x_i)
  + sum_{i<j} dot(v_i,v_j) x_i x_j
```

这三项分别完成：

```text
w0：
全局基础分。

w_i x_i：
特征 i 单独产生的一阶贡献。

dot(v_i,v_j) x_i x_j：
特征 i 与 j 的二阶组合贡献。
```

对于 one-hot 离散输入，`x_i x_j` 是激活开关：当前样本同时包含两个特征时，这对交叉才生效；对于数值特征，它还会按数值大小缩放交叉贡献。`v_i` 和 `v_j` 是可训练 embedding，内积输出一个标量，表示这两个特征的匹配强度。

实际执行过程：

```text
稀疏输入 x
→ 找出当前样本激活的特征
→ 查询每个特征的一阶权重 w_i 和 embedding v_i
→ 累加一阶分数
→ 计算激活特征 embedding 的二阶交叉总分
→ 加上 w0，得到一个 logit
```

交叉参数由独立的 `w_ij` 改为 `dot(v_i,v_j)`。同一个 `v_i` 会参与特征 i 与所有其他特征的交叉，因此稀疏或未充分共现的组合也能共享训练信息。

### 4.2 高效计算

```text
sum_{i<j} dot(v_i,v_j) x_i x_j

= 1/2 * sum_k[
     (sum_i v_i,k x_i)^2
     - sum_i(v_i,k x_i)^2
   ]
```

这个变换来自：

```text
(a_1 + ... + a_N)^2
= sum_i(a_i^2) + 2 * sum_{i<j}(a_i a_j)
```

对 embedding 的每个维度 `k`：

1. 先计算所有 `v_i,k x_i` 的和并平方；
2. 减去每个 `v_i,k x_i` 自身平方的和；
3. 除以 2，正好留下所有不同特征之间的两两乘积；
4. 再对 K 个 embedding 维度求和，得到二阶交叉标量。

因此不需要逐对执行 `dot(v_i,v_j)`：

```text
逐对计算：N(N-1)/2 个特征对，每对做 K 维内积
高效计算：每个 embedding 维度只遍历一次 N 个特征

O(N²K) → O(NK)
```



### 4.3 FFM

FM 中一个特征只有一个 embedding；FFM 为它与不同 field 的交互学习不同 embedding：

```text
v_{i,field(j)}

interaction_ij =
dot(
  v_{i,field(j)},
  v_{j,field(i)}
) x_i x_j
```

操作含义：

```text
FM：
特征 i 无论与哪个 field 交叉，都使用同一个 v_i。

FFM：
特征 i 与 user field 交叉时查一套 embedding，
与 item field 交叉时查另一套 embedding。
```

这样可以区分同一特征在不同交叉对象下的语义，表达更强；但每个特征需要保存多套 embedding，参数和内存显著增加。

## 五、DeepFM：最经典的通用精排基线



### 5.1 优化的问题

Wide & Deep 的 Wide 部分仍依赖人工交叉。DeepFM 希望：

```text
FM 自动学习低阶交叉
DNN 自动学习高阶交叉
并共享同一套 embedding
```



### 5.2 完整链路

```text
raw sparse features
→ shared embedding lookup
→ E:[B,F,D]

分支 1：
E → FM 一阶 + 二阶 → y_fm

分支 2：
flatten(E) + dense
→ MLP
→ y_deep

logit = y_fm + y_deep
p = sigmoid(logit)
```



### 5.3 核心公式

```text
y_fm =
  w0
  + sum_i(w_i x_i)
  + sum_{i<j} dot(v_i,v_j) x_i x_j

h0 = concat(v_1 x_1,...,v_F x_F,dense)
h_{l+1} = activation(W_l h_l + b_l)
y_deep = W_out h_L

p = sigmoid(y_fm + y_deep)
```

这里不是先执行 FM 再执行 DNN，而是两个分支并行：

1. embedding lookup 得到 `E:[B,F,D]`；
2. FM 分支直接从 E 计算所有 field 的二阶内积总分；
3. Deep 分支把 E 展平，使 MLP 可以联合使用所有 field；
4. 两个分支的标量 logit 相加，共同反向更新同一套 embedding。

共享 embedding 的作用是让同一个特征表示同时学习“适合与谁做二阶组合”和“如何参与更复杂的非线性模式”。

### 5.4 为什么长期实用

- embedding 同时被 FM 和 DNN 监督；
- 实现简单、训练稳定；
- 对稀疏离散特征非常友好；
- 可轻松接序列兴趣和多任务塔。



### 5.5 局限

- FM 只显式学习二阶；
- DNN 高阶交叉是隐式的；
- flatten 后 field 结构逐渐丢失；
- 盲目加深 DNN 通常不会持续 Scaling。

## 六、xDeepFM：显式向量级高阶交叉



### 6.1 CIN

输入：

```text
X0:[B,F,D]
```

其中 `F` 是 field 数，`D` 是 embedding 维度。CIN 不先把它展平成一个长向量，而是始终保留“有多少个 feature map”和“每个 map 是 D 维向量”。

第 k 层输入：

```text
X_{k-1}:[B,H_{k-1},D]
X0:       [B,F,D]
```

核心操作分三步。

第一步，对上一层每个 feature map 与原始每个 field 做逐元素乘法：

```text
cross_{i,j} =
X_{k-1,i} elementwise_mul X_{0,j}

cross_{i,j}:[B,D]
```

逐元素乘法保留 D 个 embedding 维度，不像 FM 的 `dot` 那样立即压成一个标量。若 `X_{k-1,i}` 已表示 k 阶关系，再乘原始 field `X0_j`，就得到 k+1 阶关系。

第二步，用可学习权重将大量 `(i,j)` 交叉组合压缩成第 h 个新 feature map：

```text
X_k,h =
sum_i sum_j
  W_k,h,i,j * cross_{i,j}

X_k:[B,H_k,D]
```

这里 `W_k,h,i,j` 决定第 h 个输出 map 应保留哪些交叉组合。它对整个 D 维向量使用同一个系数，所以 CIN 学的是 vector-wise interaction。

第三步，各层输出沿 embedding 维度 sum pooling：

```text
p_k = sum_over_D(X_k)       [B,H_k]
cin_output = concat(p_1,...,p_K)
cin_logit = Linear(cin_output)
```

完整链路：

```text
X0:[B,F,D]
→ Layer 1：X0 与 X0 逐元素交叉并加权组合，得到二阶 maps
→ Layer 2：上一层 maps 再与 X0 交叉，得到三阶 maps
→ ...
→ 各层 maps 做 sum pooling 并拼接
→ Linear → CIN logit

同时：
X0 → DNN → deep logit

final = CIN logit + deep logit + linear
```

因此：

```text
FM：两两 embedding 内积，显式二阶，输出标量
CIN：逐元素向量交叉并逐层叠加，显式高阶，保留向量结构
```

局限是中间 `(H_{k-1} × F)` 组合较多，层宽和分组方式敏感，计算图也不如简单 MLP/GEMM 规则。

## 七、DCN / DCNv2：可控的显式高阶交叉



### 7.1 DCN Cross Layer

输入展平：

```text
x0:[B,D]
```

第 l 层：

```text
x_{l+1} =
  x0 * (x_l^T w_l)
  + b_l
  + x_l
```

其中：

```text
x_l^T w_l → [B,1]
x0 * scalar → [B,D]
```

操作含义：

1. `x_l^T w_l` 将当前层全部维度加权汇总成一个样本级标量；
2. 用该标量整体缩放原始输入 `x0`，相当于让当前交叉状态控制原始特征重新进入网络；
3. 加上 `x_l` 残差，保留已有低阶信息。

因为每层都让当前表示再乘一次 `x0`，所以最高交叉阶数每层增加一阶；但一个标量统一缩放所有维度，表达能力受限。

### 7.2 DCNv2 Matrix Cross

```text
x_{l+1} =
  x0 elementwise_mul (W_l x_l + b_l)
  + x_l
```

DCNv2 先用矩阵 `W_l` 让当前表示各维度充分线性组合，再与 `x0` 对应维度相乘：

```text
W_l x_l：生成 D 个不同的交叉控制量
x0 * (...)：每个原始维度分别形成乘性交叉
+ x_l：保留原表示
```

相比 DCN 的单一标量，DCNv2 能为不同维度学习不同交叉方式。

### 7.3 Low-rank DCNv2

```text
W_l ≈ U_l V_l
 
V_l:[R,D]
U_l:[D,R]
R << D
```

纯 Low-rank 只是将完整矩阵乘法拆成两次较小的线性变换：

```text
h_l = V_l x_l                       [B,R]
z_l = U_l h_l + b_l                 [B,D]

x_{l+1} =
x_l + x0 elementwise_mul z_l
```

操作顺序：

```text
x_l
→ V_l：D 维压缩到 R 维
→ U_l：R 维恢复到 D 维
→ 与 x0 逐元素相乘
→ 加回 x_l
```

如果中间没有激活函数，`U_l V_l` 仍等价于一个线性矩阵，只是其秩最高为 R。它假设完整 W 中真正独立的交叉方向远少于 D。

参数与计算量：

```text
Full-rank：
W:[D,D]
参数和单层矩阵计算约 O(D²)

Low-rank：
V:[R,D]，U:[D,R]
参数和单层矩阵计算约 O(2DR)
```

只有 `2R < D` 时才真正比完整矩阵便宜。公开 TensorFlow Recommenders 实践中，`R≈D/4` 常能较好保留 Full-rank 精度；具体仍需按数据和延迟调参。

### 7.4 MoE Cross

DCN-Mix 为每个 Expert 增加一套低秩子空间和非线性变换。较完整的单 Expert 可写为：

```text
expert_e(x_l) =
x0 elementwise_mul
U_e activation(
  C_e activation(
    V_e x_l
  )
)

V_e:[R,D]
C_e:[R,R]
U_e:[D,R]

gate = softmax(G x_l)
cross = sum_e gate_e * expert_e(x_l)

x_{l+1} = x_l + cross
```

执行过程：

1. E 个 Expert 并行把 `x_l` 压入各自的 R 维子空间；
2. `C_e` 和激活函数在低维空间学习该 Expert 专属的非线性交叉模式；
3. 各 Expert 恢复到 D 维并与 `x0` 逐元素相乘；
4. Gate 根据当前样本生成 E 个权重；
5. 对 Expert 交叉结果加权求和，再与 `x_l` 做残差。

这里的 MoE 通常是 Dense MoE：所有 Expert 都会计算，再由 softmax Gate 加权；它主要增加样本自适应表达能力，不像 LLM 的 Top-K Sparse MoE 那样天然节省计算。

近似复杂度：

```text
E 个 Low-rank Experts：
O(E * (2DR + R²))

当 E*R 远小于 D 时，
才可能比 Full-rank 的 O(D²) 更经济。
```



### 7.5 Cross 与 Deep 如何组合

DCNv2 常见两种结构。

并联：

```text
x0 ─→ Cross Network ─┐
                     ├→ concat → output layer
x0 ─→ Deep Network ──┘
```

Cross 保留显式有界阶交叉，Deep 补充隐式非线性关系，两条分支互不阻塞。

串联：

```text
x0
→ Cross Network
→ DNN
→ output
```

DNN 直接消费显式交叉后的表示，结构更紧凑，但 Cross 输出成为后续唯一输入。两种结构没有固定胜负，需要按数据、参数预算和线上延迟验证。

### 7.6 工程上如何选择

```text
D 较小、追求表达能力：
Full-rank DCNv2

D 较大、延迟或显存受限：
Low-rank DCNv2，先尝试 R=D/4 或 D/8

单个 Low-rank 明显欠拟合，样本模式差异大：
DCN-Mix
```

一般先从 Full-rank 或单个 Low-rank 开始，再根据离线收益和线上成本决定是否增加 Expert；不建议默认直接使用 DCN-Mix。

### 7.7 为什么 DCNv2 是重要基线

- 显式交叉阶数可控；
- 比纯 MLP 更容易学习乘性关系；
- Low-rank/MoE 可平衡容量与成本；
- 工业实现成熟。

局限：展平后缺少 token 结构，继续扩大会受到矩阵规模与收益饱和限制。

## 八、AutoInt 与 Hiformer：Attention 做 field 交叉



### 8.1 AutoInt

把每个 field embedding 当作 token：

```text
X:[B,F,D]

Q = X Wq
K = X Wk
V = X Wv

A = softmax(Q K^T / sqrt(d))
O = A V
```

操作含义：

1. 每个 field token 分别生成 Query、Key、Value；
2. `Q K^T` 生成 `[B,F,F]` 分数矩阵，第 i 行表示 field i 对所有 field 的相关性；
3. softmax 将每行归一化为权重；
4. `A V` 让每个 field 按权重汇总其他 field 的 Value；
5. 多层堆叠后，每个 field 表示包含动态选择的高阶交互信息。

多层 Self Attention：

```text
field tokens
→ MHA + residual
→ MHA + residual
→ pooling/flatten
→ prediction
```

每个 field 都能动态选择其他 field。

### 8.2 Hiformer

普通 Self Attention 对所有 field 共享 Q/K/V，但推荐字段高度异构：

```text
user_id、price、device、context
```

Hiformer 使用 feature-aware/heterogeneous projection，并配合低秩近似与剪枝满足线上时延。

具体区别是：普通 AutoInt 的所有 field 共用一套 Q/K/V 投影；Hiformer 让不同 field 或 field 组合使用有区别的投影参数，再用低秩分解控制参数。这样 `user_id` 和 `price` 不必被迫用完全相同的变换理解其他字段。

### 8.3 局限

- Attention 复杂度约 `O(F²D)`；
- field 间点积相似度不一定符合业务语义；
- QKV 和小矩阵算子可能降低 GPU 利用率。

这也是 RankMixer 放弃动态 Attention、改用固定 Token Mixing 的背景。

## 九、DLRM：工业稀疏推荐基线



### 9.1 链路

```text
dense features
→ Bottom MLP
→ dense vector d:[B,D]

sparse fields
→ embedding tables
→ e_1...e_F:[B,D]

[d,e_1,...,e_F]
→ pairwise dot interaction
→ concat(original dense)
→ Top MLP
→ prediction
```

Pairwise interaction：

```text
z_i,j = dot(e_i,e_j)
```

操作含义：

1. Bottom MLP 先把所有 dense 数值特征压成一个 D 维 token；
2. 每个 sparse field 查表得到一个 D 维 embedding；
3. 对这些 token 两两内积，每一对得到一个标量交叉值；
4. 将所有上三角交叉标量与原 dense token 拼接；
5. Top MLP 在二阶交叉结果上继续学习非线性组合。

DLRM 与 FM 都使用内积，但 FM 将全部二阶内积求和为一个标量；DLRM 保留每一对 field 的内积结果，再交给 Top MLP 区分不同交叉。

### 9.2 价值

- 明确拆分 sparse embedding 和 dense MLP；
- 方便做 embedding shard、All-to-All 和 GPU 系统优化；
- 是 Meta/Wukong/HSTU 等工作的关键工业基线。

局限：交叉主要是二阶内积，序列与复杂高阶关系需要额外模块。

# 路线 B：用户行为序列



## 十、Pooling：不要低估简单基线



### Mean/Sum Pooling

```text
interest = sum_i mask_i * h_i / valid_count
```

操作含义：用 mask 去掉 padding，再对有效行为 embedding 逐维求平均。输出仍是 D 维向量，但行为顺序和候选差异都被忽略。

### 时间衰减

```text
decay_i = exp(-lambda * time_gap_i)
interest =
  sum_i decay_i * h_i
  / sum_i decay_i
```

操作含义：先根据行为距当前时刻的时间差生成衰减系数，再做加权平均；近期行为贡献更大，但权重只由时间决定，不由候选内容决定。
优点：

- 成本极低；
- 可跨候选复用；
- 对行为少、顺序弱的任务很强。

问题：所有候选共享同一个兴趣向量，无法表达“用户面对不同候选时兴趣不同”。

---



## 十一、DIN：候选相关兴趣



### 11.1 优化的问题

同一个用户面对酒店、机票、火车票时，相关历史不同。DIN 使用 target 查询历史：

```text
target q:[B,D]
history H:[B,L,D]
→ Target Attention
→ interest(q,H):[B,D]
```



### 11.2 Local Activation Unit

将 target 复制到每个时间位置：

```text
q_expand:[B,L,D]
```

构造匹配特征：

```text
m_i = concat(
  q,
  h_i,
  q - h_i,
  q * h_i
)                         [B,4D]

score_i = MLP(m_i)        [B,1]
```

这四组输入分别表示：

```text
q、h_i：候选和历史各自是什么
q-h_i：两者差异
q*h_i：逐维匹配关系
```

MLP 将这组匹配特征压成一个标量分数，因此每条历史行为都有一个候选相关权重。

聚合：

```text
weight_i = mask_i * score_i
interest = sum_i weight_i * h_i
```

原始 DIN 不强制对 score 做 softmax，因此权重和可以随相关行为数量增大，兴趣向量能保留一定的兴趣强度；一些工程实现会根据稳定性需要加入 softmax。加权求和后，长度 L 被压成一个 D 维候选兴趣。DIN 更新的是最终兴趣向量，不更新每条历史行为表示。

完整链路：

```text
target embedding + history embeddings
→ Local Activation Unit
→ target-aware interest
→ concat(user,target,context,interest)
→ MLP
→ CTR
```



### 11.3 特点和局限

优点：

- 计算约 `O(LD)`；
- 候选相关；
- 对短序列精排性价比很高。

局限：

- 历史行为之间不交互；
- 天然不理解顺序；
- 需要额外加入位置、时间间隔、行为类型。

---



## 十二、DIEN：兴趣抽取与演化



### 12.1 优化的问题

DIN 直接对原始行为 Attention，没有显式建模兴趣状态随时间演化。DIEN 分为：

```text
Behavior Layer
→ Interest Extractor
→ Interest Evolving Layer
→ Prediction
```



### 12.2 Interest Extractor

```text
h_t = GRU(x_t,h_{t-1})
```

GRU 按时间顺序读取行为。`h_t` 不只是第 t 个 item embedding，而是融合了截至 t 时刻历史的兴趣状态。由于 GRU 串行更新，顺序信息被明确保留。
使用相邻行为预测辅助任务：

```text
positive: next clicked item e_{t+1}
negative: sampled non-click item e'_{t+1}

p_pos = sigmoid(MLP(concat(h_t,e_{t+1})))
p_neg = sigmoid(MLP(concat(h_t,e'_{t+1})))

L_aux =
-sum_t[
  log(p_pos)
  + log(1-p_neg)
]
```

操作含义：用 `h_t` 分别与真实下一条行为和负采样行为计算匹配概率，要求前者高、后者低。辅助损失直接约束每个中间状态，而不是只依赖最终 CTR 标签，从而让 `h_t` 更像可预测下一步行为的兴趣表示。

### 12.3 Interest Evolving

候选对每个兴趣状态计算 Attention：

```text
a_t = Attention(target,h_t)
```

AUGRU 用 `a_t` 调整 GRU 更新门：

```text
u'_t = a_t * u_t

h'_t =
(1-u'_t) * h'_{t-1}
+ u'_t * h_t_candidate
```

普通 GRU 的更新门 `u_t` 只由序列状态决定；AUGRU 再乘候选相关权重 `a_t`。相关行为使 `u'_t` 较大，当前兴趣更充分写入演化状态；不相关行为使更新减弱。最终状态因此同时包含顺序和候选偏好。

### 12.4 完整链路

```text
behavior embeddings
→ GRU interest states
→ auxiliary next-item loss
→ target attention scores
→ AUGRU interest evolution
→ final evolved interest
→ concat other features
→ MLP → CTR
```



### 12.5 局限

- GRU 串行，训练并行度低于 Transformer；
- 对超长序列成本较高；
- 辅助采样质量影响表示；
- 工程复杂度明显高于 DIN。

---



## 十三、BST：Transformer 行为建模



### 13.1 链路

```text
history item embedding
+ position embedding
+ time/action embedding
→ X:[B,L,D]
→ Transformer Encoder
→ sequence representation
→ concat target/user/context
→ MLP
→ CTR
```

Self Attention：

```text
Q = X Wq
K = X Wk
V = X Wv

A = softmax(Q K^T / sqrt(d) + mask)
O = A V
```

操作含义：

1. `Q K^T` 得到 `[B,L,L]`，每条行为都对所有允许访问的行为打分；
2. mask 去掉 padding，并可限制只能查看过去；
3. softmax 后，每条行为按权重汇总全部 Value；
4. FFN 再对每个位置做非线性变换；
5. pooling、CLS 或 Target Attention 将 L 个上下文化行为压成用户序列表示。

优势：行为之间两两交互、并行训练。  
局限：`O(L²D)`，且最终 concat 仍属于“先序列、后交叉”。

常见增强：

```text
Self Attention 编码 history
→ target 再对 encoded history 做 Target Attention
```

---



## 十四、SIM：长序列两阶段建模



### 14.1 优化的问题

DIN 对全历史逐条计算 Target Attention，长度达到几千时成本过高。

### 14.2 链路

```text
long history
→ GSU General Search Unit
   快速检索 target 相关子序列
→ Top-K behaviors
→ ESU Exact Search Unit
   精细 Target Attention
→ long-term interest
→ CTR model
```

GSU 可以是：

- 类目/属性 hard search；
- embedding similarity soft search。

GSU 只负责低成本缩小候选历史范围，不生成最终兴趣；ESU 对 Top-K 行为重新使用更精细的特征和 Target Attention，得到最终 D 维兴趣向量。这与召回后精排的思想相同，只是被检索对象变成了用户自己的历史行为。

优势：长度和时延可控。  
局限：GSU 漏掉的行为无法被 ESU 恢复，检索和精排目标可能不一致。

# 路线 C：多任务学习



## 十五、Shared Bottom：最基础的多任务结构

```text
x
→ shared bottom
→ h_shared
   ├→ CTR tower → pCTR
   ├→ CVR tower → pCVR
   └→ value tower → E[value]
```

操作含义：所有任务先共用同一个特征提取网络，得到一份共享表示；每个 Tower 只负责把共享表示变换成自己的目标。所有任务 Loss 都会更新 Shared Bottom，因此可以共享样本信息，也可能产生梯度冲突。
总损失：

```text
L =
lambda_ctr * L_ctr
+ lambda_cvr * L_cvr
+ lambda_value * L_value
```

优点：参数共享充分。  
问题：任务相关性弱或梯度冲突时发生负迁移。

---



## 十六、ESMM：曝光空间中的 CTR + CVR



### 16.1 优化的问题

CVR 标签只在点击样本上可见：

```text
曝光 → 是否点击
点击 → 是否转化
```

直接在点击样本训练 CVR 会产生：

- Sample Selection Bias；
- 点击样本少导致 Data Sparsity。



### 16.2 概率分解

```text
pCTR   = P(click=1 | impression)
pCVR   = P(conversion=1 | click=1, impression)
pCTCVR = P(click=1, conversion=1 | impression)

pCTCVR = pCTR * pCVR
```

这里不是把两个独立预测结果做后处理，而是将乘法放进训练计算图：

```text
CTR tower 学习曝光后点击概率
CVR tower 学习点击条件下的转化概率
两者相乘得到曝光后最终转化概率
```

转化标签虽然稀疏，但 `pCTCVR` 可以在所有曝光样本上计算 BCE，梯度会通过乘法同时回传到 CTR 和 CVR Tower。

### 16.3 网络链路

```text
impression features
→ shared embeddings

CTR tower → pCTR
CVR tower → pCVR

pCTCVR = pCTR * pCVR
```

损失全部在曝光空间计算：

```text
L =
BCE(click_label, pCTR)
+ BCE(conversion_label, pCTCVR)
```

CVR tower 不直接使用仅点击样本的 CVR BCE。

因此 ESMM 解决的是“监督空间”问题：CVR Tower 的输入仍来自全曝光样本，训练目标通过概率链间接约束，不再把点击人群当作完整总体。

### 16.4 优点和问题

优点：

- 全曝光样本参与；
- 缓解 CVR 样本选择偏差和稀疏；
- 概率链路符合转化漏斗。

问题：

- pCVR 通过乘法间接监督；
- pCTR 很小时梯度可能弱；
- 复杂漏斗需要扩展为多阶段联合模型；
- 训练分布偏差不等于因果偏差，ESMM 不能自动解决曝光选择机制。

---



## 十七、MMoE：任务使用不同专家组合



### 17.1 优化的问题

Shared Bottom 强制所有任务共享同一表示。MMoE 建立多个共享专家，每个任务使用自己的 gate。

### 17.2 前向链路

```text
x
→ Experts:
   E_1(x), E_2(x), ..., E_M(x)

对任务 k：
gate_k = softmax(W_gate_k x)
h_k = sum_m gate_k,m * E_m(x)
y_k = Tower_k(h_k)
```

公式：

```text
E_m(x) = MLP_m(x)
g_k(x) = softmax(W_k x + b_k)

h_k =
sum_m g_k,m(x) * E_m(x)
```

操作顺序：

1. 所有 Expert 并行处理同一个输入，每个输出同维向量；
2. 任务 k 的 Gate 根据当前样本生成 M 个权重；
3. 对 Expert 输出逐向量加权求和，形成任务 k 的表示 `h_k`；
4. Task Tower 将 `h_k` 转成该任务预测。

Gate 是 sample-wise、task-specific 的：同一个样本在 CTR 与 CVR 任务上可以选择不同专家，不同样本在同一任务上也可以选择不同组合。

### 17.3 特点

- Expert 参数共享；
- Gate 参数任务独立；
- 不同任务可选择不同专家组合；
- 适合任务相关但不完全一致的场景。

局限：

- 所有专家仍是 shared experts；
- 某些专家可能被所有任务争抢；
- gate 容易坍缩到少数专家；
- 任务差异大时仍可能负迁移。

---



## 十八、PLE：显式区分共享专家与任务专家



### 18.1 CGC Layer

对任务 k：

```text
task experts:
E_k,1(x_k),...,E_k,Mt(x_k)

shared experts:
E_s,1(x_s),...,E_s,Ms(x_s)

gate_k
→ 在 task experts + shared experts 中选择
→ h_k
```

共享分支 gate：

```text
gate_shared
→ 聚合所有 task experts + shared experts
→ h_shared
```

在一个 CGC 层中：

- 任务 k 的 Gate 只能读取任务 k 专家和共享专家，避免其他任务专属信息直接污染它；
- Shared Gate 可以读取所有任务专家和共享专家，提炼下一层仍可复用的公共信息；
- 每个输出都是若干同维 Expert 向量的加权和。



### 18.2 Progressive Layered Extraction

```text
CGC Layer 1
→ task/shared representations
→ CGC Layer 2
→ ...
→ task towers
```

“Progressive”的含义是这种分流不只做一次。浅层仍允许较多公共信息交换，经过多层 CGC 后，各任务表示逐渐专门化；最后 Tower 不再共享参数，完成任务输出。
随着层数增加：

- task-specific 表示逐渐分离；
- shared 表示继续交换公共信息；
- 最后只保留任务分支进入 tower。



### 18.3 MMoE 与 PLE

```text
MMoE：
全部专家共享，任务 gate 不同

PLE：
共享专家 + 任务独享专家
+ 多层渐进分离
```

PLE 更适合：

- CTR、CVR、时长等目标差异明显；
- 观察到 Shared Bottom/MMoE 负迁移；
- 有足够参数和 serving 预算。

## 十九、经典模型如何组合成工业精排



### 19.1 轻量短序列方案

```text
categorical/dense → embeddings
history + target  → DIN interest

concat(
  user tokens,
  target tokens,
  context tokens,

→ Shared Bottom / MMoE
```

### 19.2 旅行多业务推荐

```text
火车历史 + 线路候选 → DIN → train_interest

所有 interest
```

```text
feature/sequence backbone
```

## 二十、模型选型

```text
需要简单稳健基线：
DeepFM

显式高阶交叉重要：
DCNv2

field 动态交互重要且字段不多：
AutoInt/Hiformer

短序列、候选相关：
DIN

顺序和兴趣演化明显：
DIEN 或 BST + Target Attention

几千级历史：
SIM

CTR→CVR 漏斗：
ESMM

多个相近任务：
MMoE

任务差异大、存在负迁移：
PLE
```

实践建议：

1. 先建立 DeepFM/DCNv2 + DIN + Shared Bottom 基线；
2. 有转化漏斗再加入 ESMM；
3. 明确观察任务冲突后再升级 MMoE/PLE；
4. 只有序列顺序带来稳定收益时才从 DIN 升级 DIEN/BST；
5. 经典模型稳定后，再评估 RankMixer、LONGER、OneTrans 等新架构。

## 二十一、面试高频问题



### 1. DeepFM 和 Wide & Deep 的区别

```text
Wide & Deep：
Wide 依赖人工交叉

DeepFM：
FM 自动学习一阶/二阶交叉
FM 与 DNN 共享 embedding
```



### 2. FM 为什么能处理未共现组合

因为交叉参数由两个特征 embedding 内积产生，而不是为每个组合单独学习 `w_ij`。

### 3. DCN 的交叉阶数

第 l 个 Cross Layer 在已有表示上乘回 `x0`，每层将最高交叉阶数增加一阶。

### 4. DIN 是 Self Attention 吗

不是。DIN 是 target 查询 history 的 Target Attention，也是 Cross Attention 的特例；history 之间不两两交互。

### 5. DIEN 比 DIN 多什么

```text
GRU Interest Extractor
+ next-item auxiliary loss
+ target-aware AUGRU Interest Evolution
```



### 6. ESMM 推理时的 pCVR 怎么得到

CVR tower 直接输出 pCVR；训练时通过：

```text
pCTCVR = pCTR * pCVR
```

在曝光空间间接监督它。不要线上用 `pCTCVR / pCTR` 做不稳定除法。

### 7. MMoE 和 PLE 的区别

```text
MMoE：所有专家共享，每个任务 gate 不同
PLE：共享专家 + 任务专家，多层渐进分离
```



### 8. 为什么不直接上最新模型

新模型解决的是明确瓶颈：

- RankMixer：GPU 利用率和交叉 Scaling；
- LONGER：长序列；
- OneTrans：S/NS 统一。

如果业务只有几十条行为和有限算力，DIN + DCNv2 往往更稳定、更便宜。
